# plugin/hooks/

The hooks of the assay plugin (`docs/architecture/02-architecture.md` §2, §6). Local mode is advisory: CI never trusts its output (ADR-10).

- `pre-push`: the git pre-push helper (#108, `04-pipeline.md` §9 CP1). It runs `assay pre-push`, which lists the current branch's open Weigh-In items with `weighin open --repo --json`: a *blocking* item (open, triaged, and `door != two-way`, `authority == authority` or a non-null `blocks`) stops the push, an item *pending triage* only warns. `git push --no-verify` skips it. Install it with a symlink, `ln -s /path/to/assay/plugin/hooks/pre-push .git/hooks/pre-push`. `git config core.hooksPath /path/to/assay/plugin/hooks` also works but replaces every hook the repository has (git then no longer reads `.git/hooks`), so use it only in a repository with no other hooks. A refused or failing `weighin` stops the push too (exit 2). `ASSAY` names the `assay` program and `ASSAY_WEIGHIN` the `weighin` program (absolute; the plugin's launcher, `<weigh-in plugin>/libexec/weighin`, is not on `PATH`); with no `weighin`, or on a detached `HEAD`, it says it did not check and lets the push through. `crates/assay-cli/tests/it/pre_push.rs` pushes through it.
- No mod. The assay mod (an in-session view over `assay.status/1` and `assay.event/1`, ADR-25, `docs/design/assay-mod.md`) lives in its own plugin, `plugin-mod/` (#127), so a desktop chat does not switch this plugin off.
