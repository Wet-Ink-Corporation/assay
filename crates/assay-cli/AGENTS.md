# Crate charter: `assay-cli`

## Purpose
The `assay` binary: the composition root. It parses arguments, loads and validates configuration once, wires the adapters into the use cases and maps outcomes to exit codes (`docs/architecture/02-architecture.md` §2). It also hosts the workspace's architecture tests, because it is the one crate that may depend on every other.

## Layer
binary. Thin (ARC-14): no business logic, nothing a test would want to call directly.

## Allowed dependencies
- Workspace crates: all five others, added by the story that first wires each.
- Third-party: crates on the pre-approved list in `.claude/temper.json`, each justified in the root decisions log when added. `serde_json` (writes the `assay-self` gate's document, #76; a dev-dependency before, for the architecture test's `cargo metadata`). `tempfile` (`assay check --local`'s scratch directory and atomic report write, #107; dev-only before, for scratch directories in the supervisor tests).
- Wired so far: `assay-app`, `assay-forge`, `assay-gates`, `assay-runner` (#150); `assay-domain` (#55, for `ForgePullRequest`'s `FileChange`; a dev-dependency before).
- Never: `weighin-core` or temper code (P8).

## Public surface
The `assay` command line. With no arguments it exits 0 and does nothing. `assay self-gate <corpus-dir> <rubric-file>` (#76, `src/self_gate.rs`) is the `assay-self` exec gate (02 §7): it reads the corpus and the rubric relative to the working directory (at most 4,096 entries, 1 MiB per file, 64 MiB in all; symlinks listed, never followed or read), runs `assay_app::replay_golden` and writes the document with `create_new` to `ASSAY_FINDINGS_OUT`, with `ASSAY_RUN_KEY` as its `run_key` and `assay/<version>` as its `version`; exit 0 on `pass`, 1 on `fail`, and 2 with no document for a usage error, a missing or empty variable, an unreadable or over-cap tree, or a failed write. `assay gate <gates-static|gates-lint|gates-test> --config <plugins-toml> --head <dir> --out <dir>` (#67, `src/gate.rs`) is a gates job's entry point (03 §2.1 step 7, as built): `gates-test`, `gates-static` and `gates-lint` (below) run; with `ASSAY_RUN_KEY` required, it refuses before anything runs a head that is not a directory, a config that is not a regular file outside the head tree and an `--out` that exists, is inside the head tree, has no directory as parent, or whose parent is not named by its resolved path (a symlink or `..` on the way, refused rather than followed); the resolved head, config and `--out` are the ones used; then runs `run_gates` in `gates-test` over `assay_gates::TemperTestAdapter` (the temper plugin's `test` steps, nothing of `gates-lint`) and `ExecAdapter` (exec gates of `job = "test"`, documents in a scratch directory), each over its own `ForgeSupervisor`, with the process's variables through `GateEnvironment`; creates `--out` afterwards and writes each concluded gate's validated document, compact, as `<out>/<plugin>.json` through a dot-named temporary file and `persist_noclobber`; then appends the `gates` output (#60 ST-6, 03 §4a) to the regular file `GITHUB_OUTPUT` names (required, checked and opened for appending, never created, before anything runs): one compact JSON entry per gate in file order, `{"plugin","conclusion","sha256"}` with the sha256 of the exact bytes of `<plugin>.json`, or `{"plugin","error"}` with the gate error's reason; every document and the output are encoded before anything is written and the output is appended last (`src/gate/results.rs`), so a job that cannot encode or write its documents appends nothing; prints `<plugin> <pass|fail|neutral|gate-error:<detail>>` per gate on stdout and each gate error's cause on stderr; exit 0 once written whatever the conclusions, 2 when it cannot run or write, or the scratch directory is left. `assay gate gates-static ... --node <abs> --temper <abs>` (#60 ST-7, `src/gate/static_job.rs`, Z2s) takes the same three flags plus exactly these two (`gates-test` takes neither; a missing or repeated one is a usage error), each refused unless absolute as given and, resolved, outside the head tree (`PinnedError::{RelativeProgram, ProgramInHead}`, the closed `gate::Program`); `--temper` is the pinned copy the workflow prepared from the base's `oci:sha256:` pin (D8 A) and is not checked against the pin here. Before anything runs it also reads `ASSAY_BASE_SHA` and `ASSAY_HEAD_SHA` (`CommitSha`: 40 lowercase hex), `ASSAY_RUN_TOKEN` (the job's `github.token`; the only token it reads), `GITHUB_REPOSITORY` and `PATH`, each named by the closed `gate::Variable` and never shown (`PinnedError::{Missing, Invalid}`). Then it fetches base and head by SHA into an object-only repository in its scratch directory with `ObjectRepo::fetch_authorized` to `https://github.com/<repo>.git` (git with only `PATH`; `PinnedError::{Git, Fetch { side }}`; `src/gate/fetch.rs`, shared with `gates-lint`), and runs `run_gates` over a binary-private `StaticGates`: `TemperAdapter` (the Z2s checks; the scan by `--node` over `--temper`, from the head tree, through its own `ForgeSupervisor`) and `WeighInAdapter`, both over one `ForgeRevisions`; an `exec` plugin is never scheduled there. A pinned commit that cannot be fetched is exit 2 (`PinnedError::Fetch`) before any gate runs, with nothing written; once the scratch directory exists it is closed on every path, and one that cannot be removed is reported beside the job's error (`GateCliError::ScratchLeft`) or as left by a job that ran, for both jobs (`gate::closing`). The workflow must check out `ASSAY_HEAD_SHA` into `--head`, which `gates-static` does not verify; Z2s fails closed through the scan's cross-check against the fetched head (an `#[expect]` or `allow` the fetched head holds that the scan of the checkout did not report fails). Documents, lines, output and exit codes are as for `gates-test` (the shared `prepare`/`finish` and `results::write`). `assay gate gates-lint ... --node <abs> --temper <abs>` (#60 ST-8, `src/gate/lint_job.rs`, Z2b) takes the same flags, programs and variables as `gates-static`, plus `ASSAY_MERGE_BASE` (plan's `merge_base`, D4 A; `CommitId`, 40 lowercase hex), read first and refused by name before anything runs (`PinnedError::{Missing, Invalid}`); `ASSAY_BASE_SHA` and it are the `RatchetBase` of `TemperSettings::with_ratchet`. It fetches base and head with `gates-static`'s `fetch::Source`, then refuses (exit 2, no gate run, nothing written) a `--head` checkout that is not exactly `ASSAY_HEAD_SHA`'s tree (#348, `src/gate/checkout.rs`, `PinnedError::Checkout` naming the commit and the first differing path, `HeadTree`, `CheckoutRead`, `CheckoutTooLarge { files, directories }`): every tree entry present as the same kind, a regular file with the same owner execute bit and its blob's bytes (read from the object-only repository in batches within `TreeLimits`), a symlink with the same target (never followed), a submodule as an empty directory, and no other non-directory entry, untracked or ignored, except the root `.git` and an untracked root `target/` directory (the warm `target/`, ADR-21, not examined); a non-UTF-8 name is untracked (named by its lossy text, and two names that read as one path are refused). The walk reads each directory lazily and counts each entry before its metadata: non-directories against the listing's entry cap, directories against those the tree implies plus `UNTRACKED_DIRECTORIES` (1,024). It then runs `run_gates` over a binary-private `LintGates`: `TemperAdapter` (the `lint` steps, then the pinned `baseline --check` by `--node` over `--temper`, believed only against `ASSAY_MERGE_BASE`; its evidence through `ForgeRevisions`) and `ExecAdapter` (exec gates of `job = "lint"`, documents under the scratch directory's `exec/`), each over its own `ForgeSupervisor`, all in the checkout with the `GateEnvironment` allowlist, so no token and no `ASSAY_MERGE_BASE` reaches them; a Weigh-In plugin is never scheduled there. Documents, lines, output and exit codes are as for `gates-test`. `assay doctor <plugins-toml> <claude-program>` (#121, `src/doctor.rs`) runs `assay_app::doctor` with `assay_runner::ClaudeCanary` against the absolute `claude-program`: it reads the config (at most 1 MiB, UTF-8), requires its `claude_cli` pin, passes `CLAUDE_CODE_OAUTH_TOKEN` and `PATH` to the CLI, draws the canary nonce from `/dev/urandom`, prints `ok <check>` or `FAIL <check>: <why>` per check and exits 0 when all pass, 1 when one fails and 2 when they cannot run. `assay doctor --repository <owner/name> --app <id> --ledger-app <id>` (#75, `src/prerequisites.rs`) checks the repository prerequisites of 05 §7: `PrerequisitesArgs::parse` (`PrerequisitesArgs::requested` tells the form apart by a first argument starting `--`; `PrerequisitesUsage` for an unknown, repeated, missing or invalid flag) and `run_prerequisites(&repository, connect, apps)`, which reads the base with `assay_app::read_base`, connects to the configured `ledger_repo` through `connect` and returns `assay_app::prerequisites`' report (`PrerequisitesRunError::{Base, Ledger}`), written by `write_prerequisites` as `ok <check>` or `FAIL <check>: <cause chain>` lines. `prerequisites_exit_code(&report)` is 0 when every prerequisite holds and 1 when one fails. It is generic over the `PrerequisiteForge` and tested with fakes; until the live `gh` transport (#273) exists the binary answers a well-formed invocation with exit 2 naming #273, and a usage error with exit 2. `assay doctor --profile <plugins-toml> <claude-program>` (#84, `src/doctor/profile.rs`, dispatched before the prerequisites form) runs `assay_app::verify_profile` with `ClaudeHeadless` (in an empty temporary directory, removed after, also when the canary could not run; a failed removal is reported after the report, or beside the error, with exit 2) as the preflight's `CliProbe` and `ClaudeCanary` as the `ProfileProbe`, with the same refusals as the session form plus a token too short for the egress scan (`EgressToken::new`, never echoed); the preflight sees the names of every variable of the process. It prints `ok <check>` or `FAIL <check>: <cause chain>` per profile check, then `ok flag <flag>: <evidence>` or `FAIL flag <flag>: <check> failed` per flag of the argv, and exits 0 when all pass, 1 when one fails and 2 when they cannot run. The session form `assay doctor <plugins-toml> <claude-program>` alone judges the token's expiry (`--profile` does not read it): when `ASSAY_TOKEN_EXPIRES_ON` is set and not empty (#93), it is read as `YYYY-MM-DD` before its canary runs and judged with `assay_app::token_expiry_warning` against the wall clock's UTC day: a last line `warn token-expiry: <why>` from 30 days before the expiry (exit unchanged), `FAIL token-expiry: <why>` from the date on (exit 1), both linking the rotation runbook. `assay pre-push` (#108, `src/check/weigh_in.rs`) runs CP1 alone for `plugin/hooks/pre-push` (04 §9): the current branch's open Weigh-In items from `weighin open --repo --json`, exit 1 on a blocking item and 0 otherwise (pending items warn), 2 when it cannot run. `assay check --local [--base <branch>] [--claude <program>]` (#107, `src/check.rs`), run from the repository root, runs `assay_app::check_local` on a snapshot of the working tree (02 §6) against `refs/remotes/origin/<branch>` (default `main`), with the prompt bundle and rubric embedded at build time, `exec` gates through `ExecAdapter` in the working tree (other gates are `not run in local mode`) and `ClaudeHeadless` with `HeadlessEnv::logged_in` (`HOME` and `PATH` passed, the program `--claude` or the first `claude` on `PATH`); it writes `<git dir>/assay/<tree>.json` (`assay.local-check/2`) and then `<git dir>/assay/latest` (the tree, for a stale lookup), each through a temporary file and a rename (`src/check/store.rs`), and prints the report, exiting 0 on `success` or `neutral`, 1 otherwise and 2 when it cannot run. With `--events <path|->` (#130, `src/check/events.rs`) it streams every `assay.event/1` envelope as one compact JSON line, flushed per line, through `JsonlEvents` (`assay_app::EventSink`); `-` is stdout and the report then goes to stderr; a path is created with `create_new` after the snapshot and an existing one is refused (exit 2) with advice to use `-` or a path outside the working tree or ignored; a line over 64 KiB or a stream past 16 MiB stops the check (exit 2). `assay status [--json] --local` (#130, `src/status_local.rs`) snapshots the working tree the same way, looks up the report for its tree, else the one `latest` names (`store::find`: regular files only, a FIFO refused before it is opened, at most 8 MiB and 128 bytes), and writes `assay_app::local_status`'s `assay.status/1` (`source: "local"`) or its text to stdout, exit 0, or exit 2 when it cannot. `assay reconcile [--ledger]` (#73, `src/reconcile.rs`) is the per-repo sweep of the repository's own verdict checks or, with `--ledger`, the single ledger-side sweep (06 §4); it refuses a `GITHUB_RUN_ATTEMPT` other than `1`, unset or not a number (R3-05), then exits 2 naming #273 until the live GitHub transport exists, when it will wire `assay_app::reconcile_checks` and `reconcile_ledger`; any other argument is a usage error (exit 2). Any other first argument is a usage error (exit 2). A library target, `assay_cli`, holds the adapters the composition root lends one crate from another, so they are tested before a command wires them: `ForgeSupervisor` (`new`), `assay-forge`'s process-group supervisor as an `assay_gates::Supervisor`, an `assay_gates::CaptureSupervisor` (stdout kept; none after a timeout or an over-cap run), an `assay_runner::GroupKill` (wi-603c63) and an `assay_forge::github::GhRunner` (#273: runs forge's `GhCall` for `gh api` with exactly its arguments, environment, working directory, stdin and limits, so forge's `GhApi` is the GitHub transport); and `ForgeRevisions` (`new(repo, base, head, limits)`), forge's object-only repository as the temper adapter's `assay_gates::RevisionFiles` (#63), every listing and read bounded by forge's `TreeLimits`; to read blobs it lends each requested entry's path and object id to forge as a borrowed `BlobRef`, copying nothing; and `ForgePullRequest` (`new(repo, limits, diff_cap)`, error `ForgeObjectsError::{Git, Commit}`), the same repository as `assay_app::PullRequestObjects` for `plan` (#55): forge's `changed_files` mapped to the domain's `FileChange` (a gitlink on either side is `Gitlink`, else a symlink `Symlink`; an unmeasured count `Binary`), and its tree listings and reads, and as `assay_app::ChangePatches` for `check_local` (one `ObjectRepo::file_patch` per file, the text read lossily as UTF-8); `assay status`'s parsing and runner (below); and `assay doctor --repository`'s parsing and runner (below). Its other public items (`OpenCommand` and `run_open`, `run_plan`, the CI plumbing and `outputs`) are described below with the commands that use them. As a `Supervisor` it discards the gate's output, but forge reads it back first: a gate run briefly holds up to twice `max_output_bytes` in memory (32 MiB at `ExecLimits::DEFAULT`), accepted because one gate runs at a time. `assay status [--json] [--pr <n>] [--full]` (#126, `src/status.rs`) parses its arguments (`StatusCommand::parse` into `Pull(StatusArgs)` or, with `--local`, `Local(Format)`; `StatusArgs::parse`, `Format`, `StatusUsage`, whose `NotLocal` refuses `--pr` or `--full` with `--local`) and wires `assay_app::status` through `run(&StatusArgs, &StatusContext, &StatusPorts, out)` (re-exported as `run_status`, with `StatusContext` and `StatusRunError`; `StatusContext::pull` is the `PullSelector` the composition root chose once, so `run` reads only the format and detail from `StatusArgs`), generic over the ports so it is tested with fakes. The binary (#273, `src/status_pr.rs`) runs it from the root of a checkout over forge's `GitHub<GhApi<ForgeSupervisor>, ThreadSleep>` as both ports: `main` reads `ASSAY_GITHUB_TOKEN` (the viewer's token), `ASSAY_VERDICT_APP_ID` and `ASSAY_VERDICT_BOT_ID` (positive decimal ids; a missing or invalid one is named, its value never shown, before any process runs), `PATH` (the first absolute `gh`) and `GhEnvironment::from_process_env()`; the repository is the checkout's single `remote.origin.url` read by `Repository::from_remote_url` (the URL is never echoed), which GitHub must answer for (`status_repository`); without `--pr` the PR is the open one of the checkout's branch (a detached HEAD is refused, naming `--pr`); the PR is read once first (`assay_app::read_pull`) and the status reports that read (`PullSelector::Read`); the base P10 lists are `assay_app::base_identities` at `refs/remotes/origin/<the PR's base>`, where CI reads base config (03 §1; a plain branch name, fetched, else exit 2 naming it), read through `ForgePullRequest` on a scratch snapshot repository that borrows the checkout's objects; the rubric is the embedded one (`read_rubric`); the run bundle comes through forge's `gh run download` `BundleSource` (wi-6b26d6). The status goes to stdout with exit 0; anything refused is exit 2 with the cause chain, and gh's scratch configuration directory and the snapshot's scratch directory are closed on every path after gh's transport exists, a failure to remove either reported with exit 2 (a usage error is also exit 2); the `--local` form runs as above. `assay open --config <plugins-toml>` (#54, #60 ST-4, `src/open.rs`, `src/open/run.rs`, `src/open_job.rs`, S0) is the open job: `OpenCommand::parse(args, &RunVariables) -> Result<OpenCommand { run: FirstAttempt, config }, OpenUsage>` takes exactly `--config <path>` and reads the run through `RunEnv::from_vars` and `first_attempt` (so `01`, `+1` and an unset attempt are refused as `RunEnv` refuses them, #322), refusing any attempt but 1 before anything else is read (R3-05, I1; `assay_app::open` refuses it again); then guard's identity from `ASSAY_NEEDS` (exactly `guard`, through `Identity::from_needs`), base config's `[assay].ledger_repo` (required, `owner/name`; none is exit 2), `ASSAY_GITHUB_TOKEN` (the `assay-verdict` App's), `ASSAY_LEDGER_TOKEN` (the `assay-ledger-writer` App's) and `ASSAY_VERDICT_APP_ID`/`ASSAY_VERDICT_BOT_ID` (positive decimal, no leading zero), each named and never shown when missing or invalid, all before any process starts. `run_open(OpenJob { run, identity }, &impl OpenReads, &OpenPorts) -> OpenRunOutcome` reads the run's `created_at` (the record's `at`) and, for a `synchronize`, `forced(before, head)` through the `OpenReads` port (implemented here for forge's `GitHub`: `run_created_at`, `forced`), before any write (`OpenRunError::{RunCreatedAt, Forced}`), then runs `assay_app::open` with the event mapped one to one onto `OpenTrigger` (`opened`'s sender is the opener); the system clock (`SystemClock`, binary-private) only times the lock's lease and pauses 2, 4 and 8 s between lock attempts. The binary runs it over `GitHub` through `gh` with the App token, and `LedgerRepo` and `LedgerRefsRepo` through one `gh` transport with the ledger token, the lock's deletion pushed by `ledger_push_remote` from an object-only repository in a scratch directory (git with only `PATH`, 60 s and 1 MiB); it prints one line (`assay open: <check name> check <id> <what was written>, stamp <stamp>; <record>`, plus the lock's release failure, which leaves the lock to its lease) and exits 0 once `open` returned, whatever it stamped (a yield or `failure (re-deciding)` included), and 2 for anything refused, with the cause chain, or when gh's or the scratch directory is left behind. The pipeline's CI plumbing (#60 ST-1, `src/ci.rs`, `src/outputs.rs`; 03 §4a), of which `assay guard` (below) wires `RunEnv::from_vars`, `Outputs` and `Identity::outputs` and later stories the rest: `RunEnv::from_vars(&RunVariables)` (`RunEnvError::{Missing, Invalid, NotFirstAttempt}`, the variable named, never its value; ids in canonical decimal, so `01` is refused) and `RunEnv::first_attempt(self) -> Result<FirstAttempt, NotFirstAttempt>`, the only constructor of `FirstAttempt` (API-13); `Outputs::new(W).write(OutputName, &str)` (one `name=value\n` write; `OutputError::{Multiline, Write}`, nothing written for a value holding `\n` or `\r`), `OutputName` holding `guard`'s names (`OutputName::GUARD`) and the gates jobs' `gates` (`OutputName::GATES`) and review's `stage`, `cost_aeu`, `documents` (`OutputName::REVIEW`); `Needs::parse(&[u8], &[JobName])` (`MAX_NEEDS_BYTES` 256 KiB, through `assay_app::parse_json_strict`; `NeedsError` names the job and output, `EntryProblem` the entry's shape), `Needs::job`, `Upstream::{result, output, outputs}`, `JobName`, `JobResult`; and `outputs::Identity` (`outputs()` and `from_needs(&Needs)`) with `outputs::Trigger`; and a gates job's `gates` output (#60 ST-6, `src/outputs/gates.rs`): `outputs::gates_output(&[assay_app::ReportedGate]) -> Result<String, GatesOutputError>` (the compact JSON in the given order, `plugin` first; `GatesOutputError::Plugin { index, name }` for a plugin that is not a `GateName`, nothing encoded) and `outputs::gates_from_needs(&Needs, GateJob) -> Result<Vec<ReportedGate>, NeedsError>` (only from a job whose result is `success`; `gates` required and the only output; `NeedsError::Output` unless exactly the encoded shape: one array without repeated keys, each entry exactly `{plugin, conclusion, sha256}` or `{plugin, error}`, a `GateName`, `pass|fail|neutral`, a `Sha256Digest` and a `GateError` reason as `Display` writes it; a plugin named twice or not scheduled is `decide`'s to refuse). `assay guard` (#60 ST-2, `src/guard.rs` in the library target, `src/guard_job.rs` in the binary; 0006) is the pipeline's first job: it takes no arguments, reads `GITHUB_RUN_ID`, `GITHUB_RUN_ATTEMPT`, `GITHUB_REPOSITORY_ID` and `GITHUB_REPOSITORY` through `RunEnv::from_vars` (no first-attempt check: it holds no write token), `GITHUB_EVENT_NAME` (`pull_request_target` or `workflow_dispatch`) and the regular file `GITHUB_EVENT_PATH` names (checked by `fs::metadata` before it is opened, so a FIFO never blocks, and again after) through `assay_forge::github::EventPayload::read` (at most 8 MiB), and decides with `guard(repository_id, EventPayload, read_pull) -> Result<Guarded, GuardError<E>>`: a payload whose `repository.id` is not `GITHUB_REPOSITORY_ID` is `GuardError::OtherRepository`; a head in another repository, or a deleted one, is `Guarded::Refused(Refusal::UntrustedHead { pr, head: UntrustedHead::{Other, Deleted} })`, checked before the `edited` filter so every event of such a PR is refused; an `edited` without a base change is `Guarded::Skip`; a `workflow_dispatch` reads its PR with `read_pull` (not called for any other event) and refuses an untrusted head as above, a closed PR (`Refusal::Closed`), and a base branch that is empty or holds a control character (`GuardError::BaseRef`); a failed read is `GuardError::Pull`. `Guarded::outputs()` is the identity's outputs for a run, `run=false` alone for a skip, none for a refusal. The binary appends them to the regular file `GITHUB_OUTPUT` names (opened for appending, never created) and exits 0; a refusal is written to stderr (`untrusted head repository: ...`) with nothing written and exit 1; anything that stops it deciding or writing is exit 2. Only a dispatch reads a token: `ASSAY_RUN_TOKEN` (the job's `github.token`), with the first absolute `gh` on `PATH` under `ForgeSupervisor` and `GhEnvironment::from_process_env()`, through forge's `GitHub::pull_identity` with GitHub Actions' App as the adapter's identity (app 15368, bot 41898282: the run token's owner; `pull_identity` attributes nothing to an App); gh's scratch directory is removed after the read, a failure to remove it is exit 2. `assay review --placeholder` (#60 ST-9, D11 A, `src/review.rs`) is the Z3 review job until the real review (M2): it takes exactly `--placeholder` (anything else is a usage error, exit 2, before `GITHUB_OUTPUT` is read) and appends `outputs::REVIEW_PLACEHOLDER`, `stage=not-run`, `cost_aeu=0` and `documents=[]` in `OutputName::REVIEW`'s order, to `GITHUB_OUTPUT` through `guard_job::open_output` (a regular file opened for appending, never created; unset, missing, a FIFO or a directory is exit 2); it reads no secret and no run variable. `assay plan --out <dir>` (#60 ST-5, S1, `src/plan_job.rs`) is the Z1 plan job: exactly `--out <dir>` (anything else is a usage error); then, before any process starts, the run (`RunEnv::from_vars`; no first-attempt check, it holds no write token), `GITHUB_OUTPUT` (opened as for `guard`), guard's identity from `ASSAY_NEEDS` (`Identity::from_needs`), `--out` as an `OutDir` and `ASSAY_RUN_TOKEN` (the job's `github.token`; the only token it reads), each refused by name with exit 2 and the value never shown (the variables are the closed `plan_job::Variable`). It reads the PR's REST file list through `gh` (`GitHub::pull_files`, GitHub Actions' App as the adapter identity, as `guard`), then fetches the pinned base and head by SHA into an object-only repository in a scratch directory with `ObjectRepo::fetch_authorized` to `https://github.com/<repo>.git` (the same token as `GhToken::git_authorization`), and runs the library target's `run_plan`. `run_plan(PlanJob { run, identity, rest_files, prompt_bundle }, PlanPorts { objects: &ForgePullRequest, nonces, validator }, &OutDir) -> Result<outputs::PlanOutputs, PlanRunError<N>>` builds the `PlanRequest` (no package sets, D2 B: every Rust change is exec surface; `IncludeTargets::NotScanned`), plans, reads git's merge base of the pinned commits (`ForgePullRequest::merge_base`, D4 A), creates `--out` with `fs::create_dir` and writes the document as `RUN_FILE` (`run.json`) with `File::create_new`; `PlanRunError::{Plan(PlanError) (a REST list git does not confirm is `PlanError::FileList`), MergeBase, NoMergeBase, Write}`. `OutDir::new` refuses a path that exists in any form, one ending in `..`, a parent reached through a symlink or `..`, and a directory inside a checkout (an ancestor holds `.git`): `OutDirError::{Path, Exists, NoName, NotResolved, InCheckout}`. `outputs::PlanOutputs` (built only by `new(&PlannedRun, run_digest, draft, merge_base)` or `from_needs`) writes `OutputName::PLAN`: `run_digest` (sha256 of the exact bytes written), `run_key`, `tier`, `draft`, `review` (`assay_app::reviewed`), `merge_base` and `artifact_<job>` for each `ArtifactJob` (`OutputName::artifact`); `from_needs` reads only a `success` plan, every output required, an artifact name `assay-<job>-<32 hex>` of its own job and a `review` equal to the one its tier and draft give. The outputs are appended after the document; the binary prints one line, `assay plan: wrote <dir>/run.json (<digest>); tier <tier>, review <bool>`, and exits 0; every refusal is exit 2 with no output written.
