# Crate charter: `assay-cli`

## Purpose
The `assay` binary: the composition root. It parses arguments, loads and validates configuration once, wires the adapters into the use cases and maps outcomes to exit codes (`docs/architecture/02-architecture.md` §2). It also hosts the workspace's architecture tests, because it is the one crate that may depend on every other.

## Layer
binary. Thin (ARC-14): no business logic, nothing a test would want to call directly.

## Allowed dependencies
- Workspace crates: all five others, added by the story that first wires each.
- Third-party: crates on the pre-approved list in `.claude/temper.json`, each justified in the root decisions log when added. `serde_json` (writes the `assay-self` gate's document, #76; a dev-dependency before, for the architecture test's `cargo metadata`). `tempfile` (`assay check --local`'s scratch directory and atomic report write, #107; dev-only before, for scratch directories in the supervisor tests).
- Wired so far: `assay-app`, `assay-forge`, `assay-gates`, `assay-runner` (#150); `assay-domain` (#55, for `ForgePullRequest`'s `FileChange`; a dev-dependency before).
- Never: `weighin-core` or temper code (P8).

## Public surface
The `assay` command line. With no arguments it exits 0 and does nothing. `assay self-gate <corpus-dir> <rubric-file>` (#76, `src/self_gate.rs`) is the `assay-self` exec gate (02 §7): it reads the corpus and the rubric relative to the working directory (at most 4,096 entries, 1 MiB per file, 64 MiB in all; symlinks listed, never followed or read), runs `assay_app::replay_golden` and writes the document with `create_new` to `ASSAY_FINDINGS_OUT`, with `ASSAY_RUN_KEY` as its `run_key` and `assay/<version>` as its `version`; exit 0 on `pass`, 1 on `fail`, and 2 with no document for a usage error, a missing or empty variable, an unreadable or over-cap tree, or a failed write. `assay doctor <plugins-toml> <claude-program>` (#121, `src/doctor.rs`) runs `assay_app::doctor` with `assay_runner::ClaudeCanary` against the absolute `claude-program`: it reads the config (at most 1 MiB, UTF-8), requires its `claude_cli` pin, passes `CLAUDE_CODE_OAUTH_TOKEN` and `PATH` to the CLI, draws the canary nonce from `/dev/urandom`, prints `ok <check>` or `FAIL <check>: <why>` per check and exits 0 when all pass, 1 when one fails and 2 when they cannot run. When `ASSAY_TOKEN_EXPIRES_ON` is set and not empty (#93), it is read as `YYYY-MM-DD` before the canary runs and judged with `assay_app::token_expiry_warning` against the wall clock's UTC day: a last line `warn token-expiry: <why>` from 30 days before the expiry (exit unchanged), `FAIL token-expiry: <why>` from the date on (exit 1), both linking the rotation runbook. `assay check --local [--base <branch>] [--claude <program>]` (#107, `src/check.rs`), run from the repository root, runs `assay_app::check_local` on a snapshot of the working tree (02 §6) against `refs/remotes/origin/<branch>` (default `main`), with the prompt bundle and rubric embedded at build time, `exec` gates through `ExecAdapter` in the working tree (other gates are `not run in local mode`) and `ClaudeHeadless` with `HeadlessEnv::logged_in` (`HOME` and `PATH` passed, the program `--claude` or the first `claude` on `PATH`); it writes `<git dir>/assay/<tree>.json` (`assay.local-check/2`) and then `<git dir>/assay/latest` (the tree, for a stale lookup), each through a temporary file and a rename (`src/check/store.rs`), and prints the report, exiting 0 on `success` or `neutral`, 1 otherwise and 2 when it cannot run. With `--events <path|->` (#130, `src/check/events.rs`) it streams every `assay.event/1` envelope as one compact JSON line, flushed per line, through `JsonlEvents` (`assay_app::EventSink`); `-` is stdout and the report then goes to stderr; a path is created with `create_new` after the snapshot and an existing one is refused (exit 2) with advice to use `-` or a path outside the working tree or ignored; a line over 64 KiB or a stream past 16 MiB stops the check (exit 2). `assay status [--json] --local` (#130, `src/status_local.rs`) snapshots the working tree the same way, looks up the report for its tree, else the one `latest` names (`store::find`: regular files only, a FIFO refused before it is opened, at most 8 MiB and 128 bytes), and writes `assay_app::local_status`'s `assay.status/1` (`source: "local"`) or its text to stdout, exit 0, or exit 2 when it cannot. Any other first argument is a usage error (exit 2). A library target, `assay_cli`, holds the adapters the composition root lends one crate from another, so they are tested before a command wires them: `ForgeSupervisor` (`new`), `assay-forge`'s process-group supervisor as an `assay_gates::Supervisor`, an `assay_gates::CaptureSupervisor` (stdout kept; none after a timeout or an over-cap run), an `assay_runner::GroupKill` (wi-603c63) and an `assay_forge::github::GhRunner` (#273: runs forge's `GhCall` for `gh api` with exactly its arguments, environment, working directory, stdin and limits, so forge's `GhApi` is the GitHub transport); and `ForgeRevisions` (`new(repo, base, head, limits)`), forge's object-only repository as the temper adapter's `assay_gates::RevisionFiles` (#63), every listing and read bounded by forge's `TreeLimits`; to read blobs it lends each requested entry's path and object id to forge as a borrowed `BlobRef`, copying nothing; and `ForgePullRequest` (`new(repo, limits, diff_cap)`, error `ForgeObjectsError::{Git, Commit}`), the same repository as `assay_app::PullRequestObjects` for `plan` (#55): forge's `changed_files` mapped to the domain's `FileChange` (a gitlink on either side is `Gitlink`, else a symlink `Symlink`; an unmeasured count `Binary`), and its tree listings and reads, and as `assay_app::ChangePatches` for `check_local` (one `ObjectRepo::file_patch` per file, the text read lossily as UTF-8); and `assay status`'s parsing and runner (below). Nothing else is public. As a `Supervisor` it discards the gate's output, but forge reads it back first: a gate run briefly holds up to twice `max_output_bytes` in memory (32 MiB at `ExecLimits::DEFAULT`), accepted because one gate runs at a time. `assay status [--json] [--pr <n>] [--full]` (#126, `src/status.rs`) parses its arguments (`StatusCommand::parse` into `Pull(StatusArgs)` or, with `--local`, `Local(Format)`; `StatusArgs::parse`, `Format`, `StatusUsage`, whose `NotLocal` refuses `--pr` or `--full` with `--local`) and wires `assay_app::status` through `run(&StatusArgs, &StatusContext, &StatusPorts, out)` (re-exported as `run_status`, with `StatusContext` and `StatusRunError`), generic over the ports so it is tested with fakes; until the GitHub adapter (#53) exists the binary refuses the PR form with exit 2 naming #53 (a usage error is also exit 2); the `--local` form runs as above.

## Invariants
- `main` returns `ExitCode`; nothing calls `process::exit` (ARC-14).
- Output goes through locked handles with `writeln!`, never print macros (H-06).

## Errors
`doctor::DoctorCliError` (`Usage`, `RelativeProgram`, `Token`, `TokenNotUnicode`, `ExpiresOn`, `Clock`, `Read`, `TooLarge`, `NotUtf8`, `Config`, `NoPin`, `Killer`, `Env`, `Doctor`), binary-private, reported on stderr as exit 2 with every cause in its chain. `Env` cannot occur while `PATH` is not a reserved name; it exists because `HeadlessEnv::pass` checks every name. `self_gate::SelfGateError` (`Usage`, `Variable` (missing or empty), `VariableNotUnicode`, `Read`, `Shape`, `TooLarge`, `Encode`, `Write`), binary-private, reported on stderr as exit 2. `check::CheckCliError` (`Usage`, `BaseName`, `NoBase`, `NoClaude`, `RelativeProgram`, `Cwd`, `Killer`, `Git`, `Scratch`, `Bundle`, `Settings`, `Workdir`, `Env`, `Commit`, `Objects`, `Contracts`, `EventsExist`, `EventsOpen`, `Check`, `Encode`, `Write`), binary-private, exit 2; `Check` carries `assay_app::CheckError` with the sink's `check::events::EventWriteError` (`Encode`, `LineTooLong`, `StreamFull`, `Write`). `status_local::LocalStatusCliError` (`Tree`, `Read`, `Clock`, `Head`, `Contracts`, `Status`), binary-private, exit 2 with its chain; `Read` is `check::store::ReadError` (`Io`, `NotAFile`, `Latest`), and a report write failure is `store::WriteError` mapped to `CheckCliError::Write`. `anyhow` with `.context()` is allowed here only (ERR-06), once approved as a dependency.

## Test strategy
One integration binary, `tests/it/` (TST-14):
- `architecture.rs` with `layering.rs`: the ADR-07 crate graph read from `cargo metadata`, plus synthetic graphs proving each rule rejects a violation.
- `layout.rs`: the repository layout of 02 §7.
- `check.rs`: `assay check --local` end to end on a fixture repository with a dirty tree, a required `exec` gate and a stand-in `claude` that lists the tree it was given (the real CLI never runs): the report lands at `.git/assay/<tree>.json`, advisory, the developer's status is unchanged and the model sees the snapshot without the ignored `.env`; without package sets a Rust change is `full` and fails with its specialists missing (the known gap); a subdirectory, an unfetched base, malformed arguments, a base that is not a plain branch name and a relative program exit 2; and no workflow or production module but local mode's own names the report. Linux only; needs git.
- `check_local_events.rs` (#130): `--events -` streams valid `assay.event/1` lines numbered per job on stdout with the report on stderr, `--events <file>` writes a new file, an existing path is refused and left unchanged, a stream inside the working tree makes the status stale and its rerun is refused, `--events` with no, an empty or a flag value or given twice is a usage error; `assay status --local` with no result (`check: null`), fresh after a check and stale after an edit, as text, and refused with `--pr`. The #107 test in `check.rs` also refuses any `.github` file passing `--local` or `--events`. Unit tests: `src/check/events.rs` (one compact line flushed per event, the line and stream caps at and past the cap, a closed pipe, no stream) and `src/check/store.rs` (found by its tree and through `latest`, a `latest` naming a missing report or not one tree id, a directory or FIFO refused, reads stopped one byte past the cap). Linux only; needs git.
- `binary.rs`: the `assay` binary runs; an unknown subcommand, a wrong argument count and an empty `ASSAY_FINDINGS_OUT` exit 2 and write nothing.
- `src/self_gate/tests.rs` (unit, #76 review round 1): the reader's caps through an injectable `Budget` (a file at the per-file cap is read and one byte more is `TooLarge`; the entry past the entry cap, a file after the total is spent, and a rubric after the corpus spent the budget are `TooLarge`); on Unix, a symlinked case file is listed as `Other` and fails the replay with `golden-unexpected-entry`, a symlinked corpus directory or rubric and a non-UTF-8 name are `Shape`, and a missing `ASSAY_RUN_KEY` is told apart from a non-Unicode one.
- `doctor.rs`: `assay doctor` end to end against `assay-runner`'s stand-in `fake-claude-canary` (no real `claude`): a clean stand-in passes every check, drift from the pinned allowlist and a stand-in that ignores its flags fail with exit 1, and each refusal (argument count, relative program, missing, empty or non-Unicode token, unreadable, unparseable or unpinned config, a config at the 1 MiB cap and one byte over, a CLI that cannot start, an expiry that is not `YYYY-MM-DD` or not Unicode, never echoed) exits 2; a distant or empty expiry adds no line and a past one fails with exit 1 (#93). Unit tests in `src/doctor.rs` cover what the end-to-end tests cannot, since they cannot fix the clock: a near expiry is a warning that does not fail the run (`expiry_fails`), the `warn` line, and a clock before the epoch (`Clock`). Linux only.
- `exec_surface.rs`: exec-surface detection end to end (04 §2.2, #65) on fixture PRs built as git repositories and fetched into an `ObjectRepo`: forge's manifest copy, the real cargo that built the tests as the pinned cargo (`PinnedCargo` under `ForgeSupervisor`) with registry crates from a directory source in the test's own `CARGO_HOME` (no network), and `assay_app::exec_surface`. A new `build.rs` and a bumped crate gaining a build script are exec surface, a plain registry bump is only `Registry`, a path build-dependency inherited through `[workspace.dependencies]` is an exec root, a symlink in a build-time crate leading outside it (a `.cargo/` one the copy never writes included) and a build-dependency's `[lib] path` outside its crate are `Everything` (cargo leaves `..` in that `src_path`), an unresolvable `workspace = true` fails closed, and the `rustc` and `rustc-wrapper` of a PR's root `.cargo/config.toml` never run (the wrapper, outside the tree, would leave a marker). The test's cargo is not a rustup proxy, so it proves nothing about `rust-toolchain.toml`; that the copy holds no toolchain file, nested `.cargo` or `.gitattributes` is pinned by forge's `manifest_copy` tests. Unix only; needs git.
- `fetch_by_digest.rs`: `.github/actions/fetch-by-digest/fetch-by-digest.sh` against a fake `oras` (no network): a digest, artifact-type, media-type or size mismatch aborts with nothing installed, malformed repositories and out-dirs are usage errors, and the token travels on stdin (ADR-14, 05 T14). Unix only; needs `bash`, `jq`, `sha256sum` and `python3` >= 3.11.
- `plan.rs`: `plan` end to end (#55) on fixture PRs whose base moved on after the fork, fetched into an `ObjectRepo` and read through `ForgePullRequest`: the plugins come from the base config even when the head rewrites it (a trust-path change), only the head's own files are listed (merge base), a REST list git does not confirm fails the plan, and a submodule under base `.assay/` is refused. Needs git.
- `release_workflow.rs`: `.github/workflows/release.yml` runs only on `v*` tags with least-privilege jobs, and every action in `.github/` is pinned by commit SHA.
- `warm_target_workflow.rs`: `.github/workflows/warm-target.yml` (#69, ADR-21) runs only on pushes to `main` with least-privilege jobs, builds at the fixed path `/work/ws` (A-29) and cleans the workspace crates before packing; `publish` runs no repository code; `verify` restores the freshly published digest through the warm-target action and builds offline; the restore action fetches by digest, unpacks, then cleans, and removes its download directory on every exit.
- `warm_target.rs`: `.github/actions/warm-target/warm-target.sh` with fake `zstd` and `cargo` (nothing compiles, no network): pack and unpack round-trip `target/` and the registry index and cache (not `registry/src`); cargo's hardlinked build outputs are packed as regular files with their bytes and exec bit (`tar --hard-dereference`); an entry outside that allowlist, a link, a special file, a `..`, empty or `.` component, an absolute or control-character name, or a `target` that links out of the workspace refuses the archive with nothing written, as do one entry or one byte past the caps (lowered through the test-only `WARM_TARGET_TEST_MAX_ENTRIES` and `WARM_TARGET_TEST_MAX_BYTES`, which can only lower them), a cap variable that is not a count, and an empty archive (an archive at the caps is accepted); `clean` runs one `cargo clean --locked -p` per workspace package and refuses a name that is not a cargo package name. Unix only; needs `bash`, `jq` and `python3` >= 3.11.4 (tarfile extraction filters).
- `workflow_cache.rs`: no decision-bearing job uses the Actions cache (ADR-21, 05 T6). Allowlists both ways (wi-b5affa): a job is decision-bearing unless exempted by name (`rust.yml`'s `gate`, `aarch64`, `miri`), and such jobs and every composite action may use only listed cache-free actions; a `uses:` the line reader cannot judge is a finding. A local action counts only as one plain segment naming an existing `.github/actions/<name>/action.yml`, and the scan fails on an action directory without `action.yml` or with an `action.yaml`. `workflow.rs` holds the line readers shared with `release_workflow.rs`.
- `self_gate.rs`: `assay self-gate` as the `assay-self` exec plugin 02 §7 documents (the binary under test as its program), run through `ExecAdapter`, `ForgeSupervisor` and `run_gates`, so its document passes the gate contract: it passes on this repository, a rubric change without a snapshot update fails it, and no `ASSAY_RUN_KEY` or no corpus is `gate-error:exit-2`. Unix only.
- `supervisor.rs`: `ForgeSupervisor` with the system `kill`: a gate's exit code, signal, timeout (its whole group gone), output cap, working directory and exact environment; and `ClaudeHeadless` with it against a stand-in `claude` that leaves a helper in its group, which must be dead after a timeout and after a clean exit. Linux only (`/proc`, procps or util-linux `kill`).
- `temper.rs`: the temper adapter's Z2s checks end to end on fixture PRs built as git repositories and fetched into an `ObjectRepo`, read through `ForgeRevisions`, with a stand-in `node` at an absolute path (run by `ForgeSupervisor`) that accepts only the pinned invocation and prints a recorded scan, `tests/fixtures/temper-scan-expect.json` or `temper-scan-expect-two-lints.json`, modelled on temper 1.3.0's `scan --all --json` (which names only an `#[expect]`'s first lint). A raise, an unallowlisted `#[expect]`, a two-lint `#[expect]` whose first lint is allowlisted and gate-config drift fail; a pure decrease and an allowlisted single-lint `#[expect]` pass; vendored drift is reported. The real temper never runs. Unix only; needs git.
- `gh.rs` (#273): forge's `GhApi` run by `ForgeSupervisor` against a stand-in `gh` script (no network): the exact arguments, environment (only the six `GH_*`/`NO_COLOR` variables), working directory (the scratch `GH_CONFIG_DIR`, removed by `close`) and stdin; a paged `labels` read through `GitHub` following `Link`; a hanging `gh` stopped at its timeout and one writing past `GH_OUTPUT_CAP` stopped. Linux only.
- `status.rs`: `assay status` (#126): argument parsing and each usage error, `run_status` over fakes of the read port and bundle store writing a schema-valid `assay.status/1` document or the text, a refused status writing nothing, a failed writer reported, the binary's exit 2 naming #53, and `StatusCommand` parsing `--local` (and refusing `--pr`/`--full` with it).

Run: `cargo test -p assay-cli`.

## Do not
- Do not put use-case logic here; it belongs in `assay-app`.
- Do not relax `tests/it/layering.rs` to admit a new crate or edge without the H-16 decision that allows it.
