# Crate charter: `assay-runner`

## Purpose
The model-runner adapter: builds and supervises `claude -p` processes, parses `--output-format stream-json --verbose`, accounts for cost from `result` messages, and runs the auth and session-init preflight. It implements the `ModelRunner` port of `assay-app`. It is its own crate because it holds the headless profile and is the only code that starts a model process (ARC-07, `docs/architecture/02-architecture.md` §2, §7).

## Layer
adapter. Implements application ports; stream-json DTOs live here and are converted with `TryFrom` into domain types (OUT-01). No business rules.

## Allowed dependencies
- Workspace crates: `assay-app` and `assay-domain`, added by the story that first uses them.
- Third-party: crates on the pre-approved list in `.claude/temper.json`, each justified in the root decisions log when added.
- Never: `assay-forge`, `assay-gates`, `assay-cli`, `weighin-core` or temper code (P8). `crates/assay-cli/tests/it/architecture.rs` fails on a violation.

## Public surface
Workspace-internal, not published (`publish = false`). Re-exported from `lib.rs`:
- `ClaudeHeadless<K>` (`new`, `with_max_output_bytes`, `with_status_timeout`): the `ModelRunner` that runs `claude -p` with the 03 §8 profile, and the preflight's `CliProbe` (`claude --version`, then `claude auth status`, each in the same empty `Workdir` with the same environment and group kill, under a 30 s timeout and a 64 KiB output cap; #83, `src/headless/status.rs`), built from the CLI's path, a `Workdir` (absolute, empty, checked again before every call), a `HeadlessEnv` (the OAuth token plus explicitly passed variables) and a `K: GroupKill`.
- `ParentDeath` (`probe`, `probe_paths`, `setpriv`, `SETPRIV_PATHS`; #154, `src/headless/parent_death.rs`): how the CLI is started, given to `ClaudeHeadless::with_parent_death` and `ClaudeCanary::with_parent_death`. `probe` looks at `/usr/bin/setpriv`, then `/bin/setpriv`, never `PATH`; a candidate is used when it is absolute and, symlinks followed (merged /usr makes `/bin` a link to `usr/bin`), a regular file with an execute bit; one whose metadata cannot be read is not. The default (no call) starts the CLI directly, so the tests here choose a stand-in through `probe_paths` and never depend on the host.
- `GroupKill` (`kill_led_group` while the CLI is unreaped, `kill_group` after; implemented for `&K` too): the process-group kill the composition root lends; `assay-cli` implements it with `assay-forge`'s `GroupKiller` (wi-603c63).
- `read_session_init(&[u8]) -> Result<SessionInit, InitReadError>`: the `system/init` that opens a stream-json transcript, read into `assay-app`'s `SessionInit` (`src/stream/init.rs`, #121). It must be the first message, appear once and repeat no key in any object (`assay_app::parse_json_strict`); a plugin entry has exactly the string keys `name`, `path` and `source`; a list over 256 entries is refused before it is mapped.
- `read_cli_status(version, auth_status) -> Result<CliStatus, StatusReadError>` (`src/status.rs`, #83): `claude --version` must be one line `<version> (Claude Code)` (an optional final newline aside, no whitespace in the version); `claude auth status` one JSON object with no repeated key (`assay_app::parse_json_strict`) holding `loggedIn` (boolean), `authMethod` and `apiProvider` (strings); other fields are ignored.
- `ClaudeCanary<K>` (`new(program, HeadlessEnv, killer)`, `in_dir(parent)`): the `CanaryProbe` of `assay doctor` (03 §8, #121, `src/headless/canary.rs`). It plants a throwaway sandbox (`assay-canary-*`): a `HOME` whose `.claude/settings.json` names a user-scope mod in `env.CLAUDE_CODE_PLUGIN_DIRS`, and a working directory and `--add-dir` tree each with a skills-folder mod and an `AGENTS.md` and `CLAUDE.md` giving the canary word in two parts; each mod's `session.start` hook writes its own marker. It makes one call with the production argv (`Invocation`, shared with `ClaudeHeadless`; 2 turns, 0.25 AEU, 300 s), reads the init and the markers, and removes the sandbox, also when planting, the call or the inspection failed. It is also the `ProfileProbe` of `assay doctor --profile` (#84, `src/headless/canary/profile.rs`, `probe_profile(&ProfileWords)`): a sandbox of its own whose `HOME`, working directory and `--add-dir` tree each hold a `.claude/settings.json` planting a command hook on `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse` (matcher `*`), `Stop` and `SessionEnd` that writes `markers/hook-<scope>` (user, project, tree), `pr/TREE.md` and `outside/OUTSIDE.md` with their words, and `prompt/system.md` with the system word; one call with the production argv (`PROFILE_SCHEMA`, 4 turns, 0.25 AEU, 300 s) followed only by `--include-hook-events`, whose stdin prompt gives the prompt word and asks to `Read //proc/self/environ`, the tree file and the outside file. Both canaries share the sandbox lifecycle (`in_sandbox`) and `CanaryError`.
- `Replay`, `Recording` (`Completed`, `TimedOut`): the `ModelRunner` over recorded transcripts, classified exactly as live ones.
- Errors: `HeadlessError`, `WorkdirError`, `EnvVarError`, `ReplayError`, `CanaryError`, `StatusError` (with `StatusCommand`).

## Invariants
- Every spawned process has an owner that waits on or kills it, and a timeout (H-13).
- The CLI leads its own process group, which the `GroupKill` kills whole: at the timeout or the cap with `kill_led_group` before the CLI is reaped (so its pid, the group id, cannot have been reused), and after the CLI exits on its own with `kill_group`, so no process it started outlives the call. A call returns only once the group is shown gone, or with `HeadlessError::Kill`; the CLI itself is killed and reaped even when its group kill fails.
- Output read from a process is size-capped (H-13): stdout is spooled to an anonymous temporary file and the call is killed past the cap (32 MiB by default); stderr is discarded.
- The prompt reaches the CLI on stdin, from an anonymous temporary file written before the CLI starts, never as an argument (wi-9fe37e).
- With a `setpriv` from `ParentDeath`, every CLI start (model calls, both status commands, both canaries) is `<setpriv> --pdeathsig KILL -- <claude> <argv>`: `setpriv` arms `PR_SET_PDEATHSIG` and execs the CLI, so the pid, and with it the process group the group kill names, is the CLI's, and the CLI's argv below is unchanged. Under it the program is checked first (metadata, symlinks followed: a regular file with an execute bit), so a CLI that cannot be executed is still `HeadlessError::Spawn` and nothing is charged, rather than a `setpriv` that starts and exits 127 with an empty transcript; a program removed between the check and the exec is that residual, and so is what the check cannot see (an execute bit that is not the caller's, a script whose interpreter is missing): those start `setpriv`, exit 126 or 127 with an empty transcript and are charged at the budget, since `setpriv`'s exec failure cannot be told from the CLI's own exit and an over-charge is the safe side of the cost cap (review F1); `assay doctor` fails on such a host. The program must be absolute (`with_parent_death`'s docs; the composition root refuses a relative one). The parent-death signal fires when the thread that spawned the CLI exits: `supervise::run` spawns, polls and reaps on the calling thread and returns only once the CLI is reaped (or `Kill` says it may still run), so a worker thread (`assay-app`'s scoped specialist threads) cannot end before its CLI and kill it early.
- The argv is exactly 03 §8's, in its order (`tests/it/headless.rs` pins it flag for flag): `-p --output-format stream-json --verbose --json-schema --append-system-prompt-file --exclude-dynamic-system-prompt-sections --restricted --safe-mode --settings <03 §8 JSON> --tools Read,Grep,Glob --add-dir --permission-mode dontAsk --max-turns --max-budget-usd <cap>`. Never `--bare`. The tool set is a constant, not a call field.
- The environment is cleared; only the OAuth token, `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1` and passed variables reach the CLI, and `CLAUDE_CONFIG_DIR`, `CLAUDE_CODE_PLUGIN_DIRS` (a mod folder, #121), every credential or provider variable (`assay_app::is_provider_variable`: `ANTHROPIC_*`, `CLAUDE_CODE_USE_*`, `AWS_*`, `GOOGLE_*`, `CLOUD_ML_*`, `VERTEX_*`), `NODE_*` (#149: `NODE_OPTIONS` loads code, `NODE_EXTRA_CA_CERTS` with a proxy can intercept the token), `LD_*` and `DYLD_*` cannot be passed.
- Cost comes only from the last `result` message's `total_cost_usd`; a timeout, a transcript past the cap, or a missing or unreadable cost is charged at the call's budget, and a cost too large for `Aeu` saturates. The `result` decides the outcome: budget, turn and quota endings stay final even when a stray stdout line is unreadable, which only stops a success from counting (it becomes `Malformed`). Only `rate_limit_event`s with status `rejected` or `allowed_warning` are reported. The exit status is not consulted.
- Every `ModelResult` carries the transcript's `system/init` as `read_session_init` reads it (a timed-out or capped transcript included), so the preflight can judge the first call (#83). The status commands' outputs decide, not their exit status; a status command past its timeout or cap is an error, never a partial read.
- The CLI is killed only at the timeout or the output cap, never on assay's own mid-run accounting (03 §8).
- The profile canary reads its transcript fail-closed (`src/stream/profile.rs`, #84): `permissionMode` only from an opening `system/init`; `permission_denials` only from the last `result`, and only when every entry is an object with a string `tool_name` (else none); every message with a `hook_event` key, a `hook_*` subtype or a `hook*` type is a hook event (the 2.1.42 bundle's shapes, `system/hook_started|hook_progress|hook_response`).

## Runtime prerequisites
- Unix (`process_group`), and whatever the lent `GroupKill` needs: in production `assay-forge`'s, a Linux `/proc` describing this process and a procps or util-linux `kill` (`docs/architecture/06-operations.md` §5 F22).
- Optional: util-linux `setpriv` 2.33 or later (`--pdeathsig`) at `/usr/bin/setpriv` or `/bin/setpriv` (#154; GitHub's Ubuntu images have it). The probe does not run it, so an older one there is used and every CLI start fails with its usage error, which `assay doctor` fails on (review F2). With it, the composition root's `ParentDeath::probe` starts the CLI under `setpriv --pdeathsig KILL`, so the CLI is killed when assay is, even by a signal that runs none of assay's code (`SIGKILL`, or a default-action `SIGTERM` or `SIGINT`), which its own group does not receive.
- Known gap without `setpriv` (macOS, minimal images): the CLI is stopped by assay only, so it outlives an assay killed by a signal and runs until its own `--max-turns` or `--max-budget-usd` stop, or until the runner VM is torn down. `assay doctor` warns (`warn parent-death`). Residuals with it: the signal reaches the CLI alone, so a helper the CLI started (in its group) outlives a killed assay until it ends (`--tools Read,Grep,Glob` start no long-lived process); and an assay killed between the fork and `setpriv`'s `prctl` leaves the CLI unguarded (a window of microseconds).

## Errors
- `HeadlessError`: `may_have_run()` says whether to charge. Before the CLI starts (`RelativePath`, `Workdir`, `TimeoutTooLong`, `SpoolCreate`, `Spawn`, which under `setpriv` also covers a program that is not an executable file) it is `false` and nothing is charged; after it (`Supervise`, `Kill`, `ReadBack`) it is `true`, the cost is unknown and the caller charges the call's budget. `Kill` means the CLI or a process in its group may still be running, even after a CLI that exited cleanly: abort the job, do not retry.
- Model-side endings (budget, turns, timeout, quota, malformed output) are `ModelOutcome`s, not errors (ERR-10).
- `CanaryError` (`RelativeDir`, `Sandbox`, `NotUtf8`, `Run` wrapping `HeadlessError`, `Inspect`, `Cleanup`, `Abandoned`): the canary could not be planted, run, inspected or removed; `Abandoned` is a failure whose sandbox could not be removed either, with both causes and the path left behind. A sandbox that cannot be removed is an error, not a log line, because it holds the planted files.
- `StatusError` (`Run` wrapping `HeadlessError`, `TimedOut`, `TooLarge` naming the `StatusCommand`, `Read` wrapping `StatusReadError`): the CLI's status could not be read; the preflight fails with it as `PreflightFailure::Probe`.

## Test strategy
Integration tests in `tests/it/` parse recorded stream-json transcripts (`tests/fixtures/stream/`, one per outcome) through `Replay`, and drive `ClaudeHeadless` against a stand-in script (`tests/fixtures/fake-claude`) that records its pid, argv, stdin, cwd and environment; no test starts the real `claude` (TST-10). A recording `GroupKill` (`tests/it/support.rs`) pins which group is killed and whether the CLI was still unreaped then; that the group really dies, helpers included, is tested with the forge killer in `assay-cli` (`tests/it/supervisor.rs`). The timeout test runs a real 300 ms limit but asserts only the outcome and the charge, not how much the stand-in wrote before the kill. The init reader runs on `tests/fixtures/stream/init_2_1_296.jsonl`, a captured 2.1.296 init (paths and ids sanitised), against the allowlist `tests/fixtures/plugins-2.1.296.toml`, and on one fixture per unclean case. `ClaudeCanary` runs against `tests/fixtures/fake-claude-canary`, whose `knobs` file chooses a transcript and whether it runs the mods, follows the planted instruction, breaks the markers, removes the sandbox or replaces it with a file (it runs under `set -eu` and deletes only inside `*/assay-canary-*/`); "safety flags removed" is tested as a stand-in that ignores its flags (runs every mod and follows the instruction), which must fail both canaries. The parent-death guard (#154) has unit tests of the probe in `src/headless/parent_death.rs` (temporary files: executable, symlinked, missing, directory, not executable, dangling, relative) and integration tests in `tests/it/parent_death.rs` against `tests/fixtures/fake-setpriv`, which records its argv and execs the rest, used in place (never copied, ETXTBSY): the argv of a model call, the status commands and both canaries, the group killed being the CLI's own pid, and the spawn errors of a program that cannot be executed and of a `setpriv` removed after the probe. That the CLI really dies with a killed assay is `assay-cli`'s `tests/it/doctor.rs`, with the real `setpriv`; `fake-claude-canary`'s `HANG` knob serves it. Run: `cargo test -p assay-runner`. The profile canary runs against `tests/fixtures/fake-claude-profile` (`tests/it/profile_canary.rs`, #84), which also answers `--version` and `auth status` for the preflight's `ClaudeHeadless`, and whose knobs make it report another permission mode, run the planted hooks, stream a hook event, let the environ or outside read through, deny the tree read, answer without the prompt or system word, or refuse the argv; `IGNORE_FLAGS` (hooks run and streamed, both reads let through) must fail the hook, fence and outside checks. The stream observer has unit tests in `src/stream/profile.rs`. The preflight's readers run on `tests/fixtures/status/` (README there: the 2.1.296 version line and auth statuses for OAuth, API key and Bedrock captured and sanitised, one constructed fixture per refusal), and the probe against `fake-claude`, which answers `--version` and `auth status` from `FAKE_VERSION` and `FAKE_AUTH` and records them with `.version` and `.auth` suffixes; the 64 KiB cap is tested at the cap and one byte over.

## Do not
- Do not trust model output as authoritative; it is validated mechanically downstream (ADR-08).
