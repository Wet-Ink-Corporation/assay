# Crate charter: `assay-forge`

## Purpose
The GitHub adapter: REST and GraphQL through `gh`, App-token minting narrowed per job, diffs and objects, checks (compare-and-swap by check id and `external_id`), comments, timeline events, reactions and the ledger repository. It implements the `Forge` and `Ledger` ports of `assay-app`. It is its own crate because it is the only code that talks to GitHub and decides who counts as an owner (ARC-07, `docs/architecture/02-architecture.md` §2, §7).

## Layer
adapter. Implements application ports; wire DTOs for GitHub live here and are converted with `TryFrom` into domain types (OUT-01). No business rules.

## Allowed dependencies
- Workspace crates: `assay-app` and `assay-domain`, added by the story that first uses them.
- Third-party: crates on the pre-approved list in `.claude/temper.json`, each justified in the root decisions log when added.
- Never: `assay-runner`, `assay-gates`, `assay-cli`, `weighin-core` or temper code (P8). `crates/assay-cli/tests/it/architecture.rs` fails on a violation.

## Invariants
- Every external call has a timeout and a bounded response size (H-13).
- Every git process is built by `git::command::git`, the only `Command::new("git")` in production code; the only other process is the validated `GroupKiller` program that signals a timed-out process group (`tests/it/single_constructor.rs` enforces both). The constructor clears the environment to what `GitEnvironment` holds, sets `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=/dev/null` and `GIT_ATTR_NOSYSTEM=1`, and passes the §9 `-c` flags including `attr.tree=<empty tree>`; every diff carries `--no-ext-diff --no-textconv`.
- PR objects are fetched only by full SHA over https into a bare repository; refs such as `refs/pull/N/merge` cannot be expressed.
- Every child leads its own process group, has its stdio spooled to anonymous temporary files (no pipes, so no reader can block), and is waited on. A run completes only when the child has exited and its group has no live member; past the deadline, or past the output cap, the whole group is killed and must be verifiably gone (`/proc`), else `ProcessError::Kill`. A group whose leader is reaped is signalled only when `/proc` shows a live member: with none it is left alone, and when `/proc` cannot be read it is `ProcessError::Kill`, never a signal (pgid reuse). A diff past its cap is `needs-split`, never a hang.
- `GroupKiller::kill_group` signals a group only when `/proc` shows a live member; `kill_led_group` signals unconditionally, for a group whose leader is unreaped (so its id cannot have been reused). Both refuse groups 0 and 1 (`kill` reads `-0` as this process's group and `-1` as every process), this process's pid and its own process group (from `/proc/self/stat`), and return `Ok` only once no live member is left. The caller passes the pid of a child that leads its own group; the same pgid-reuse window as above applies to `kill_group` once that child is reaped.
- A `/proc` scan skips a process only when it is shown to be gone: its stat read fails with `NotFound` or `ESRCH`, or an unparseable stat line (an exiting process can yield an empty or truncated one; a line without the kernel's trailing newline counts as truncated) is followed by a re-read that does. A process whose stat stays unparseable is an error, never an empty group. Stat files are read as bytes: `comm` is raw and may be any bytes (`prctl(PR_SET_NAME)`, the executable's file name), so only the fields after its last `) ` must be text.
- `changed_files` diffs from the merge base (`base...head`, as GitHub lists a PR), never against what the base gained after the fork. Its raw and numstat records are joined one by one and refused (`GitError::Malformed`) when their counts or paths disagree; a raw record with an unknown mode, an abbreviated id, or a status inconsistent with its sides (an addition with a base side, a rename without a score) is refused too.
- Every changed path (both sides of renames) is policed; Rust sources, manifests and trust files can never be allowlisted, and allowlisted paths come back as `opaque`, never silently trusted.
- Files are read from commits as blobs (`ls-tree -r -z -l`, then one `cat-file --batch` by full object id, each a bounded git process), never checked out, so no filter, textconv or attribute applies. A listing past `max_entries` is `GitError::TooManyEntries`, a read whose listed sizes sum past `max_total_bytes` is `GitError::TooManyBytes` before git runs, a submodule or short id is `GitError::NotABlob`, and a blob whose batch header disagrees with its listed id or size is `GitError::Malformed`. ls-tree matches whole path components and expands no wildcard; an unknown mode, a short object id or a non-UTF-8 path is `GitError::Malformed`.
- A manifest copy (`manifest_copy`) is written only into an absent or empty directory and holds only what it wrote, none of it a symlink: each `Cargo.toml` and `Cargo.lock` file with its blob, every other file and every symlink to an in-tree file (or to nothing) as an empty regular file (cargo's target discovery needs `src/lib.rs`, `build.rs` and the rest to exist), and nothing under a `.cargo` directory or named `rust-toolchain`, `rust-toolchain.toml` or `.gitattributes`, at any depth and in any ASCII case. A tree the copy cannot mirror for cargo's discovery is refused, never copied with something missing (glob `members` must find every member the real build finds): a submodule is `CopyError::Submodule`, and a symlink whose target is absolute, not UTF-8, leaves the tree, is the root or another directory, or passes through another symlink (resolved lexically from the link's directory) is `CopyError::Symlink`. Every symlink is resolved, refused by those rules and reported in `symlinks`, including the neutralised ones the copy never writes (under `.cargo`, toolchain files, `.gitattributes`), since one can lie in an exec root (#65 review round 4). A tree path with an empty, `.` or `..` segment is `CopyError::Path`. Only git runs here; cargo is run by `assay-gates` (`PinnedCargo`), lent forge's supervisor by `assay-cli`.

- The App is recognised by numeric ids only, never by name or body (T7, ADR-11): a check run is the App's when `app.id` is `AppIdentity::app`; an issue comment when `performed_via_github_app.id` is the App and its `user` is the `Bot` with id `AppIdentity::bot`; a review comment (which carries no app) when its `user` is that bot. A same-named check or a marker comment by anyone else is skipped. Two App checks of one name on one head, or two App comments with one marker, are `ForgeError::Ambiguous`, never "pick one".
- `update_check_if` refuses an empty `expected` before any request (it would match an unset `external_id`), then reads the check by id, refuses a check of another app (`ForeignCheck`) and an `external_id` other than the expected one (`CompareAndSetError::Conflict`), and only then PATCHes: nothing is written on a refusal. GitHub offers no atomic check update, so this is a compare-and-set only under the per-head publish lock (02 §5). `upsert_comment` writes nothing when the body is unchanged, and refuses an empty marker, or a body that does not carry its marker, before any request (`InvalidRequest`), since the next run could not find that comment again.
- A retryable response (5xx; 429; 403 with `Retry-After` or GitHub's secondary-rate-limit message) is retried three times after the first attempt, waiting 1 s, 2 s and 4 s or `Retry-After` when given, never longer than 60 s, then `ForgeError::Exhausted` (displayed `publish-error: ...`, 06 F8). Other statuses are `Rejected` at once. A POST that failed retryably is sent again only after a probe (the list read again) shows it did not land, so a 5xx after a landed write never duplicates a check or comment.
- Every request path is an `ApiPath`: relative to `https://api.github.com/`, not empty, with no leading `/` or `-`, no `://`, no `..` segment and no control byte, space or backslash, so no path leaves the API or reads as a flag. A transport ends each request within its own timeout and stops reading past `MAX_RESPONSE_BYTES`; a body over it is `ResponseTooLarge`, refused unparsed.
- Every list is paged at 100 and refused past `MAX_LIST_ITEMS` items or 30 pages, never cut below the caller's limit (a caller with a limit stops reading once it has that many); a `Link: rel="next"` outside `https://api.github.com/`, or whose rest is not an `ApiPath`, is refused. `pulls_on_head` keeps only PRs whose head is the commit (GitHub's listing also names PRs that contain it); `current` and `newer_run` refuse a PR or run GitHub answered for another number, workflow or head. JSON is decoded through `assay_app::parse_json_strict` (a repeated key is refused) into wire DTOs; a missing field, a zero id, a short commit id, an unknown check status, conclusion, review state or reaction is `Malformed`. An unknown timeline kind is kept as `TimelineKind::Other(name)` with no field read.
- doctor's reads (`PrerequisiteForge`) are reads only and fail closed: a `contents` path that is empty, absolute or has an empty, `.` or `..` segment is refused unsent, each segment percent-encoded; a file that is not `type: file` with `base64` content, whose base64 is not strict, or whose decoded length differs from `size` is `Malformed`; a 404 is absence (`None`) only for files, directories and environments. An unknown ruleset target, rule or bypass actor type is kept by name (`Other`) and judged by the app, never read as a pass, and an unknown enforcement is `Malformed`; an environment policy that is both or neither protected and custom is `Malformed`; a permission answered for another user id is `Malformed`, and an unknown role name is `Access::Custom`.
- `gh api` (#273) runs with exactly `GH_TOKEN`, `GH_HOST=github.com`, `GH_PROMPT_DISABLED=1`, `NO_COLOR=1`, `GH_NO_UPDATE_NOTIFIER=1` and `GH_CONFIG_DIR` set to a scratch directory the transport owns and `TMPDIR` set to its mode-0700 `tmp/` (so a temporary file gh leaves when killed, such as `gh run download`'s `gh-artifact.*.zip`, stays inside the directory `close` removes; #301 review round 2), followed by whichever of `HTTPS_PROXY`, `https_proxy`, `NO_PROXY`, `no_proxy`, `SSL_CERT_FILE` and `SSL_CERT_DIR` its `GhEnvironment` holds (wi-fe594c), and nothing else (mode 0700, also the working directory, so no checkout is read), with arguments `api --include --method <M> --header Accept: application/vnd.github+json --header X-GitHub-Api-Version: 2022-11-28` [`--header Content-Type: application/json --input -` and the body on stdin] `-- <path>`. A path gh would fill in is refused before gh runs: one holding `{` or `}`, or `:owner`, `:repo` or `:branch` followed by anything but an ASCII letter, digit or `_` (gh's own placeholder pattern, anywhere in the path or query, so wider than a whole segment). `GhCall`'s `Debug` shows variable names, never values. stdout is capped at `GH_OUTPUT_CAP` (a 64 KiB head, `MAX_RESPONSE_BYTES` and one byte), so a body just over the cap reaches the adapter's `ResponseTooLarge` and a larger one stops gh. The output is read strictly: `HTTP/<version> <100..=599> <printable reason>\n`, `Name: value\r\n` lines (name ASCII letters, digits and `-`; value printable ASCII, space or tab), `\r\n`, the body; anything else is `GhError::Malformed`. gh's exit must agree with the status: 0 with a 2xx, 1 with any other status or with any status from `graphql` (gh exits 1 on GraphQL errors), else `GhError::Inconsistent`; a failure with no stdout is `NoResponse` with at most 512 bytes of stderr, the token replaced by `<redacted>`. `gh run download` (#273 part 2) runs through the same `GhRunner` with the same environment and working directory, a `GH_DOWNLOAD_TIMEOUT` deadline and a 64 KiB output cap, into a fresh 0700 `download-*` directory inside the scratch configuration directory, removed with `TempDir::close` on every path (a failure is `Cleanup` unless an earlier error stands); this crate never opens the zip. gh's extraction is bounded by a `DirectoryCap` on that directory (the bundle limit in bytes of regular files, 16 entries at any depth): the runner (`process::run_capped`) walks the tree, symlinks not followed and at most 17 entries per walk, on every 5 ms poll and once more after the group is gone, and kills the group past the cap (`ProcessError::DirectoryTooLarge`, read as `StoredBundle::TooLarge`). The residual overshoot is what gh writes in one poll interval plus the kill (roughly 5 ms times its write rate), on the disk of the scratch directory. A bundle fetch lists `actions/runs/<id>/artifacts` and requires exactly one artifact whose name starts with `assay-decide` (ASCII case folded; none is `Missing`, more is `Ambiguous`), named exactly `assay-decide-<32 lowercase hex>` (`Name`), with `workflow_run.id` the run and `workflow_run.repository_id` the repository (`OtherRun`); expired is `Expired` and a zip over the limit plus 1 MiB is `TooLarge`, both without a download. The directory must then hold exactly one entry, the regular file asked for (else `Contents`; empty is `Missing`), read with `take(limit + 1)` (over the limit `TooLarge`).
- The ledger adapter moves bytes and holds no record rule (those are `assay-app`'s). A read is `GET contents/<path>`: only `type: file` at exactly the requested path, a 40-hex `sha`, a listed `size` within `MAX_LEDGER_FILE_BYTES` before anything is decoded (`TooLarge` otherwise, the blob never fetched), canonical padded base64 (GitHub's line breaks aside) decoding to exactly `size` bytes, in a response within `MAX_RESPONSE_BYTES` (the app's 4 MiB file cap keeps the largest file's blob under it); `encoding: none` (over 1 MB) reads `git/blobs/<sha>`, which must name the same sha and size. A 404 is an absent file only after `GET repos/<owner>/<name>` answers for that repository, since GitHub answers 404 for a private repository the token cannot see. A write is `PUT contents/<path>` with `sha` when the condition is `At` (none for `Absent`) and is refused unsent past the cap; 409, and 422 for `Absent`, are `WriteOutcome::Conflict`; a retryable failure is followed by a read before any resend (contents equal: written; version unchanged: resend, GitHub's `sha` check letting at most one send land). Once an attempt went unanswered, a moved file or a resend refused as stale (409, or 422 on a create) is `LedgerRepoError::Unconfirmed { path }`, never `WriteOutcome::Conflict`: the write may have landed and been overwritten, and a conflict would make the app re-apply its change (#280 F1).
- The lease-ref adapter (#71) holds no lease rule (those are `assay-app`'s). A creation is `POST git/commits` (a parentless commit of the empty tree whose message is the lease, checked as GitHub wrote it, one trailing newline tolerated) and then `POST git/refs`; a 422, or an attempt retried after no answer, is settled by reading the ref: at our commit it was created, at another it exists, absent after a 422 the creation was refused. A message over `MAX_LEASE_MESSAGE_BYTES` is never sent and never returned. A read is `GET git/ref/<name>` (only that ref, pointing at a commit, with a full id) and `GET git/commits/<sha>`; a 404 is an absent ref only once the repository itself is visible, so a token without access never reads as a free slot. A deletion is only `git push --porcelain --force-with-lease=<ref>:<commit> -- <remote> :<ref>`, which receive-pack checks atomically; REST `DELETE /git/refs` is never sent (A-33). Its outcome is read from the porcelain report: `[deleted]` is `Deleted`, a `stale info` rejection is `Stale`, anything else is an error. The push is the hardened git layer's: the token travels in `http.<remote>.extraHeader` through `GIT_CONFIG_COUNT` variables (never on the command line, never in a URL, redacted from `Debug`), redirects are refused (`http.followRedirects=false`), and only `PushLocal` allows the file protocol.
- A minted token's permissions must equal the request plus GitHub's implicit `metadata: read`, its `repository_selection` must be `selected` and its repositories the requested ones, else `ScopeMismatch`.

## Runtime prerequisites
- Linux `/proc` describing this process (process-group supervision; `/proc/self/stat` must name `std::process::id()`, so a `/proc` from another pid namespace is refused, and must have the shape a `/proc` scan parses, trailing newline included, so such a `/proc` fails once at startup rather than every run) and a procps or util-linux `kill` in `/usr/bin` or `/bin`. Every `GroupKiller` is built after that preflight: `GroupKiller::system` (and so `GitEnvironment::from_process_env`) checks both, and `GroupKiller::at` checks `/proc` before accepting its program, so any `GitEnvironment` carries a checked killer. A failure is `KillerError::ProcUnavailable` (its `ProcFault` says whether the file was unreadable, malformed or named another process) or `KillerError::NotFound` (`docs/architecture/06-operations.md` §5 F22).
- git 2.42 or later (see the last invariant below).
- Spool files live in the system temp directory (`TMPDIR`). Each is bounded by the output cap plus what the group writes before it is stopped: up to one poll interval plus one `/proc` scan until the overshoot is seen, then up to the kill grace (`KILL_GRACE`, 5 s) while the kill runs and the group exits. When the kill fails (`ProcessError::Kill`) the group may still be writing and no bound holds.
- Attribute policing needs git 2.40 or later (`check-attr --source`), and `attr.tree` needs 2.42; an older git fails closed or ignores the setting (then in-tree attributes can only make numstat print `-`, which counts as maximum size).

## Errors
A `thiserror` enum per operation, separating GitHub rejections from transport failures (ERR-10). git: `GitError` (process failure, non-zero exit, unreadable output, missing commit, a tree or read over its `TreeLimits`, a submodule read as a blob), `CopyError` (`List` and `Read` with the `GitError`, `Inspect`, `DirectoryNotEmpty`, `Path`, `Symlink`, `Submodule`, `CreateDir`, `WriteFile`, `Canonicalize`: no manifest copy, so that side has no package set) and `AttributeError` (`Forbidden`, displayed as `gate-error:gitattributes`, or a `GitError`); both fail closed. GitHub: `ForgeError<E>` over the transport's error `E`: `Transport` (no response), `Rejected { status }` (GitHub refused), `Exhausted { status, attempts }` (publish-error after backoff), `Malformed`, `Json`, `ResponseTooLarge { cap }`, `TooMany { cap }`, `InvalidRequest` (refused before sending) and `Ambiguous` carry the `Operation`; `ForeignCheck { id }`, `UnknownApp { app }` and `ScopeMismatch` carry none. All fail closed (wi-b5affa). `ScopeError` refuses a token scope that would widen to the whole installation. `ProcessError::Kill` (inside `GitError::Process`) means a process group may still be running, unbounded: callers must abort the job (`gate-error`), not retry or run more git in the same job. `BundleFetchError` (#273 part 2) keeps the listing's `ForgeError<GhError>`, gh's `GhDownloadError` and the I/O errors of reading and removing the download directory apart from the refusals of what was listed or downloaded.

## Test strategy
Integration tests in `tests/it/` against recorded `gh` responses; no live network in tests (TST-10). The `gh api` transport is tested in `tests/it/github/gh.rs` over a fake `GhRunner` (the call it builds, exit and status agreement, malformed output) and its `--include` reader by unit tests in `src/github/gh/reply.rs`; `assay-cli` runs it under the real supervisor against a stand-in `gh`. The GitHub adapter is tested in `tests/it/github/` through a `Recorded` transport that replays the bodies under `tests/fixtures/github/` in order and keeps every request (so a test can show that nothing was written), and a `Waits` sleeper that records backoffs instead of taking them; `settings.rs` covers doctor's reads (#75); `recorded.rs` says which bodies were recorded from this repository and which follow GitHub's documented schema. The git layer is tested against fixture repositories built with plain git in a temporary directory (`tests/it/support.rs`; `tree.rs` and `manifest_copy.rs` read commits as data); fetch is covered by its argument list, not by a network fetch. The per-process `/proc` decision is tested with scripted reads, so the exit-mid-scan race is covered deterministically. Symlink resolution in `git/copy/link.rs` is property-tested with `proptest` (dev-dependency) against its pre-#184 reading. `GroupKiller::kill_group` and `kill_led_group` are tested against a real group with a grandchild, and against a spy kill program for the cases that must, or must not, signal. Its use by the gate and model-runner adapters is tested in `assay-cli` (`tests/it/supervisor.rs`). Run: `cargo test -p assay-forge`. `tests/it/github/artifacts.rs` drives the `BundleSource` over a scripted `GhRunner` that writes the download directory: the exact list and download calls, the directory removed, each refusal above, the limit and zip-cap boundaries and a failed download's stderr redacted; `tests/it/worktree/checkout.rs` reads `origin` and the branch from fixture repositories (one URL, none, two refused, user config ignored, a branch, detached).

## Do not
- Do not decide verdicts or severities here; that is the domain's job.
- Do not hold a write token longer than the operation needs.
