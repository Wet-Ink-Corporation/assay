# Crate charter: `assay-forge`

## Purpose
The GitHub adapter: REST and GraphQL through `gh`, App-token minting narrowed per job, diffs and objects, checks (compare-and-swap by check id and `external_id`), comments, timeline events, reactions and the ledger repository. It implements the `Forge` and `Ledger` ports of `assay-app`. It is its own crate because it is the only code that talks to GitHub and decides who counts as an owner (ARC-07, `docs/architecture/02-architecture.md` §2, §7).

## Layer
adapter. Implements application ports; wire DTOs for GitHub live here and are converted with `TryFrom` into domain types (OUT-01). No business rules.

## Allowed dependencies
- Workspace crates: `assay-app` and `assay-domain`, added by the story that first uses them.
- Third-party: crates on the pre-approved list in `.claude/temper.json`, each justified in the root decisions log when added.
- Never: `assay-runner`, `assay-gates`, `assay-cli`, `weighin-core` or temper code (P8). `crates/assay-cli/tests/it/architecture.rs` fails on a violation.

## Public surface
Workspace-internal, not published (`publish = false`).
- `git`: the hardened git layer for PR objects (`docs/architecture/03-contracts.md` §9, §2.1). `ObjectRepo` (bare, object-only repository: `init` into an absent or empty directory, `fetch` by `CommitSha` from an `HttpsRemote`, `numstat` under a wall-clock cap returning `DiffOutcome::{Measured, NeedsSplit}`, `changed_files` (the PR's file list for `plan`: `--raw` joined with `--numstat --text`, both over `base...head` and sharing one wall-clock cap, returning `ChangeListing::{Listed, NeedsSplit}` of `ChangedFile`s with both sides' `EntryKind`, `into_paths`), `police_attributes` over every changed path with an `AttributeAllowlist`, returning an `AttributeReport` whose `opaque` entries downstream gates must treat as fully changed, and, for reading a commit as data, `list_tree` (the `TreeEntry`s, with `EntryKind` `File`/`Executable`/`Symlink`/`Submodule`, object id and size, at or under a literal path or of the whole tree, refused past `TreeLimits::max_entries`), `read_blobs` (listed blobs, borrowed as `BlobRef`s (`From<&TreeEntry>`), in one `cat-file --batch`, their listed sizes summed and refused past `TreeLimits::max_total_bytes` before anything is read), `hash_blob` (the blob id of given bytes, `hash-object --no-filters`), for re-review (04 §7, #99) `ancestry(previous, head) -> Ancestry::{Ancestor, Rewritten, Unreachable}` (`rev-parse --verify --quiet <previous>^{commit}` for presence, exit 1 alone being `Unreachable` and any other failure an error, then `merge-base --is-ancestor`, exit 1 being `Rewritten`) and `range_diff(RangeDiffCommits { base, previous, head }, limit, cap) -> RangeDiffOutcome::{Listed, TooLarge, TooSlow}` (each side counted first with `rev-list --count`, past `MAX_RANGE_DIFF_COMMITS` (250) `TooLarge` without running; then `range-diff --no-color --no-notes --no-ext-diff --no-textconv` within `cap`, callers passing `RANGE_DIFF_TIMEOUT` (60 s); output past `limit` or the output cap is `TooLarge`, past `cap` `TooSlow`; it holds the commits' messages), and `manifest_copy` (a sanitised manifest-only copy of a commit for the pinned base cargo, returning `ManifestCopy` (`root`, `manifests`, `symlinks`: each accepted symlink as a `CopiedSymlink` with its lexically resolved target, which the app checks against every exec root, wi-b5affa) or `CopyError`)), `TreeLimits`, `GitEnvironment` (the inherited variables and the `GroupKiller`, captured once at the edge), `GitLimits`, `PolicedAttribute`, `is_protected_path`, and the errors `GitError`, `AttributeError`, `GlobError`, `ParseShaError`, `ParseRemoteError`. Parsing the allowlist out of base `.assay/plugins.toml` belongs to the config story (#62); this crate takes the globs as a parameter.
- `process`: the bounded process-group supervisor under the git layer, public so that `assay-cli` can lend it to the gate and model-runner adapters, which may not depend on this crate (wi-603c63). `run` (one child under `Limits`, returning `Captured`), `GroupKiller` (`system`, `at`, and for another supervisor's group `kill_group`, after its leader may have been reaped, and `kill_led_group`, while its leader is unreaped), and the errors `ProcessError`, `KillerError` (with its `ProcFault` cause). Each item has this one path; `git` no longer re-exports them.

## Invariants
- Every external call has a timeout and a bounded response size (H-13).
- Every git process is built by `git::command::git`, the only `Command::new("git")` in production code; the only other process is the validated `GroupKiller` program that signals a timed-out process group (`tests/it/single_constructor.rs` enforces both). The constructor clears the environment to what `GitEnvironment` holds, sets `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=/dev/null` and `GIT_ATTR_NOSYSTEM=1`, and passes the §9 `-c` flags including `attr.tree=<empty tree>`; every diff carries `--no-ext-diff --no-textconv`.
- PR objects are fetched only by full SHA over https into a bare repository; refs such as `refs/pull/N/merge` cannot be expressed.
- Every child leads its own process group, has its stdio spooled to anonymous temporary files (no pipes, so no reader can block), and is waited on. A run completes only when the child has exited and its group has no live member; past the deadline, or past the output cap, the whole group is killed and must be verifiably gone (`/proc`), else `ProcessError::Kill`. A group whose leader is reaped is signalled only when `/proc` shows a live member: with none it is left alone, and when `/proc` cannot be read it is `ProcessError::Kill`, never a signal (pgid reuse). A diff past its cap is `needs-split`, never a hang.
- `GroupKiller::kill_group` signals a group only when `/proc` shows a live member; `kill_led_group` signals unconditionally, for a group whose leader is unreaped (so its id cannot have been reused). Both refuse groups 0 and 1 (`kill` reads `-0` as this process's group and `-1` as every process), this process's pid and its own process group (from `/proc/self/stat`), and return `Ok` only once no live member is left. The caller passes the pid of a child that leads its own group; the same pgid-reuse window as above applies to `kill_group` once that child is reaped.
- A `/proc` scan skips a process only when it is shown to be gone: its stat read fails with `NotFound` or `ESRCH`, or an unparseable stat line (an exiting process can yield an empty or truncated one; a line without the kernel's trailing newline counts as truncated) is followed by a re-read that does. A process whose stat stays unparseable is an error, never an empty group. Stat files are read as bytes: `comm` is raw and may be any bytes (`prctl(PR_SET_NAME)`, the executable's file name), so only the fields after its last `) ` must be text.
- `changed_files` diffs from the merge base (`base...head`, as GitHub lists a PR), never against what the base gained after the fork. Its raw and numstat records are joined one by one and refused (`GitError::Malformed`) when their counts or paths disagree; a raw record with an unknown mode, an abbreviated id, or a status inconsistent with its sides (an addition with a base side, a rename without a score) is refused too.
- Every changed path (both sides of renames) is policed; Rust sources, manifests and trust files can never be allowlisted, and allowlisted paths come back as `opaque`, never silently trusted.
- Files are read from commits as blobs (`ls-tree -r -z -l`, then one `cat-file --batch` by full object id, each a bounded git process), never checked out, so no filter, textconv or attribute applies. A listing past `max_entries` is `GitError::TooManyEntries`, a read whose listed sizes sum past `max_total_bytes` is `GitError::TooManyBytes` before git runs, a submodule or short id is `GitError::NotABlob`, and a blob whose batch header disagrees with its listed id or size is `GitError::Malformed`. ls-tree matches whole path components and expands no wildcard; an unknown mode, a short object id or a non-UTF-8 path is `GitError::Malformed`.
- A manifest copy (`manifest_copy`) is written only into an absent or empty directory and holds only what it wrote, none of it a symlink: each `Cargo.toml` and `Cargo.lock` file with its blob, every other file and every symlink to an in-tree file (or to nothing) as an empty regular file (cargo's target discovery needs `src/lib.rs`, `build.rs` and the rest to exist), and nothing under a `.cargo` directory or named `rust-toolchain`, `rust-toolchain.toml` or `.gitattributes`, at any depth and in any ASCII case. A tree the copy cannot mirror for cargo's discovery is refused, never copied with something missing (glob `members` must find every member the real build finds): a submodule is `CopyError::Submodule`, and a symlink whose target is absolute, not UTF-8, leaves the tree, is the root or another directory, or passes through another symlink (resolved lexically from the link's directory) is `CopyError::Symlink`. Every symlink is resolved, refused by those rules and reported in `symlinks`, including the neutralised ones the copy never writes (under `.cargo`, toolchain files, `.gitattributes`), since one can lie in an exec root (#65 review round 4). A tree path with an empty, `.` or `..` segment is `CopyError::Path`. Only git runs here; cargo is run by `assay-gates` (`PinnedCargo`), lent forge's supervisor by `assay-cli`.

## Runtime prerequisites
- Linux `/proc` describing this process (process-group supervision; `/proc/self/stat` must name `std::process::id()`, so a `/proc` from another pid namespace is refused, and must have the shape a `/proc` scan parses, trailing newline included, so such a `/proc` fails once at startup rather than every run) and a procps or util-linux `kill` in `/usr/bin` or `/bin`. Every `GroupKiller` is built after that preflight: `GroupKiller::system` (and so `GitEnvironment::from_process_env`) checks both, and `GroupKiller::at` checks `/proc` before accepting its program, so any `GitEnvironment` carries a checked killer. A failure is `KillerError::ProcUnavailable` (its `ProcFault` says whether the file was unreadable, malformed or named another process) or `KillerError::NotFound` (`docs/architecture/06-operations.md` §5 F22).
- git 2.42 or later (see the last invariant below).
- Spool files live in the system temp directory (`TMPDIR`). Each is bounded by the output cap plus what the group writes before it is stopped: up to one poll interval plus one `/proc` scan until the overshoot is seen, then up to the kill grace (`KILL_GRACE`, 5 s) while the kill runs and the group exits. When the kill fails (`ProcessError::Kill`) the group may still be writing and no bound holds.
- Attribute policing needs git 2.40 or later (`check-attr --source`), and `attr.tree` needs 2.42; an older git fails closed or ignores the setting (then in-tree attributes can only make numstat print `-`, which counts as maximum size).

## Errors
A `thiserror` enum per operation, separating GitHub rejections from transport failures (ERR-10). git: `GitError` (process failure, non-zero exit, unreadable output, missing commit, a tree or read over its `TreeLimits`, a submodule read as a blob), `CopyError` (`List` and `Read` with the `GitError`, `Inspect`, `DirectoryNotEmpty`, `Path`, `Symlink`, `Submodule`, `CreateDir`, `WriteFile`, `Canonicalize`: no manifest copy, so that side has no package set) and `AttributeError` (`Forbidden`, displayed as `gate-error:gitattributes`, or a `GitError`); both fail closed. `ProcessError::Kill` (inside `GitError::Process`) means a process group may still be running, unbounded: callers must abort the job (`gate-error`), not retry or run more git in the same job.

## Test strategy
Integration tests in `tests/it/` against recorded `gh` responses; no live network in tests (TST-10). The git layer is tested against fixture repositories built with plain git in a temporary directory (`tests/it/support.rs`; `tree.rs` and `manifest_copy.rs` read commits as data); fetch is covered by its argument list, not by a network fetch. The per-process `/proc` decision is tested with scripted reads, so the exit-mid-scan race is covered deterministically. `GroupKiller::kill_group` and `kill_led_group` are tested against a real group with a grandchild, and against a spy kill program for the cases that must, or must not, signal. Its use by the gate and model-runner adapters is tested in `assay-cli` (`tests/it/supervisor.rs`). Run: `cargo test -p assay-forge`.

## Do not
- Do not decide verdicts or severities here; that is the domain's job.
- Do not hold a write token longer than the operation needs.
