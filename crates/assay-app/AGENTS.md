# Crate charter: `assay-app`

## Purpose
The use cases (`open`, `plan`, `admit`, `gate`, `review`, `decide`, `replay`, `report`, `doctor`, `status`) and the port traits they need (`ModelRunner`, `Forge`, `EventSink`, `GateRunner`, `Ledger`, `Clock`). It is its own crate because the ports must be owned by their consumer so adapters depend inward (ARC-03, `docs/architecture/02-architecture.md` §2).

## Layer
application. Orchestrates domain decisions and effects through ports. No concrete adapter, no HTTP or process types, no runtime choice, no `anyhow` in `pub` signatures.

## Allowed dependencies
- Workspace crates: `assay-domain` only, added by the story that first uses it.
- Third-party: crates on the pre-approved list in `.claude/temper.json`, each justified in the root decisions log when added.
- Never: `assay-forge`, `assay-runner`, `assay-gates`, `assay-cli`, `weighin-core` or temper code (P8). `crates/assay-cli/tests/it/architecture.rs` fails on a violation.

- The specialists' fan-out (S4, 04 §3, 06 §1-§2, #95, `src/specialists.rs`): `run_specialists(&R, SpecialistsRequest) -> Result<Specialists<R::Error>, InvalidPrompt>` with `R: ModelRunner + Sync`, `R::Error: Send`; `InvalidPrompt` only before any call (the pack starts with `-` or holds NUL). `SpecialistsRequest` (`roles: &[RequiredRole]` from the plan, run once each in roster order; `context_pack`; `intent`, the envelope already built, sent to `design` and `meta` only, between the pack and the instruction; `bundle`; `json_schema`; `system_prompt_file`; `add_dir`; `timeout`; `head_start`, `HEAD_START` = 20 s in production); `Specialists` (`roles: Vec<RoleReport>` in roster order, `run_cap`, `halt: Option<Halt>`, why the stage stopped starting calls; `cost()`, `completed_roles()`); `RoleReport` (`role`, `outcome`, `attempts`, `cost`, `rate_limits`, `init` of the last attempt that returned); `RoleOutcome` (`Completed(Structured)` with `source.role` stamped to the role that ran (#173), `Failed(RoleFailure::{Call(CallFailure), Runner, Spawn(io::ErrorKind), Panicked, Lost})` with `reason()`, `Skipped(Halt::{RunCap, RateLimited, Panicked})`); `MAX_MODEL_PROCESSES` (4). Invariants: never more than 4 calls in flight; the first role's call goes alone until the head start passes or it ends; every worker is a named scoped thread (`thread::Builder::spawn_scoped`) joined by the coordinator, which waits on a board (`Mutex<Vec<slot>>` and `Condvar`) that each worker posts to from a drop guard, so a panicking runner still posts and is joined (`Panicked`, charged at its cap, nothing more starts); a thread the OS refuses is `Spawn`, not charged. The run cap is the sum of the roles' caps; a role's first call starts only when `spent + reserved + cap <= run cap` (each call in flight reserves its budget until it settles at its real cost, or its budget when unknown), and when the next role does not fit with nothing in flight every role not yet started is `Skipped(RunCap)`. Only `Malformed` is retried, once, behind every first attempt (so a retry never takes a role's room), with a budget of `min(role cap, run cap - spent - reserved)`: while the cap does not fit and first attempts are in flight it waits for them to settle (never for another retry, #217), and with nothing left the role is `Failed(Call(Malformed))` after one attempt. No call's budget passes the run cap. `QuotaExhausted` or any kept rate-limit event (`rejected`, `allowed_warning`) pauses the stage (`RateLimited`): nothing more starts, and a retry not yet made leaves its role `Failed(Call(Malformed))`. Each call is bounded by `timeout`, enforced by the runner. Worst case: 6 roles × 2 attempts within the run cap; prompts copy the pack once per role, and each call is moved into its thread and handed back on join, so a retry reuses it.
- Sharding by dependency cluster (04 §3, #98, `src/shard.rs`, `src/specialists/sharded.rs`): `shard(&[ShardFile], &[Import]) -> Result<Sharding, ShardError>` over `ShardFile { path, pack_bytes }` and `Import { importer, imported }` (the caller reads the import edges from the head tree); `Sharding` (`shards()`, one to `MAX_SHARDS` = 3, `count() -> ShardCount`); `Shard` (`files()` changed, in input order; `importers()` unchanged, sorted, once per shard; `pack_bytes()`, at most `MAX_DIFF_BYTES`); `ShardCount` (`new` for 1 to 3, `ONE`, `get`); `full_run_cap(roles, ShardCount)`, per shard the distinct roles' caps plus `COORDINATOR_CAP` and the full verifier budget ($2.30, $2.60 with `meta`), times the count ($6.90, $7.80). `ShardError` (`NoFiles`, `TooManyFiles` past `MAX_SHARD_FILES` = 3,000, `TooManyImports` past `MAX_IMPORTS` = 65,536, `RepeatedFile`, `Overfull { withheld_bytes, files }`) refuses; nothing is sharded then. A pack within `MAX_DIFF_BYTES` is one shard; a larger one is clustered with union-find (union by size, path halving, no recursion) over changed-to-changed imports only, packed first-fit decreasing into at most 3 shards of `MAX_DIFF_BYTES`, and refused as `Overfull` when a cluster fits nowhere. Each unchanged importer is attached to every shard holding a file it imports, deduplicated with a hash set. Worst case: O((F + E) α) for the clusters, O(C log C) to sort them, O(3C) to pack, O(E) plus a sort per shard for the importers; no loop over pairs. `run_shards(&R, &ShardsRequest) -> Result<ShardedSpecialists<R::Error>, ShardsError>`: `ShardsRequest` is `SpecialistsRequest` with `packs: &[String]` (1 to 3) for `context_pack`; every shard's prompts are checked before any call (`ShardsError::{Count, Prompt { shard, source }}`); shards run one after another through the fan-out, each under its own run cap, so never more than 4 calls in flight; a shard whose `halt` is `RateLimited` or `Panicked` skips every later shard (each role `Skipped` for that halt), one halted by `RunCap` does not. `Specialists::halt` is the strongest halt (`RunCap < RateLimited < Panicked`), so a pause or panic in a retry after a run-cap halt still stops later shards; the roles still due keep the first halt as their skip reason. `ShardedSpecialists` (`shards: Vec<Specialists>`; `cost()`, `completed_roles()` = completed on every shard, `run_cap()` summed).
- The coordinator (S5, 04 §3 "Coordinator", §4 step 7, #96, `src/coordinate.rs`): `coordinate(&impl ModelRunner, CoordinateRequest) -> Coordination<E>`, total, for `full`; `merge_mechanically(&[ValidFinding]) -> Coordination<E>` for `lite` and `micro` (`NotNeeded`). `CoordinateRequest` (`findings: &[ValidFinding]`, `bundle`, `system_prompt_file`, `add_dir`, `timeout`); `Coordination` (`ranked: Vec<Ranked>` in rank order, `merged: Vec<Merged>` in input order, `merged_by: MergedBy::{Coordinator, Mechanical}`, `failure: Option<CoordinatorFailure<E>>`, `attempts`, `cost`, `rate_limits`, `refusals: Vec<CoordinationRefusal>`; `outcome() -> SupportOutcome` for `decide`, `events()`); `Ranked` (`index` into the findings given, `group: GroupId`, `placement`); `Merged` (`index`, `into`, `fp`: the merged finding's own fingerprint, which its `duplicate` event names, #263); `GroupId` (`Display` `g<n>`, numbered in rank order); `CoordinatorFailure` (`Call(CallFailure)`, `Runner(E)`, `TooMany { findings }`, with `reason()`: `unavailable` for a runner error, `cap` for too many); `CoordinationRefusal` (`Shape`, `UnknownFinding`, `Repeated`, `Missing`, `EmptyGroup`, `MixedClasses`, `SeveralMajors`, `DuplicateOutsideGroup`, `DuplicateElsewhere`, `DuplicateTooSevere`, `DuplicateOtherClass`, `DuplicateOtherKind`, `DuplicateApart`, `DuplicateOutranks`, `NoiseTooSevere`, `NoiseMerged`); `COORDINATION_SCHEMA`, `COORDINATOR_MAX_TURNS` (10), `COORDINATOR_CAP` ($0.30), `MAX_COORDINATED_FINDINGS` (64). Invariants: every finding given ends exactly once, ranked or merged; a merge (`may_absorb`) needs the same file and side, a severity no higher than the keeper's, and never puts a new finding under a pre-existing one; findings of one fingerprint are merged mechanically before any call, and only those merges may absorb a `major` or `blocker`; a coordinator duplicate must also be below `major`, of the keeper's `class` and `kind`, on overlapping lines; a coordinator group holds at most one `major` or `blocker`, so the coordinator can never lower rule 7's distinct-major count; the reader maps ids to positions as it reads, so the accepted plan needs no lookup; the coordinator sees only `{id, class, severity, confidence, pre_existing, file (at head), line, title, evidence, trigger, group_hint}` of at most 64 distinct findings, and answers in ids only, read strictly (wi-b5affa): one refusal variant per rule, a refused or malformed answer retried once, then the mechanical merge with the failure kept. The stage spends at most `COORDINATOR_CAP`, retries included, each attempt getting what is left; nothing left is `cap`; a runner error is charged at the attempt's budget. Rank: noise last, then severity, then confidence, then the coordinator's order (input order when mechanical); a group's findings share a `class`; noise moves only a `minor` or `nit` to the summary. Events: a `FindingDisposed` `duplicate` per merge, then `CoordinatorFinished` or `StageDegraded{stage: coordinator}`. Worst case: O(n log n) in the findings, and reading the answer is linear in the smaller of the answer and the findings shown (each accepted id marks one finding).
- The blind verifier (04 §3, §4 step 8, §7, #91, #97, `src/verify.rs`): `verify(&impl ModelRunner, VerifyRequest) -> Verification<E>`, total. `VerifyRequest` (`tier: VerifierTier`, `repository`, `findings: &[ValidFinding]`, `carried: &[CarriedFinding]`, `bundle`, `system_prompt_file`, `add_dir`, `timeout`); `VerifierTier` (`Full`, `Lite`, `Micro`; `calls`; `budget`, the stage total of `VERIFIER_CAP` per call; `TryFrom<Tier>`, refusing `trivial` and `needs-split` with `UnsupportedTier`); `CarriedFinding` (re-review's, below); `ClaimRef` (`Raised(FindingRef)`, `Carried(usize)`); `Verification` (`findings: Vec<VerifiedFinding>` and `carried` in input order, `failure: Option<VerifierFailure<E>>`, `attempts`, `cost`, `rate_limits`, `refusals: Vec<VerdictRefusal>`; `outcome() -> SupportOutcome` for `decide`, `events()`); `VerifiedFinding` (`at: ClaimRef`, `fp` (named by its `verifier-rejected-downgraded` event, #263), `raised`, `severity`, `status: VerifierStatus`, `verdict()`); `VerifierStatus` (`Judged(Judgement)`, `NotCandidate`, `NoVerifier`, `OverCap`, `Unverified`); `Judgement` (`verdict`, `reason: VerdictReason`); `VerifierFailure` (`Call { at, reason: CallFailure }`, `Runner { at, source }`); `VERDICT_SCHEMA`, `MAX_REASON_CHARS` (200), `VERIFIER_MAX_TURNS` (8), `VERIFIER_CAP` ($0.08). The live reject rate (QA-12): `VerdictTally::of(&[Event])` (`confirmed`, `refuted`, `unclear`, `runs`; `reject_rate() -> RejectRate::{TooFewRuns, Within, Below, Above}`, 10 % to 60 % inclusive over at least `REJECT_RATE_MIN_RUNS` = 20 runs, in integers). Invariants: this run's findings reach the verifier only Z3-validated; carried findings are the caller's, taken from findings already published and read as untrusted text by `read_carried` (re-review owns their provenance and trust, #212 F1). Each call's user prompt is one JSON object of exactly `{file (at head), line, class, claim (the title), trigger}`, a blank line, then the verifier instruction (for a carried claim the carried-verifier instruction), never `body`, `fix`, `evidence` or the rest. Every carried finding is a candidate and is judged first, by severity then in order; then this run's findings of at least `major`, blockers first, then by confidence, then in order; at most `VerifierTier::calls` in all (5 in `full`, 3 in `lite`, none in `micro`). A carried claim is the same five-field object, followed by the carried-verifier instruction. The stage spends at most `VerifierTier::budget` ($0.40 full, $0.24 lite), retries included: each attempt's budget is the smaller of `VERIFIER_CAP` and what is left, and nothing left stops the stage as `cap` before any call. A verdict is read strictly (wi-b5affa): an object of exactly `verdict` (one of the three codes, exact case) and `reason` (printable ASCII, not blank, at most 200 characters, clear of the injection screen of validation step 5); anything else, like a `Malformed` outcome, is retried once and is then `malformed`; each refused verdict's `VerdictRefusal` is kept. `confirmed` keeps the severity, `refuted` lowers it to `minor` with the reason attached (`FindingDisposed` `verifier-rejected-downgraded`), `unclear` lowers it one level; each verdict emits `FindingVerified`. The first call that ends without a verdict stops the stage: `outcome()` is `Failed` with the `CallFailure` (`cap`, `turns`, `timeout`, `unavailable` for quota or a runner error, `malformed`), a `StageDegraded` event names it, verdicts already given stand, every candidate within the cap not yet judged is `Unverified`, shown at most `major` (06 §6), and a candidate past the cap stays `OverCap` at its severity. ## Invariants
- `admit` (#72) fails closed (wi-b5affa) and spends only after every read it needs: it refuses a re-run and a plan document it did not expect before any port call, reads the PR's state, the cost window and the slots at one clock reading, decides reuse, then the budget gate (3 admissions per PR per hour, then the reservation under the 24-hour day cap, a classless `full` run tried as `lite`, a run with a class never degraded), builds the context pack, and only then takes a slot (reaping expired leases before any wait, at most 20 waits of 30 s). Holding the slot, it reads the costs and slots again (its own lease left out) and re-runs the gate, so reservations made during the wait count (R3-27); if that defers, it releases the slot by compare-and-set and defers for budget; it never reserves more than its lease, so no rival's read undercounts the run (refs cannot be rewritten by compare-and-set, #300): a price at or below the lease's spends, a price above it (a `full` run degraded before the wait that fits at the slot, a grant recorded during the wait) spends at the price the lease was taken for while that still fits, leaving a grant recorded since waiting, and otherwise it releases the slot the same way and defers with `slot-busy`. Then it appends the `reserved` cost record, consumes the waiting grant it reserved for, and writes the run description; any failure there releases the slot by compare-and-set (`AfterSlot`). A deferral writes the PR's deferral record (kept as is for the same head, reset to count 0 for a new one) and takes no slot; a run that spends nothing reads no port.
- Ports speak domain types; no adapter type crosses a port signature (ARC-03).
- `validate` is pure, total and deterministic, so Z3 and Z4 run one function and, without gate findings, agree exactly; each file is indexed once per call. Every input ends kept or dropped by exactly one dropping disposition; non-dropping ones (`line-not-in-diff-moved`, `pre-existing`, `cap-exceeded` with `from`/`to`, `no-trigger`) are recorded as they apply. A document's findings past the 256th are dropped before step 2 as `cap-exceeded` without `from`/`to` (each costs a search of its file; wi-641e1a); with `from`/`to`, `cap-exceeded` is the role's severity ceiling and does not drop. The severity ceiling is that of the role the call ran as (`ReviewerDocument::role`, the caller's, never read from the document; #173), and a document whose `source.role` is not that role, one outside the roster included, is `schema`; `rule` over 128 bytes and `group_hint` over 100 characters are `schema`. Evidence needs 12 non-whitespace characters after normalisation, summed across wildcard pieces, else `evidence-missing`. A kept finding's `line` is a line where its normalised evidence starts (nearest to the cited line, the earlier on a tie, spanning at most 50 lines); its `side` is explicit (base for a deleted file); its `evidence`, and an interaction's `caller.evidence`, are replaced by the tree's own lines they matched (cut to 400 characters), so the quotes the model wrote never reach the output; the fingerprint, and the occurrence index (earlier matches of those lines in the same function), are computed over those lines, so every quote of one line gets one fingerprint. Only an interaction may carry a `caller`; on any other finding it is `schema`. The other free-text fields remain model text: the screen is a heuristic, and neutralising them at publish time is a separate backstop (the publication sanitiser, #88). An `end_line` past the file or outside the hunk holding `line` is dropped and the finding goes to the summary. Step 4 applies the role's severity ceiling (`cap-exceeded`), then requires a trigger with an alphanumeric character other than an invisible one from `major` up (`no-trigger`). Every free-text field, `rule`, and an interaction's caller evidence as the model wrote it are injection-screened; the tree's lines that replace `evidence` and `caller.evidence` are repository content, published as code, and are not (wi-d4735c). The screen refuses rather than models (wi-b5affa): wherever it cannot be sure how GitHub renders text, it reads it as prose and flags it. Precondition: each free-text field is published as its own markdown block, so no markup from one field or from the publisher's template continues into another; the publisher owns that (#175), and the screen's reading of a field holds only under it. CRLF is read as LF; a carriage return that remains flags the field outright (`Html`). Only a plain field has anything removed as code: one with no `|` (tables), no whitespace other than ASCII space, tab and line feed, and no line beginning with a container marker (`>`, `-`, `*`, `+`, `N.`, `N)`); any other field is screened whole as prose. In a plain field it removes only closed fences (within three spaces of indent, a backtick fence's info string without a backtick) whose info string is empty or a single word of `[a-z0-9_+-]` on an allowlist of inert languages (`rust`, `rs`, `toml`, `json`, `yaml`, `yml`, `text`, `txt`, `plain`, `sh`, `bash`, `shell`, `console`, `diff`, `patch`, `sql`, `c`, `cpp`, `go`, `python`, `py`, `js`, `ts`, `javascript`, `typescript`, `html`, `xml`, `ini`, `makefile`, `dockerfile`; ASCII case-insensitive); any other closed fence (mermaid, math, an unknown or encoded word, extra words) and an unclosed fence keep their lines raw as prose, with no code span stripped, and code spans only from a paragraph every backtick run of which pairs within its own line (a line is blank only if it holds nothing but spaces and tabs); everything else is prose. Text is lowercased ASCII-only for the link checks, so no non-ASCII letter folds into an ASCII one (U+212A). Every URL is judged on the longest extent a renderer could read, ending only at an ASCII space or control: a written-out one also at `<` (GFM autolink), which may point to the allowlist (an authority of `[a-z0-9.-]` only) or the repository and is foreign if it holds a non-ASCII character or is cut by a character other than `)` or `>`; a markdown link destination also at an unbalanced `)` (or the closing `>` of an angled one), which must be an ASCII, absolute `https` URL into the repository after `.`/`..` resolution of the whole destination, with no `%` or `\` in its path and no `&` anywhere. A backtick anywhere between `](` and the link's closing `)`, title included, flags the text, as do `]:` anywhere in the text, code spans included (definitions are parsed before spans), TeX's `\href` and `\url` anywhere (math renders them as links), reference links, character references (`&#…`, `&name;`), an email address (GFM makes it a `mailto:` link), a reference into another repository (`owner/name#digits` or `owner/name@` and 7 to 40 hex digits, unless `owner/name` is the repository; `user@` and 7 to 40 hex digits, a commit in that user's fork, unless `user` is the repository's owner; ASCII case-insensitive) and an `@` followed by a name character unless an ASCII letter or digit precedes it. A suggestion fence is found inside any number of containers, and a fence line whose info string holds `&` or `\` counts as one. The link scan is forward-only and each URL is capped at 2048 characters. Evidence search tries one start per kept line, so it is linear in the file plus the evidence length per line, and each file is searched once per distinct normalised evidence. The enclosing-function pass finds each line's opener by binary search. The enclosing symbol is an indentation heuristic over formatted Rust: deterministic, not a parser. Nothing in it quotes model text.
- The egress scan runs first on every finding of a schema-valid document, past the 256 cap included, before step 1's shape checks and before step 2 replaces `evidence` and `caller.evidence`; a hit drops the finding as `injection-suspect` and records one `EgressHit` (its first field, in `FreeTextField` order). It reads every field the reviewer wrote (`title`, `body`, `fix`, `trigger`, `evidence`, `expected_behavior`, `group_hint`, `rule`, an interaction's caller evidence). The token is encoded, the text never decoded: text is folded as the screen folds it (invisibles dropped, lookalike and fullwidth letters read as Latin, lowercase) and reduced to ASCII letters and digits, and any 12-character window of the token, of its base64 (whole groups starting at each of its first three bytes, so every alignment; the alphabets differ only in what normalisation strips) or of its hex is a `Token` hit; the windows are also slid over a hex-only view (folded, lowercase, the byte prefixes `0x`, `\x`, `\u00`, `u+00`, `&#x` and `%` deleted, decimal references of a byte `&#115;` read as its hex, everything but `[0-9a-f]` dropped), so hex written one byte at a time is found too. Before that, every character drawn like one ASCII letter or digit is read as it, from one generated, checked-in table (`src/validation/egress/lookalikes.rs`, 2,828 entries, Unicode 15.1, no new dependency; the generator and the sha256 of the pinned `confusables.txt` are in its doc comment): canonical decompositions to an ASCII letter, `LATIN ... LETTER X WITH ...`/`BAR`, small capitals, dotless i and j, superscript and subscript digits, NFKC to one ASCII letter or digit (fullwidth, mathematical, enclosed), decimal digits of every script, then the single-character skeletons of `confusables.txt` (Cyrillic, Greek, Lisu, Cherokee and more), except the skeletons `l` and `O`, which stand for several ASCII characters and stay unread. Read characters are known symbols, so `O(n²)` is prose and a raised, dotted, stroked or other-script token is still the token. Any other non-ASCII alphanumeric (CJK, `ß`, an unread confusable) becomes a wildcard in both views rather than being deleted: a 12-symbol window holding wildcards matches a token window when every other symbol equals the token's at its position and there are at least 7 of them (normalised view; 36^-7, about 1e-11, per token window compared) or 9 (hex view; 16^-9), so an attacker must find five unread characters in every twelve. Only a numeric character or a letter-like symbol (Mathematical Alphanumeric Symbols, Enclosed Alphanumerics, superscripts and subscripts, small capitals and modifier letters) that the table does not read is `Obfuscated` (`½`, `⑳`, `Ⅻ`, a mathematical Greek letter): refused, so quoting one from the tree drops the finding too (fail closed). Ordinary non-ASCII prose raises no hit (review rounds 3 and 4). Accepted residual risk (05 T2): octal escapes (`\163`) and decimal byte lists (`115, 107`) get no view of their own; only the run rule and the per-character rules see them. A run of 20 or more characters (Unicode alphanumerics and invisible characters, so a zero-width character cannot cut one) that is not, whole, a run of the indexed texts or one of the run's own commit ids is `UnexplainedRun` (wi-b5affa: what is not provably the tree's own text is a hit; a prefix of a longer identifier is not explained). Z4 holds no token, so it applies the run rule only, and Z3 can drop more than Z4; Z3 and Z4 agree exactly when given equal scans. `scan_artifact` reads the bytes as text and, when they are strict JSON, every key and string decoded, and otherwise (a repeated key, a trailing byte, nesting past the parser's depth) the text with its escapes read back (`\uXXXX` with surrogate pairs, `\xHH`, JSON's single-character escapes; any other escape, a lone surrogate or a cut escape is `TokenShaped`), for the token windows, a private key header, `sk-ant-` in any ASCII case, and AWS key ids and mixed runs of 32 or more characters (not 40 or 64 lowercase hex) the index does not hold; it skips the run rule, since artifacts carry digests assay stamps. Quoting `sk-ant-` anywhere, even from the tree, fails closed by design: the prefix is never explained. ## Errors

## Test strategy
Integration tests in `tests/it/` drive use cases against in-memory fakes of the ports (TST-09); no real network, processes or clocks. Validation has one test per step and per disposition it emits (`tests/it/validation/`), a Z3-versus-Z4 test, and property tests (dev-dependency `proptest`) for determinism, relocation onto matching lines only, and each finding ending kept or dropped exactly once. Local mode (#130): `tests/it/check_events.rs` drives `check_local` with a sink on a fake clock (250 ms per reading) and pins the exact stream (a kept and a disposed finding, degraded, budget-exhausted and unavailable reviews, a gate that does not run locally, a refused event before the gate and before the model, a clock before 1970) and the recorded stream `tests/fixtures/events/check-local.jsonl`, the mod's fixture, byte for byte; `tests/it/status_local.rs` pins the `local-fresh`, `local-stale` and `local-missing` goldens, dedupe and gate merge, each refusal (an older report format included) and each cap at the cap and one past it. Run: `cargo test -p assay-app`. doctor's repository checks (#75): `tests/it/prerequisites.rs` over `prerequisites_fakes.rs`, a repository and ledger meeting every prerequisite, each failing fixture failing exactly the prerequisite it breaks; the workflow reader and facts are unit-tested in `src/doctor/prerequisites/{yaml,workflow}/tests.rs`, including this repository's own `.github/workflows`. doctor's profile checks (#84): `tests/it/doctor_profile.rs` with `doctor_profile_fakes.rs` (a fixed-status `CliProbe`, a profile probe that builds its run from the words, a clean run): every check's pass and each failure, a failed preflight drawing no nonce and making no call, the token and its base64 in the transcript, an unscannable escape, denials of another tool or a relative path not counting, and the flag lines; the minimum's parts are pinned in `src/doctor/profile/judge.rs`. `tests/it/status_identities.rs` (#273 part 2) pins the base identity lists: absent files, owners and approvers privileged, agents, and each refusal; `tests/it/golden.rs` reads the shipped rubric through `read_rubric` and a broken one with its line.
