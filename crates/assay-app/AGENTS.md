# Crate charter: `assay-app`

## Purpose
The use cases (`open`, `plan`, `admit`, `gate`, `review`, `decide`, `replay`, `report`, `doctor`, `status`) and the port traits they need (`ModelRunner`, `Forge`, `EventSink`, `GateRunner`, `Ledger`, `Clock`). It is its own crate because the ports must be owned by their consumer so adapters depend inward (ARC-03, `docs/architecture/02-architecture.md` §2).

## Layer
application. Orchestrates domain decisions and effects through ports. No concrete adapter, no HTTP or process types, no runtime choice, no `anyhow` in `pub` signatures.

## Allowed dependencies
- Workspace crates: `assay-domain` only, added by the story that first uses it.
- Third-party: crates on the pre-approved list in `.claude/temper.json`, each justified in the root decisions log when added.
- Never: `assay-forge`, `assay-runner`, `assay-gates`, `assay-cli`, `weighin-core` or temper code (P8). `crates/assay-cli/tests/it/architecture.rs` fails on a violation.

- The specialists' fan-out (S4, 04 §3, 06 §1-§2, #95, `src/specialists.rs`): `run_specialists(&R, SpecialistsRequest) -> Result<Specialists<R::Error>, InvalidPrompt>` with `R: ModelRunner + Sync`, `R::Error: Send`; `InvalidPrompt` only before any call (the pack starts with `-` or holds NUL). `SpecialistsRequest` (`roles: &[RequiredRole]` from the plan, run once each in roster order; `context_pack`; `intent`, the envelope already built, sent to `design` and `meta` only, between the pack and the instruction; `bundle`; `json_schema`; `system_prompt_file`; `add_dir`; `timeout`; `head_start`, `HEAD_START` = 20 s in production); `Specialists` (`roles: Vec<RoleReport>` in roster order, `run_cap`, `halt: Option<Halt>`, why the stage stopped starting calls; `cost()`, `completed_roles()`); `RoleReport` (`role`, `outcome`, `attempts`, `cost`, `rate_limits`, `init` of the last attempt that returned); `RoleOutcome` (`Completed(Structured)` with `source.role` stamped to the role that ran (#173), `Failed(RoleFailure::{Call(CallFailure), Runner, Spawn(io::ErrorKind), Panicked, Lost})` with `reason()`, `Skipped(Halt::{RunCap, RateLimited, Panicked})`); `MAX_MODEL_PROCESSES` (4). Invariants: never more than 4 calls in flight; the first role's call goes alone until the head start passes or it ends; every worker is a named scoped thread (`thread::Builder::spawn_scoped`) joined by the coordinator, which waits on a board (`Mutex<Vec<slot>>` and `Condvar`) that each worker posts to from a drop guard, so a panicking runner still posts and is joined (`Panicked`, charged at its cap, nothing more starts); a thread the OS refuses is `Spawn`, not charged. The run cap is the sum of the roles' caps; a role's first call starts only when `spent + reserved + cap <= run cap` (each call in flight reserves its budget until it settles at its real cost, or its budget when unknown), and when the next role does not fit with nothing in flight every role not yet started is `Skipped(RunCap)`. Only `Malformed` is retried, once, behind every first attempt (so a retry never takes a role's room), with a budget of `min(role cap, run cap - spent - reserved)`: while the cap does not fit and first attempts are in flight it waits for them to settle (never for another retry, #217), and with nothing left the role is `Failed(Call(Malformed))` after one attempt. No call's budget passes the run cap. `QuotaExhausted` or any kept rate-limit event (`rejected`, `allowed_warning`) pauses the stage (`RateLimited`): nothing more starts, and a retry not yet made leaves its role `Failed(Call(Malformed))`. Each call is bounded by `timeout`, enforced by the runner. Worst case: 6 roles × 2 attempts within the run cap; prompts copy the pack once per role, and each call is moved into its thread and handed back on join, so a retry reuses it.
- Sharding by dependency cluster (04 §3, #98, `src/shard.rs`, `src/specialists/sharded.rs`): `shard(&[ShardFile], &[Import]) -> Result<Sharding, ShardError>` over `ShardFile { path, pack_bytes }` and `Import { importer, imported }` (the caller reads the import edges from the head tree); `Sharding` (`shards()`, one to `MAX_SHARDS` = 3, `count() -> ShardCount`); `Shard` (`files()` changed, in input order; `importers()` unchanged, sorted, once per shard; `pack_bytes()`, at most `MAX_DIFF_BYTES`); `ShardCount` (`new` for 1 to 3, `ONE`, `get`); `full_run_cap(roles, ShardCount)`, per shard the distinct roles' caps plus `COORDINATOR_CAP` and the full verifier budget ($2.30, $2.60 with `meta`), times the count ($6.90, $7.80). `ShardError` (`NoFiles`, `TooManyFiles` past `MAX_SHARD_FILES` = 3,000, `TooManyImports` past `MAX_IMPORTS` = 65,536, `RepeatedFile`, `Overfull { withheld_bytes, files }`) refuses; nothing is sharded then. A pack within `MAX_DIFF_BYTES` is one shard; a larger one is clustered with union-find (union by size, path halving, no recursion) over changed-to-changed imports only, packed first-fit decreasing into at most 3 shards of `MAX_DIFF_BYTES`, and refused as `Overfull` when a cluster fits nowhere. Each unchanged importer is attached to every shard holding a file it imports, deduplicated with a hash set. Worst case: O((F + E) α) for the clusters, O(C log C) to sort them, O(3C) to pack, O(E) plus a sort per shard for the importers; no loop over pairs. `run_shards(&R, &ShardsRequest) -> Result<ShardedSpecialists<R::Error>, ShardsError>`: `ShardsRequest` is `SpecialistsRequest` with `packs: &[String]` (1 to 3) for `context_pack`; every shard's prompts are checked before any call (`ShardsError::{Count, Prompt { shard, source }}`); shards run one after another through the fan-out, each under its own run cap, so never more than 4 calls in flight; a shard whose `halt` is `RateLimited` or `Panicked` skips every later shard (each role `Skipped` for that halt), one halted by `RunCap` does not. `Specialists::halt` is the strongest halt (`RunCap < RateLimited < Panicked`), so a pause or panic in a retry after a run-cap halt still stops later shards; the roles still due keep the first halt as their skip reason. `ShardedSpecialists` (`shards: Vec<Specialists>`; `cost()`, `completed_roles()` = completed on every shard, `run_cap()` summed).
- The coordinator (S5, 04 §3 "Coordinator", §4 step 7, #96, `src/coordinate.rs`): `coordinate(&impl ModelRunner, CoordinateRequest) -> Coordination<E>`, total, for `full`; `merge_mechanically(&[ValidFinding]) -> Coordination<E>` for `lite` and `micro` (`NotNeeded`). `CoordinateRequest` (`findings: &[ValidFinding]`, `bundle`, `system_prompt_file`, `add_dir`, `timeout`); `Coordination` (`ranked: Vec<Ranked>` in rank order, `merged: Vec<Merged>` in input order, `merged_by: MergedBy::{Coordinator, Mechanical}`, `failure: Option<CoordinatorFailure<E>>`, `attempts`, `cost`, `rate_limits`, `refusals: Vec<CoordinationRefusal>`; `outcome() -> SupportOutcome` for `decide`, `events()`); `Ranked` (`index` into the findings given, `group: GroupId`, `placement`); `Merged` (`index`, `into`); `GroupId` (`Display` `g<n>`, numbered in rank order); `CoordinatorFailure` (`Call(CallFailure)`, `Runner(E)`, `TooMany { findings }`, with `reason()`: `unavailable` for a runner error, `cap` for too many); `CoordinationRefusal` (`Shape`, `UnknownFinding`, `Repeated`, `Missing`, `EmptyGroup`, `MixedClasses`, `SeveralMajors`, `DuplicateOutsideGroup`, `DuplicateElsewhere`, `DuplicateTooSevere`, `DuplicateOtherClass`, `DuplicateOtherKind`, `DuplicateApart`, `DuplicateOutranks`, `NoiseTooSevere`, `NoiseMerged`); `COORDINATION_SCHEMA`, `COORDINATOR_MAX_TURNS` (10), `COORDINATOR_CAP` ($0.30), `MAX_COORDINATED_FINDINGS` (64). Invariants: every finding given ends exactly once, ranked or merged; a merge (`may_absorb`) needs the same file and side, a severity no higher than the keeper's, and never puts a new finding under a pre-existing one; findings of one fingerprint are merged mechanically before any call, and only those merges may absorb a `major` or `blocker`; a coordinator duplicate must also be below `major`, of the keeper's `class` and `kind`, on overlapping lines; a coordinator group holds at most one `major` or `blocker`, so the coordinator can never lower rule 7's distinct-major count; the reader maps ids to positions as it reads, so the accepted plan needs no lookup; the coordinator sees only `{id, class, severity, confidence, pre_existing, file (at head), line, title, evidence, trigger, group_hint}` of at most 64 distinct findings, and answers in ids only, read strictly (wi-b5affa): one refusal variant per rule, a refused or malformed answer retried once, then the mechanical merge with the failure kept. The stage spends at most `COORDINATOR_CAP`, retries included, each attempt getting what is left; nothing left is `cap`; a runner error is charged at the attempt's budget. Rank: noise last, then severity, then confidence, then the coordinator's order (input order when mechanical); a group's findings share a `class`; noise moves only a `minor` or `nit` to the summary. Events: a `FindingDisposed` `duplicate` per merge, then `CoordinatorFinished` or `StageDegraded{stage: coordinator}`. Worst case: O(n log n) in the findings, and reading the answer is linear in the smaller of the answer and the findings shown (each accepted id marks one finding).
- The blind verifier (04 §3, §4 step 8, §7, #91, #97, `src/verify.rs`): `verify(&impl ModelRunner, VerifyRequest) -> Verification<E>`, total. `VerifyRequest` (`tier: VerifierTier`, `repository`, `findings: &[ValidFinding]`, `carried: &[CarriedFinding]`, `bundle`, `system_prompt_file`, `add_dir`, `timeout`); `VerifierTier` (`Full`, `Lite`, `Micro`; `calls`; `budget`, the stage total of `VERIFIER_CAP` per call; `TryFrom<Tier>`, refusing `trivial` and `needs-split` with `UnsupportedTier`); `CarriedFinding` (re-review's, below); `ClaimRef` (`Raised(FindingRef)`, `Carried(usize)`); `Verification` (`findings: Vec<VerifiedFinding>` and `carried` in input order, `failure: Option<VerifierFailure<E>>`, `attempts`, `cost`, `rate_limits`, `refusals: Vec<VerdictRefusal>`; `outcome() -> SupportOutcome` for `decide`, `events()`); `VerifiedFinding` (`at: ClaimRef`, `raised`, `severity`, `status: VerifierStatus`, `verdict()`); `VerifierStatus` (`Judged(Judgement)`, `NotCandidate`, `NoVerifier`, `OverCap`, `Unverified`); `Judgement` (`verdict`, `reason: VerdictReason`); `VerifierFailure` (`Call { at, reason: CallFailure }`, `Runner { at, source }`); `VERDICT_SCHEMA`, `MAX_REASON_CHARS` (200), `VERIFIER_MAX_TURNS` (8), `VERIFIER_CAP` ($0.08). The live reject rate (QA-12): `VerdictTally::of(&[Event])` (`confirmed`, `refuted`, `unclear`, `runs`; `reject_rate() -> RejectRate::{TooFewRuns, Within, Below, Above}`, 10 % to 60 % inclusive over at least `REJECT_RATE_MIN_RUNS` = 20 runs, in integers). Invariants: this run's findings reach the verifier only Z3-validated; carried findings are the caller's, taken from findings already published and read as untrusted text by `read_carried` (re-review owns their provenance and trust, #212 F1). Each call's user prompt is one JSON object of exactly `{file (at head), line, class, claim (the title), trigger}`, a blank line, then the verifier instruction (for a carried claim the carried-verifier instruction), never `body`, `fix`, `evidence` or the rest. Every carried finding is a candidate and is judged first, by severity then in order; then this run's findings of at least `major`, blockers first, then by confidence, then in order; at most `VerifierTier::calls` in all (5 in `full`, 3 in `lite`, none in `micro`). A carried claim is the same five-field object, followed by the carried-verifier instruction. The stage spends at most `VerifierTier::budget` ($0.40 full, $0.24 lite), retries included: each attempt's budget is the smaller of `VERIFIER_CAP` and what is left, and nothing left stops the stage as `cap` before any call. A verdict is read strictly (wi-b5affa): an object of exactly `verdict` (one of the three codes, exact case) and `reason` (printable ASCII, not blank, at most 200 characters, clear of the injection screen of validation step 5); anything else, like a `Malformed` outcome, is retried once and is then `malformed`; each refused verdict's `VerdictRefusal` is kept. `confirmed` keeps the severity, `refuted` lowers it to `minor` with the reason attached (`FindingDisposed` `verifier-rejected-downgraded`), `unclear` lowers it one level; each verdict emits `FindingVerified`. The first call that ends without a verdict stops the stage: `outcome()` is `Failed` with the `CallFailure` (`cap`, `turns`, `timeout`, `unavailable` for quota or a runner error, `malformed`), a `StageDegraded` event names it, verdicts already given stand, every candidate within the cap not yet judged is `Unverified`, shown at most `major` (06 §6), and a candidate past the cap stays `OverCap` at its severity. A runner error is charged at the attempt's budget.

- Re-review (04 §7, R-06, #99, `src/rereview.rs`): `review_target(&TargetRequest { base, head, previous }, &impl PriorHistory) -> Result<ReviewTarget<E>, TargetError<E>>` over the `PriorHistory` port (`ancestry(previous, head) -> Ancestry::{Ancestor, Rewritten, Unreachable}`, `range_diff(RangeDiffCommits { base, previous, head }, limit) -> RangeDiffListing::{Listed(bytes), TooLarge, TooSlow}`; `TargetError { source }`, the ancestry read's failure). `ReviewTarget<E>` (private fields; `increment() -> &Increment`, `carry() -> Carry`, `range_diff_failure() -> Option<&E>`, `carried(open)`, all of them only when `Kept`): `Increment::Since { previous, range_diff: RangeDiff }` (`as_str`; `Debug` shows only its length) or `Increment::Cumulative(Cumulative::{FirstReview, Unreachable, Unavailable})`; `Carry::{FirstReview, Kept, Reset(CarryReset::{Rewritten, Unreachable})}`. The carried findings' intake (`src/rereview/carried.rs`): `read_carried(Vec<CarriedParts>, repository) -> Result<Vec<CarriedFinding>, CarryRefused>` and `CarriedFinding::read(CarriedParts, repository) -> Result<CarriedFinding, CarriedRefusal { field: CarriedField, problem: CarriedProblem }>`; `CarriedParts` (`fp`, `file`, `line`, `class`, `severity`, `title`, `trigger`, `evidence`); `CarriedFinding` (private fields; `fp`, `file`, `line`, `class`, `severity`, `title`, `trigger`, `evidence`, `anchor() -> CarriedAnchor::{Unchecked, AtHead, Gone}`); `CarryRefused::{TooMany { count }, Finding { index, refusal }, Repeated { index }}`; `MAX_CARRIED` (256), `MAX_CARRIED_PATH_BYTES` (4096). `recheck_anchors(Vec<CarriedFinding>, &Change)`, the deterministic anchor re-check. `settle_carried(carried: &[CarriedFinding], raised: &[ValidFinding], &Verification<E>) -> Vec<CarriedOutcome>` (`fp`, `raised`, `severity`, `verdict`, `state: CarriedState::{Resolved { note }, Raised, Open, NotReverified(NotReverified::{Cap, VerifierFailed, AnchorPresent, AnchorGone})}`; `NotReverified::label`, `Cap` being "not re-verified (cap)"). Invariants: the target is always the cumulative diff (`plan` tiers on `base...head` and never sees a previous run); with no previous run the history is not read; an unreachable previous head marks nothing, resets the carry-over and asks for no range-diff; a reachable one is range-diffed from the pinned base, marked only when its output is UTF-8 within `MAX_RANGE_DIFF_BYTES` (120 KiB), and carries only when it is an ancestor of head; a range-diff that fails, is too large or too slow leaves the target unmarked (`Cumulative::Unavailable`, the failure kept in `range_diff_failure`) and keeps the carry decision already made, while a failed ancestry read is the error; a reset touches no dismissal record (those are ledger command records, outside the carry set). `RangeDiff` holds the commits' messages, which are the PR's intent (04 §3 "Blindness"): it belongs inside the intent envelope (#85). Carried text is untrusted (wi-b5affa): its provenance is App-authored records only (an earlier run's persisted bundle by ledger pointer, never PR comment text, 02 §2), and every field is checked before anything reads it: a path that is empty, over 4096 bytes, holds a control or invisible (format) character, is absolute or has an empty, `.` or `..` segment; a title or trigger that is blank, over its `findings-1` cap (100, 300 characters), holds a control or invisible character or is flagged by the injection screen; evidence over 400 characters or without the 12 characters of content step 2 needs. One refusal refuses the set (no carried finding is re-judged, so none is resolved); the count is checked before any field, and a fingerprint given twice refuses it. Refusals show no carried text. The anchor re-check uses validation step 2's search (nearest the published line, rename-followed; a file gone at head is `Gone`), indexing each head file once and searching each distinct normalised evidence once per file. Verification entries are paired to carried findings by `ClaimRef::Carried(index)` and length; any mismatch settles every carried finding as `VerifierFailed`. Only `refuted` resolves a carried finding, and never one whose fingerprint this run raised again and did not refute (`CarriedState::Raised`: the fresh finding stands): its thread is resolved with a note (fixed text and the verifier's reason through the publication sanitiser) and the finding is kept at `minor` (`verifier-rejected-downgraded`); `confirmed` and `unclear` keep it open; over the cap, a failed verifier and `micro` (anchor present: open and advisory; gone or unchecked: "needs re-verification", thread left open) leave it as last verified with no verdict, so rules 6-7 never count it. Worst case: 256 carried findings, each checked in time linear in its capped fields, plus at most one search of its head file per distinct evidence.

## Invariants
- Ports speak domain types; no adapter type crosses a port signature (ARC-03).
- `validate` is pure, total and deterministic, so Z3 and Z4 run one function and, without gate findings, agree exactly; each file is indexed once per call. Every input ends kept or dropped by exactly one dropping disposition; non-dropping ones (`line-not-in-diff-moved`, `pre-existing`, `cap-exceeded` with `from`/`to`, `no-trigger`) are recorded as they apply. A document's findings past the 256th are dropped before step 2 as `cap-exceeded` without `from`/`to` (each costs a search of its file; wi-641e1a); with `from`/`to`, `cap-exceeded` is the role's severity ceiling and does not drop. A document whose `source.role` is not in the roster is `schema`; the role ceiling holds only if `source.role` is stamped by the runner, never by the model (the runner's charge, tracked as an issue); `rule` over 128 bytes and `group_hint` over 100 characters are `schema`. Evidence needs 12 non-whitespace characters after normalisation, summed across wildcard pieces, else `evidence-missing`. A kept finding's `line` is a line where its normalised evidence starts (nearest to the cited line, the earlier on a tie, spanning at most 50 lines); its `side` is explicit (base for a deleted file); its `evidence`, and an interaction's `caller.evidence`, are replaced by the tree's own lines they matched (cut to 400 characters), so the quotes the model wrote never reach the output; the fingerprint, and the occurrence index (earlier matches of those lines in the same function), are computed over those lines, so every quote of one line gets one fingerprint. Only an interaction may carry a `caller`; on any other finding it is `schema`. The other free-text fields remain model text: the screen is a heuristic, and neutralising them at publish time is a separate backstop (tracked as an issue). An `end_line` past the file or outside the hunk holding `line` is dropped and the finding goes to the summary. Step 4 applies the role's severity ceiling (`cap-exceeded`), then requires a trigger with an alphanumeric character other than an invisible one from `major` up (`no-trigger`). Every free-text field, `rule`, and an interaction's caller evidence as the model wrote it are injection-screened; the tree's lines that replace `evidence` and `caller.evidence` are repository content, published as code, and are not (wi-d4735c). The screen refuses rather than models (wi-b5affa): wherever it cannot be sure how GitHub renders text, it reads it as prose and flags it. Precondition: each free-text field is published as its own markdown block, so no markup from one field or from the publisher's template continues into another; the publisher owns that (#175), and the screen's reading of a field holds only under it. CRLF is read as LF; a carriage return that remains flags the field outright (`Html`). Only a plain field has anything removed as code: one with no `|` (tables), no whitespace other than ASCII space, tab and line feed, and no line beginning with a container marker (`>`, `-`, `*`, `+`, `N.`, `N)`); any other field is screened whole as prose. In a plain field it removes only closed fences (within three spaces of indent, a backtick fence's info string without a backtick) whose info string is empty or a single word of `[a-z0-9_+-]` on an allowlist of inert languages (`rust`, `rs`, `toml`, `json`, `yaml`, `yml`, `text`, `txt`, `plain`, `sh`, `bash`, `shell`, `console`, `diff`, `patch`, `sql`, `c`, `cpp`, `go`, `python`, `py`, `js`, `ts`, `javascript`, `typescript`, `html`, `xml`, `ini`, `makefile`, `dockerfile`; ASCII case-insensitive); any other closed fence (mermaid, math, an unknown or encoded word, extra words) and an unclosed fence keep their lines raw as prose, with no code span stripped, and code spans only from a paragraph every backtick run of which pairs within its own line (a line is blank only if it holds nothing but spaces and tabs); everything else is prose. Text is lowercased ASCII-only for the link checks, so no non-ASCII letter folds into an ASCII one (U+212A). Every URL is judged on the longest extent a renderer could read, ending only at an ASCII space or control: a written-out one also at `<` (GFM autolink), which may point to the allowlist (an authority of `[a-z0-9.-]` only) or the repository and is foreign if it holds a non-ASCII character or is cut by a character other than `)` or `>`; a markdown link destination also at an unbalanced `)` (or the closing `>` of an angled one), which must be an ASCII, absolute `https` URL into the repository after `.`/`..` resolution of the whole destination, with no `%` or `\` in its path and no `&` anywhere. A backtick anywhere between `](` and the link's closing `)`, title included, flags the text, as do `]:` anywhere in the text, code spans included (definitions are parsed before spans), TeX's `\href` and `\url` anywhere (math renders them as links), reference links, character references (`&#…`, `&name;`), an email address (GFM makes it a `mailto:` link), a reference into another repository (`owner/name#digits` or `owner/name@` and 7 to 40 hex digits, unless `owner/name` is the repository; `user@` and 7 to 40 hex digits, a commit in that user's fork, unless `user` is the repository's owner; ASCII case-insensitive) and an `@` followed by a name character unless an ASCII letter or digit precedes it. A suggestion fence is found inside any number of containers, and a fence line whose info string holds `&` or `\` counts as one. The link scan is forward-only and each URL is capped at 2048 characters. Evidence search tries one start per kept line, so it is linear in the file plus the evidence length per line, and each file is searched once per distinct normalised evidence. The enclosing-function pass finds each line's opener by binary search. The enclosing symbol is an indentation heuristic over formatted Rust: deterministic, not a parser. Nothing in it quotes model text.
- The egress scan runs first on every finding of a schema-valid document, past the 256 cap included, before step 1's shape checks and before step 2 replaces `evidence` and `caller.evidence`; a hit drops the finding as `injection-suspect` and records one `EgressHit` (its first field, in `FreeTextField` order). It reads every field the reviewer wrote (`title`, `body`, `fix`, `trigger`, `evidence`, `expected_behavior`, `group_hint`, `rule`, an interaction's caller evidence). The token is encoded, the text never decoded: text is folded as the screen folds it (invisibles dropped, lookalike and fullwidth letters read as Latin, lowercase) and reduced to ASCII letters and digits, and any 12-character window of the token, of its base64 (whole groups starting at each of its first three bytes, so every alignment; the alphabets differ only in what normalisation strips) or of its hex is a `Token` hit; the windows are also slid over a hex-only view (folded, lowercase, the byte prefixes `0x`, `\x`, `\u00`, `u+00`, `&#x` and `%` deleted, decimal references of a byte `&#115;` read as its hex, everything but `[0-9a-f]` dropped), so hex written one byte at a time is found too. Before that, every character drawn like one ASCII letter or digit is read as it, from one generated, checked-in table (`src/validation/egress/lookalikes.rs`, 2,828 entries, Unicode 15.1, no new dependency; the generator and the sha256 of the pinned `confusables.txt` are in its doc comment): canonical decompositions to an ASCII letter, `LATIN ... LETTER X WITH ...`/`BAR`, small capitals, dotless i and j, superscript and subscript digits, NFKC to one ASCII letter or digit (fullwidth, mathematical, enclosed), decimal digits of every script, then the single-character skeletons of `confusables.txt` (Cyrillic, Greek, Lisu, Cherokee and more), except the skeletons `l` and `O`, which stand for several ASCII characters and stay unread. Read characters are known symbols, so `O(n²)` is prose and a raised, dotted, stroked or other-script token is still the token. Any other non-ASCII alphanumeric (CJK, `ß`, an unread confusable) becomes a wildcard in both views rather than being deleted: a 12-symbol window holding wildcards matches a token window when every other symbol equals the token's at its position and there are at least 7 of them (normalised view; 36^-7, about 1e-11, per token window compared) or 9 (hex view; 16^-9), so an attacker must find five unread characters in every twelve. Only a numeric character or a letter-like symbol (Mathematical Alphanumeric Symbols, Enclosed Alphanumerics, superscripts and subscripts, small capitals and modifier letters) that the table does not read is `Obfuscated` (`½`, `⑳`, `Ⅻ`, a mathematical Greek letter): refused, so quoting one from the tree drops the finding too (fail closed). Ordinary non-ASCII prose raises no hit (review rounds 3 and 4). Accepted residual risk (05 T2): octal escapes (`\163`) and decimal byte lists (`115, 107`) get no view of their own; only the run rule and the per-character rules see them. A run of 20 or more characters (Unicode alphanumerics and invisible characters, so a zero-width character cannot cut one) that is not, whole, a run of the indexed texts or one of the run's own commit ids is `UnexplainedRun` (wi-b5affa: what is not provably the tree's own text is a hit; a prefix of a longer identifier is not explained). Z4 holds no token, so it applies the run rule only, and Z3 can drop more than Z4; Z3 and Z4 agree exactly when given equal scans. `scan_artifact` reads the bytes as text and, when they are strict JSON, every key and string decoded, and otherwise (a repeated key, a trailing byte, nesting past the parser's depth) the text with its escapes read back (`\uXXXX` with surrogate pairs, `\xHH`, JSON's single-character escapes; any other escape, a lone surrogate or a cut escape is `TokenShaped`), for the token windows, a private key header, `sk-ant-` in any ASCII case, and AWS key ids and mixed runs of 32 or more characters (not 40 or 64 lowercase hex) the index does not hold; it skips the run rule, since artifacts carry digests assay stamps. Quoting `sk-ant-` anywhere, even from the tree, fails closed by design: the prefix is never explained. In Z3 a document that fails its schema is read the same way for the token alone; a hit (or an escape it cannot read) makes its one transition `injection-suspect` instead of `schema`, with a `RejectedDocument` hit. Cost: one pass per view (normalised, hex-only), with one hash lookup per window without wildcards and, for a window with wildcards and enough known symbols, a 12-symbol check against the token windows sharing its first known symbol at that position (at most every token window, bounded by `MAX_TOKEN_BYTES`: O(n × windows × 12)), one hash lookup per run, one character pass for lookalikes, and one unescape pass for a non-strict document, each linear in the text; the index is linear in its input, refused before reading the text that crosses its cap, and holds borrowed runs only.

It refuses rather than models (wi-b5affa): a diff past its cap, a REST list over 3,000, below the cap shorter or longer than `changed_files`, naming a path twice, or naming different paths than git (both sides of every rename, compared as sets; a truncated list only needs to be a subset, and git must then list at least `changed_files` distinct paths), a base `.assay/` without `plugins.toml` or with a symlink or submodule, a `plugins.toml` or `globs.toml` that is not UTF-8 or does not parse, a port that returns the wrong number of blobs, a repeated nonce, and a document that fails `run-1.schema.json`. A manifest that is a symlink, submodule or not UTF-8 reads as unparseable; `IncludeTargets::NotScanned` makes every changed path an include target (no `trivial`); a missing package set is exec surface. A draft gets no roles and no shards but keeps its required roles. `run_key` (the evidence key, 02 §3: repo, pr, head and base SHA, `config_hash` over every `.assay/` file, assay digest, Claude CLI version, prompt bundle hash, built-in pins) never includes `run_uid`.
- Validation errors never quote the rejected value (it is untrusted text), nor an object key the schema does not name: such keys are reported as `*`, and unexpected properties are counted, not listed (`src/contract/violation.rs`).
- `authenticate` refuses rather than models (wi-b5affa). It refuses a `run_attempt` other than 1 before any port call (R3-05). It re-fetches the PR first: a moved head or base ref is `Superseded`, whatever else is wrong (R3-03, R3-06). A cancelled upstream job yields to a newer run for the head, and is otherwise `gate-error:<job>: cancelled`; a `plan` job that did not succeed is `gate-error`. Every artifact byte is fetched under one document's limit and the run's 64 MiB budget and compared with the sha256 its producing job published; any mismatch refuses the whole run as `gate-error:artifact-digest: <job>/<file>` (F18). The plan document must pass `run-1.schema.json`, name seven `assay-<job>-<nonce>` artifacts with distinct nonces (its own being the `plan` job's), and equal, field by field, the document Z4 renders from its own recomputation through the code `plan` runs (base config, file list, tiering, classes, required roles and plugins, pins, SHAs, run key); a difference is `plan-mismatch` naming the first differing field, and a PR that `plan` would refuse is `plan-mismatch` too. `admit`'s full-to-lite degrade is accepted only from a successful `admit`, a `full` tier and no classes; any other degrade, one from an `admit` that did not succeed included, is `plan-mismatch` (R3-27). Outputs that name a plugin their job does not schedule, name one twice, come from a skipped job, or come from a successful job that leaves out a scheduled plugin refuse the run, as do documents reported by a skipped `review` job; a reported gate document whose job has no artifact name is `plan-mismatch`. Every scheduled gate gets one report: unreported, it is `gate-error:job-failed` after a failed job and `gate-skipped` after a skipped one; a reported document that is missing, too large, schema-invalid, from another plugin, or disagreeing with the job's non-failing conclusion is a gate error. Gate findings get Z4's evidence and fingerprint: one whose cited line exists on its side and normalises to its evidence's first line of content takes that tree line as evidence and is fingerprinted in its enclosing function with its occurrence index; any other keeps its evidence, is fingerprinted at file scope and loses its rule, so no waiver clears it. Evidence reads list each side once and stop at the first cited file past 1,000 files or 64 MiB (by listed size). Each cited file is indexed once, with every line normalised once, so a finding costs its own quote and one comparison, never its cited line again; a file declaring a function name longer than 256 bytes is not indexed and its findings stay unverified, so no occurrence key or fingerprint hashes an unbounded name (H-13). `open_prs_on_head` counts the PR plus each other open PR on the head into the same base once (R3-19).
- `publish` writes nothing for a superseded or yielding run (R3-06), and never releases the slot (the `release` job's). It checks its inputs before any port call: the decision key must be a `sha256:` digest and the inputs' evidence key the run's. It reads the App check for (head, `CheckName::for_base`): absent is `CheckMissing`; carrying this decision key and completed is `Unchanged`, with no write at all; carrying neither this key nor this run's stamp (`pending:<run_id>:` and one or more ASCII digits) yields without taking the lock. A decided run's bundle is built and uploaded before the lock; under the lock the check is read again and must equal the first read exactly, or the writer yields (R3-09); then the evidence record (after a successful upload only), the check (`external_id` the decision key, never `output.annotations`, R3-11) and the summary comment (written only when its body differs). The lock is released after every outcome that took it, and a failed release is reported beside the outcome, never instead of it. A persist failure (bundle not UTF-8 or over its cap, upload, ledger) makes a trust-path or exec-surface PR `failure persist-error` and is otherwise a warning on a decision left unchanged; either way there is no evidence pointer. A refused run publishes `failure` with its refusal reason and persists nothing. Rendering never lets text escape its block: every dynamic string sits in a fenced block longer than any backtick run in it, with control characters and format characters (general category Cf as of Unicode 15.1: bidi embeddings, overrides and isolates, zero-width characters, the byte-order mark, tags) replaced by U+FFFD, at most 50 items of 200 characters each and then "and N more, listed in the decision".
- `replay_decision` fails closed (wi-b5affa). A pointer to a re-run is refused before any fetch. The bundle is read under `MAX_BUNDLE_BYTES` (the adapter is held to it too) and must hash to the pointer's sha256 before it is parsed, with the contract read's strict parse (a repeated key is refused) and a private serde DTO of `assay.run-inputs/1` (unknown fields refused; events checked to be an array, not read). It must then record the pointer's run, keep documents that still hash to their recorded sha256 and an evidence key equal to its inputs', and be decided under the given rubric's version. The recomputed and recorded decisions are compared byte for byte in one canonical encoding (compact JSON, keys sorted, as a `serde_json::Value` writes it), because the bundle nests the decision rather than keeping its bytes apart. A mismatch reports the first differing byte offset of the recorded decision's canonical encoding and a JSON pointer built only from the recomputed decision's names (a key only the bundle has is `*`), indices, and digests computed here: nothing from the bundle is echoed. Absence (`Missing`, `Expired`) and unreadability are errors; a digest that does not match is a mismatch (02 §5: absence is not forgery, F19 and F20).
- Inline comments and per-gate checks (04 §6, #88, `src/publish/findings.rs`): `publish_findings(&FindingsPublication, &impl CommentForge, &impl PublishLedger) -> FindingsOutcome`, after `publish` wrote the verdict. `FindingsPublication { target, decision_key, gates: &[GateReport], findings: &[ValidFinding] }`; `CommentForge: VerdictForge` adds `app_review_comments(number)` (bodies of the App's own review comments only), `create_review_comment(number, &InlineComment)` (`commit_id`, `path`, `line`, `start_line`, `side`, `body`) and `create_check(head, &CheckName, &CheckUpdate)`. `FindingsPublished` is `Yielded { unlock }` or `Written(FindingsWritten { posted, already_posted, unlock })`. Inputs (repository `owner/name`, decision key, gate names) are checked and every body rendered before any port call; under the per-head lock the verdict check must carry the decision key (else it yields), then the App's review comments are read (more than `MAX_PRIOR_COMMENTS`, 1,024, refuses), each gate's `assay / gate: <name>` check is created or updated unless completed under this key, and each of at most `MAX_INLINE_COMMENTS` (8) findings (inline placement, severity, then confidence, then input order, one per fingerprint) is posted unless an App comment's first line, `<!-- assay-finding <fp> -->`, already names its fingerprint. The sanitiser (`src/publish/sanitise.rs`, #175, wi-b5affa) parses no Markdown: model prose has every ASCII punctuation character backslash-escaped, `@` and `#` made fullwidth, `://`, `www.` and `gh-<digit>` (any case) defanged, leading whitespace dropped and control and format characters replaced, after a per-field cap; the only links are publisher-built permalinks (percent-encoded path, none for a path with an empty, `.` or `..` segment or a control or format character); bare commit SHAs and the repository's custom autolinks remain as accepted same-repository residual links and the only fences its own, with an info string from a closed list that has no `suggestion`.
- `status` fails closed (wi-b5affa) and reads only what assay itself published. Only checks whose app id is the configured App count: another app's same-named check is ignored, two App verdict checks or two App checks for one gate are refused (A-27). The decision, tier and Weigh-In state come only from the bundle the verdict check's `output.text` pointer names, after the attempt is 1, the fetch is under `MAX_BUNDLE_BYTES`, the sha256 matches, the bundle is consistent, its rubric version is the base rubric's and its decision key is the check's. Every count is checked against its cap before the loop over it.

## Errors
- `ReadContractError` (`TooLarge`, `Malformed` (including a repeated key), `MissingSchema`, `UnknownSchema`, `UnknownVersion`, `Invalid`): every variant maps to disposition `schema` through `disposition()`.
- `ContractSchemaError`: an embedded schema does not compile, a defect in the build. Its cause is the opaque `SchemaCompileError`, so `jsonschema`'s error type is not part of this crate's API.
- `ConfigError` (`Syntax` with the opaque `TomlError`, `Digest`, `Version`, `Pin` with `ParsePinError::{Tag, UnknownScheme}`, `Name`, `DuplicateName`, `UnknownAdapter`, `MissingKey`, `UnexpectedKey`, `Job`, `Command`, `Timeout`): plugins.toml was refused. The file is from the protected base, so messages may quote it.
- `GlobsConfigError` (`Syntax` with the opaque `TomlError`, `Glob` naming the list and pattern): globs.toml was refused. `manifest_trust_keys`, `exec_roots`, `manifest_exec_roots` and `baseline_change` cannot fail: what does not parse reads as changed.
- `MetadataError` (`Syntax` with line and column, `Version`, `UnknownPackage`): `cargo metadata` output was refused; the caller passes `None` for that side to `exec_surface`, which fails closed. `exec_surface` cannot fail.
- `PlanError<O, N>` (`Objects { step, source }` with the failed port call as `ObjectsStep::{ChangedFiles, ListBase, ListHead, Read}`, `ShortRead`, `DiffTooSlow`, `FileList` with `FileListError::{OverCap, Incomplete, GitShort, Repeated, Mismatch}`, `BaseConfig` with `BaseConfigError::{Missing, NotARegularFile, NotUtf8, Plugins, Globs}`, `Nonce`, `RepeatedNonce`, `Encode`, `Invalid`): no run description; every variant fails the run. `O` and `N` are the ports' error types. A mismatch reports counts and the first differing path, `{:?}`-escaped.
- `InitReadError` (`Missing`, `Repeated`, `RepeatedKey`, `Field`, `Entry`, `TooMany`, `Name`): a session's `system/init` could not be read; `InitUnclean` (`CliVersion`, `McpServer`, `Tools`, `NotBuiltin`, `Unlisted`, `Repeated`): it was read and is not clean. Both are preflight failure `init-unclean`; names are shown `{:?}`-escaped. `ConfigError::Builtins` wraps `BuiltinsError` (`WithoutCli`, `Name`, `Repeated`, `TooMany`).
- `CalendarDateError` (`Shape`, `NoSuchDay`, `OutOfRange`): no `CalendarDate` could be read; the value is never shown.
- `DoctorError<P, N>` (`Nonce`, `Probe`): the checks could not be run. A failed check is a `CheckFailure` in the report, not an error.
- `StatusReadError` (`Version`, `NotJson`, `RepeatedKey`, `Field`, `Name`): the CLI's status could not be read; `PreflightFailure<E>` (`ProviderVariable`, `Probe`, `CliVersion`, `NotLoggedIn`, `AuthMethod`, `ApiProvider`, `InitUnreadable`, `InitUnclean`) inside `PreflightFailed<E>` (boxed): the preflight failed, an outcome the caller publishes as the LLM-unavailable policy, not a defect.
- `GateError` is an outcome, not a failure of the use case: a `GateRunner` error becomes the runner's `gate_error` of it (`GateError::NotRun` by default; the temper adapter's degraded ratchet is `GateError::RatchetDegraded`, `gate-error:ratchet-degraded`, 03 §2.1 step 5), with the runner's message kept in `GateReport::cause`.
- `DecideError<O, S, A>` (`NotFirstAttempt`, `State` with the failed call as `StateStep::{Current, PullsOnHead, NewerRun}`, `Artifacts { job, file }`, `Recompute` (a port failed while recomputing the plan), `Objects`, `ShortRead`, `Encode`): `decide` could not reach a verdict; nothing is published and the job fails. `DecideFailure<O, S, A>` names it over the ports' error types. A refusal to publish is a `Refusal` inside `Authentication`, not an error.
- `PublishError<F, L>` (`DecisionKey`, `EvidenceKey`, `CheckMissing`, `Observe`, `Lock`, `LockBusy`, `Locked { step: ForgeStep, source, unlock }`): nothing was published (for `Locked`, a forge call under the lock failed at `step`, possibly after the evidence record); the job fails. `PublishFailure` names it over the ports' error types. `PersistFailure<L, B>` (`Bundle(BundleError)`, `Upload`, `Ledger`, with `code()`) and `BundleError` (`NotUtf8 { job, file }`, `TooLarge`, `Encode`) are outcomes inside `Written`, not errors: the verdict is still published.
- `ReplayError<E>` (`NotFirstAttempt`, `Fetch`, `Missing`, `Expired`, `TooLarge`, `Unreadable(BundleShape::{Truncated, Syntax, Shape})`, `RubricVersion`, `Encode`): the decision could not be replayed, never a pass. `BundleShape` carries only a line and column. A disagreement is a `Mismatch` inside `Replayed`, not an error.
- `FindingsError<F, L>` (`Repository`, `DecisionKey`, `GateName { name }`, `Lock`, `LockBusy`, `Locked { step: CommentStep, source, unlock }`, `TooManyComments { count, unlock }`): the first three before any port call; `Locked` after the calls before `step` took effect (a re-run skips the comments already posted); `TooManyComments` before any write.
- `StatusError<F, B>` (`Repository`, `Forge { step: StatusStep, source }`, `NoSuchPull`, `NoOpenPull`, `AmbiguousBranch` (more than one, the list read only to the second), `Unreadable(StatusUnreadable::{Branch, Url, Login, GateName, CheckState, ExternalId, CheckText})`, `TooManyChecks`, `TooManyComments`, `TooManyFindings`, `TooManyReasons`, `DuplicateVerdict`, `DuplicateGate`, `Bundle(BundleProblem)`, `Encode`, `Invalid`): no status was rendered; nothing partial is returned. `BundleProblem<B>` (`NotFirstAttempt`, `Fetch`, `Missing`, `Expired`, `TooLarge`, `Digest`, `Shape`, `Inconsistent`, `Decision`, `RubricVersion`) says why the named bundle was not used.
- `CorpusError` (`TooManyEntries`, `TooManyCases`, `UnexpectedEntry`, `Incomplete`, `TooLarge`, `DiffNotText`, `Case` with `CaseProblem::{Syntax, Schema, AuthoringModel, LabelsOnTrueNegative, NoLabels, TooManyLabels, LabelSpan, LabelPath}`): the split was refused whole. `EvalError<R, L>` (`NoCases`, `RelativePath { field: PathField::{CorpusDir, SystemPromptFile} }`, `Prompt` with its `InvalidPrompt`, `Runner` with the runner's error, `QuotaExhausted`, `Exhausted { month, spent, cap }`, `Ledger`): the evaluation stopped; what it spent is already charged. `CompareError` (`SplitDiffers`, `CaseSetDiffers`, `CaseChanged`, `BaselineUnscorable`).
- Use cases to come: one `thiserror` enum each; port failures surface through each port's associated error type.

## Test strategy
Integration tests in `tests/it/` drive use cases against in-memory fakes of the ports (TST-09); no real network, processes or clocks. Validation has one test per step and per disposition it emits (`tests/it/validation/`), a Z3-versus-Z4 test, and property tests (dev-dependency `proptest`) for determinism, relocation onto matching lines only, and each finding ending kept or dropped exactly once. Run: `cargo test -p assay-app`.

## Do not
- Do not call `gh`, `claude` or the file system directly; add or extend a port.
- Do not read environment variables; configuration arrives parsed from the CLI (ARC-11).
