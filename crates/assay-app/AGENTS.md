# Crate charter: `assay-app`

## Purpose
The use cases (`open`, `plan`, `admit`, `gate`, `review`, `decide`, `replay`, `report`, `doctor`) and the port traits they need (`ModelRunner`, `Forge`, `EventSink`, `GateRunner`, `Ledger`, `Clock`). It is its own crate because the ports must be owned by their consumer so adapters depend inward (ARC-03, `docs/architecture/02-architecture.md` §2).

## Layer
application. Orchestrates domain decisions and effects through ports. No concrete adapter, no HTTP or process types, no runtime choice, no `anyhow` in `pub` signatures.

## Allowed dependencies
- Workspace crates: `assay-domain` only, added by the story that first uses it.
- Third-party: crates on the pre-approved list in `.claude/temper.json`, each justified in the root decisions log when added.
- Never: `assay-forge`, `assay-runner`, `assay-gates`, `assay-cli`, `weighin-core` or temper code (P8). `crates/assay-cli/tests/it/architecture.rs` fails on a violation.

## Invariants
- Ports speak domain types; no adapter type crosses a port signature (ARC-03).
- `validate` is pure, total and deterministic, so Z3 and Z4 run one function and, without gate findings, agree exactly; each file is indexed once per call. Every input ends kept or dropped by exactly one dropping disposition; non-dropping ones (`line-not-in-diff-moved`, `pre-existing`, `cap-exceeded` with `from`/`to`, `no-trigger`) are recorded as they apply. A document's findings past the 256th are dropped before step 2 as `cap-exceeded` without `from`/`to` (each costs a search of its file; wi-641e1a); with `from`/`to`, `cap-exceeded` is the role's severity ceiling and does not drop. A document whose `source.role` is not in the roster is `schema`; the role ceiling holds only if `source.role` is stamped by the runner, never by the model (the runner's charge, tracked as an issue); `rule` over 128 bytes and `group_hint` over 100 characters are `schema`. Evidence needs 12 non-whitespace characters after normalisation, summed across wildcard pieces, else `evidence-missing`. A kept finding's `line` is a line where its normalised evidence starts (nearest to the cited line, the earlier on a tie, spanning at most 50 lines); its `side` is explicit (base for a deleted file); its `evidence`, and an interaction's `caller.evidence`, are replaced by the tree's own lines they matched (cut to 400 characters), so the quotes the model wrote never reach the output; the fingerprint, and the occurrence index (earlier matches of those lines in the same function), are computed over those lines, so every quote of one line gets one fingerprint. Only an interaction may carry a `caller`; on any other finding it is `schema`. The other free-text fields remain model text: the screen is a heuristic, and neutralising them at publish time is a separate backstop (tracked as an issue). An `end_line` past the file or outside the hunk holding `line` is dropped and the finding goes to the summary. Step 4 applies the role's severity ceiling (`cap-exceeded`), then requires a trigger with an alphanumeric character other than an invisible one from `major` up (`no-trigger`). Every free-text field, `rule`, and an interaction's caller evidence as the model wrote it are injection-screened; the tree's lines that replace `evidence` and `caller.evidence` are repository content, published as code, and are not (wi-d4735c). The screen refuses rather than models (wi-b5affa): wherever it cannot be sure how GitHub renders text, it reads it as prose and flags it. Precondition: each free-text field is published as its own markdown block, so no markup from one field or from the publisher's template continues into another; the publisher owns that (#175), and the screen's reading of a field holds only under it. CRLF is read as LF; a carriage return that remains flags the field outright (`Html`). Only a plain field has anything removed as code: one with no `|` (tables), no whitespace other than ASCII space, tab and line feed, and no line beginning with a container marker (`>`, `-`, `*`, `+`, `N.`, `N)`); any other field is screened whole as prose. In a plain field it removes only closed fences (within three spaces of indent, a backtick fence's info string without a backtick) whose info string is empty or a single word of `[a-z0-9_+-]` on an allowlist of inert languages (`rust`, `rs`, `toml`, `json`, `yaml`, `yml`, `text`, `txt`, `plain`, `sh`, `bash`, `shell`, `console`, `diff`, `patch`, `sql`, `c`, `cpp`, `go`, `python`, `py`, `js`, `ts`, `javascript`, `typescript`, `html`, `xml`, `ini`, `makefile`, `dockerfile`; ASCII case-insensitive); any other closed fence (mermaid, math, an unknown or encoded word, extra words) and an unclosed fence keep their lines raw as prose, with no code span stripped, and code spans only from a paragraph every backtick run of which pairs within its own line (a line is blank only if it holds nothing but spaces and tabs); everything else is prose. Text is lowercased ASCII-only for the link checks, so no non-ASCII letter folds into an ASCII one (U+212A). Every URL is judged on the longest extent a renderer could read, ending only at an ASCII space or control: a written-out one also at `<` (GFM autolink), which may point to the allowlist (an authority of `[a-z0-9.-]` only) or the repository and is foreign if it holds a non-ASCII character or is cut by a character other than `)` or `>`; a markdown link destination also at an unbalanced `)` (or the closing `>` of an angled one), which must be an ASCII, absolute `https` URL into the repository after `.`/`..` resolution of the whole destination, with no `%` or `\` in its path and no `&` anywhere. A backtick anywhere between `](` and the link's closing `)`, title included, flags the text, as do `]:` anywhere in the text, code spans included (definitions are parsed before spans), TeX's `\href` and `\url` anywhere (math renders them as links), reference links, character references (`&#…`, `&name;`), an email address (GFM makes it a `mailto:` link), a reference into another repository (`owner/name#digits` or `owner/name@` and 7 to 40 hex digits, unless `owner/name` is the repository; `user@` and 7 to 40 hex digits, a commit in that user's fork, unless `user` is the repository's owner; ASCII case-insensitive) and an `@` followed by a name character unless an ASCII letter or digit precedes it. A suggestion fence is found inside any number of containers, and a fence line whose info string holds `&` or `\` counts as one. The link scan is forward-only and each URL is capped at 2048 characters. Evidence search tries one start per kept line, so it is linear in the file plus the evidence length per line, and each file is searched once per distinct normalised evidence. The enclosing-function pass finds each line's opener by binary search. The enclosing symbol is an indentation heuristic over formatted Rust: deterministic, not a parser. Nothing in it quotes model text.
- `replay_golden` is pure and total: it parses the rubric (TOML) and each case's `inputs.json` (`DecisionInputs` through serde only, so new fields need no change here), decides, writes the decision as pretty JSON plus a newline and compares bytes. The conclusion is `pass` exactly when there is no finding; every problem is a `blocker` finding in path order (`golden-mismatch` at the first differing line of the recorded file, `golden-inputs-invalid`, `golden-case-incomplete`, `golden-unexpected-entry` outside the allowlist of a root `README.md` and case directories holding a regular `inputs.json` and `decision.json` once each, `golden-corpus-empty`, and `golden-rubric-invalid` alone when the rubric does not parse). Each allowlisted entry counts once: a repeated `README.md`, case directory or case file is `golden-unexpected-entry`. Titles carry only the path reduced to `[A-Za-z0-9_:-./]`; bodies are fixed text; evidence is the recorded line, trimmed and clipped to 400 characters, or, when there is none, the path reduced as in the title.
- A session init is clean only when its CLI version equals the pin, it has no MCP server, its tools are exactly `Glob`, `Grep`, `Read` (each once), every plugin is a built-in (`path` `builtin`, `source` `<name>@builtin`), and every plugin, skill and agent is on the allowlist, none listed twice (#121). Built-ins are allowlisted, not absent. `doctor` fails closed: an unreadable init fails the checks that read it (the mod canary judges the markers first, so a mod that ran is reported anyway), a canary that planted nothing fails the mod canary, and a call that did not answer fails the AGENTS.md canary. The AGENTS.md canary fails on the joined word in any ASCII case anywhere in the transcript, and on the nonce alone in any JSON message but a `user` one (tool results quote the planted files).
- A contract document is accepted only at a supported version and only if it satisfies that version's schema; unknown fields, unknown versions, over-length text, documents over `MAX_DOCUMENT_BYTES` and repeated object keys are rejected, never repaired (03 preamble).
- plugins.toml accepts no unknown key (there is no `applies_when`); pins and digests are immutable identities (`git:<40 hex>`, `oci:sha256:<64 hex>`), and a tag is `ParsePinError::Tag`; `exec` gates and declared steps name a Z2b job (`lint`, `test`), so nothing PR-controlled can be scheduled into `gates-static`; every timeout is 1 to 21,600 s.
- A gate run counts only as exit 0 (the document's conclusion) or exit 1 (fail) with a schema-valid gate document whose `source.name` is the plugin; anything else is `GateOutcome::Error`, displayed `gate-error:<detail>` (03 §2). `run_gates` has no filter, and `account_for_required` makes a required gate without a report `gate-error:skipped`.
- A model call is retried only when its first attempt is `Malformed`, and only once; every attempt's cost is reported, including a malformed first attempt whose retry failed (`RetryError::Retry`).
- Every role gets the same system prompt (one file, so the prompt cache is shared), and its user prompt is the context pack, a blank line, then its instruction. The bundle hash is the domain's `ContentHash` over every bundle file under its versioned path, so it changes when any byte, name or version does.
- Exec surface fails closed: a side without a package set gives `PackageDiff::Unavailable` and `[ExecRoot::Everything]`; a side without a resolve graph, or a build-time path crate at the copy's root or outside it, gives `Everything`. A new or bumped package (path packages included, by version) with a `custom-build` or `proc-macro` target, or an unchanged one gaining either, is exec surface; so is a package whose name is in base only from another source, a new package from neither crates.io nor a path (git, any other registry), a change to a package's `[build-dependencies]` declarations against its base counterpart (the same package, else the first of the same name and source, so two unchanged versions are each compared with themselves) and a new `path` declaration of any kind. Only a new or bumped crates.io package (`registry+https://github.com/rust-lang/crates.io-index` or `sparse+https://index.crates.io/`) with none of these is `Registry`; any other change is `Lockfile`, including a removed package, matched by name, version and source (a dropped version of a name with several), unless a new package of its name already reports it. Build-time path crates are those reached from a build edge or a proc-macro crate (itself included), transitively over normal and build edges (never development edges; a resolve edge with no named kind counts as normal and build), at base or at head; each contributes its directory and, for a library or proc-macro target whose `src_path` lies outside it (`[lib] path`), that file and its directory, with `Everything` when either is outside the copy or at its root (real cargo reports an out-of-crate `src_path` unnormalised, `<crate>/../shared/lib.rs`, which therefore reads as outside: `Everything`). Any root, declared or build-time, that holds a symlink of either side whose resolved target it does not hold makes the roots `Everything` (wi-b5affa option b: refused, not modelled; targets are not followed further); cargo's resolve graph has already resolved `workspace = true`, renames, `[patch]` and target tables, and anything it cannot resolve fails the whole side.
- `plan` reads base `.assay/` only at the request's `base_sha` and the trees only at its two pinned SHAs. It refuses rather than models (wi-b5affa): a diff past its cap, a REST list over 3,000, below the cap shorter or longer than `changed_files`, naming a path twice, or naming different paths than git (both sides of every rename, compared as sets; a truncated list only needs to be a subset, and git must then list at least `changed_files` distinct paths), a base `.assay/` without `plugins.toml` or with a symlink or submodule, a `plugins.toml` or `globs.toml` that is not UTF-8 or does not parse, a port that returns the wrong number of blobs, a repeated nonce, and a document that fails `run-1.schema.json`. A manifest that is a symlink, submodule or not UTF-8 reads as unparseable; `IncludeTargets::NotScanned` makes every changed path an include target (no `trivial`); a missing package set is exec surface. A draft gets no roles and no shards but keeps its required roles. `run_key` (the evidence key, 02 §3: repo, pr, head and base SHA, `config_hash` over every `.assay/` file, assay digest, Claude CLI version, prompt bundle hash, built-in pins) never includes `run_uid`.
- Validation errors never quote the rejected value (it is untrusted text), nor an object key the schema does not name: such keys are reported as `*`, and unexpected properties are counted, not listed (`src/contract/violation.rs`).
- `authenticate` refuses rather than models (wi-b5affa). It refuses a `run_attempt` other than 1 before any port call (R3-05). It re-fetches the PR first: a moved head or base ref is `Superseded`, whatever else is wrong (R3-03, R3-06). A cancelled upstream job yields to a newer run for the head, and is otherwise `gate-error:<job>: cancelled`; a `plan` job that did not succeed is `gate-error`. Every artifact byte is fetched under one document's limit and the run's 64 MiB budget and compared with the sha256 its producing job published; any mismatch refuses the whole run as `gate-error:artifact-digest: <job>/<file>` (F18). The plan document must pass `run-1.schema.json`, name seven `assay-<job>-<nonce>` artifacts with distinct nonces (its own being the `plan` job's), and equal, field by field, the document Z4 renders from its own recomputation through the code `plan` runs (base config, file list, tiering, classes, required roles and plugins, pins, SHAs, run key); a difference is `plan-mismatch` naming the first differing field, and a PR that `plan` would refuse is `plan-mismatch` too. `admit`'s full-to-lite degrade is accepted only from a successful `admit`, a `full` tier and no classes; any other degrade, one from an `admit` that did not succeed included, is `plan-mismatch` (R3-27). Outputs that name a plugin their job does not schedule, name one twice, come from a skipped job, or come from a successful job that leaves out a scheduled plugin refuse the run, as do documents reported by a skipped `review` job; a reported gate document whose job has no artifact name is `plan-mismatch`. Every scheduled gate gets one report: unreported, it is `gate-error:job-failed` after a failed job and `gate-skipped` after a skipped one; a reported document that is missing, too large, schema-invalid, from another plugin, or disagreeing with the job's non-failing conclusion is a gate error. Gate findings get Z4's evidence and fingerprint: one whose cited line exists on its side and normalises to its evidence's first line of content takes that tree line as evidence and is fingerprinted in its enclosing function with its occurrence index; any other keeps its evidence, is fingerprinted at file scope and loses its rule, so no waiver clears it. Evidence reads list each side once and stop at the first cited file past 1,000 files or 64 MiB (by listed size). Each cited file is indexed once, with every line normalised once, so a finding costs its own quote and one comparison, never its cited line again; a file declaring a function name longer than 256 bytes is not indexed and its findings stay unverified, so no occurrence key or fingerprint hashes an unbounded name (H-13). `open_prs_on_head` counts the PR plus each other open PR on the head into the same base once (R3-19).
- `publish` writes nothing for a superseded or yielding run (R3-06), and never releases the slot (the `release` job's). It checks its inputs before any port call: the decision key must be a `sha256:` digest and the inputs' evidence key the run's. It reads the App check for (head, `CheckName::for_base`): absent is `CheckMissing`; carrying this decision key and completed is `Unchanged`, with no write at all; carrying neither this key nor this run's stamp (`pending:<run_id>:` and one or more ASCII digits) yields without taking the lock. A decided run's bundle is built and uploaded before the lock; under the lock the check is read again and must equal the first read exactly, or the writer yields (R3-09); then the evidence record (after a successful upload only), the check (`external_id` the decision key, never `output.annotations`, R3-11) and the summary comment (written only when its body differs). The lock is released after every outcome that took it, and a failed release is reported beside the outcome, never instead of it. A persist failure (bundle not UTF-8 or over its cap, upload, ledger) makes a trust-path or exec-surface PR `failure persist-error` and is otherwise a warning on a decision left unchanged; either way there is no evidence pointer. A refused run publishes `failure` with its refusal reason and persists nothing. Rendering never lets text escape its block: every dynamic string sits in a fenced block longer than any backtick run in it, with control characters and format characters (general category Cf as of Unicode 15.1: bidi embeddings, overrides and isolates, zero-width characters, the byte-order mark, tags) replaced by U+FFFD, at most 50 items of 200 characters each and then "and N more, listed in the decision".

## Errors
- `ReadContractError` (`TooLarge`, `Malformed` (including a repeated key), `MissingSchema`, `UnknownSchema`, `UnknownVersion`, `Invalid`): every variant maps to disposition `schema` through `disposition()`.
- `ContractSchemaError`: an embedded schema does not compile, a defect in the build. Its cause is the opaque `SchemaCompileError`, so `jsonschema`'s error type is not part of this crate's API.
- `ConfigError` (`Syntax` with the opaque `TomlError`, `Digest`, `Version`, `Pin` with `ParsePinError::{Tag, UnknownScheme}`, `Name`, `DuplicateName`, `UnknownAdapter`, `MissingKey`, `UnexpectedKey`, `Job`, `Command`, `Timeout`): plugins.toml was refused. The file is from the protected base, so messages may quote it.
- `GlobsConfigError` (`Syntax` with the opaque `TomlError`, `Glob` naming the list and pattern): globs.toml was refused. `manifest_trust_keys`, `exec_roots`, `manifest_exec_roots` and `baseline_change` cannot fail: what does not parse reads as changed.
- `MetadataError` (`Syntax` with line and column, `Version`, `UnknownPackage`): `cargo metadata` output was refused; the caller passes `None` for that side to `exec_surface`, which fails closed. `exec_surface` cannot fail.
- `PlanError<O, N>` (`Objects { step, source }` with the failed port call as `ObjectsStep::{ChangedFiles, ListBase, ListHead, Read}`, `ShortRead`, `DiffTooSlow`, `FileList` with `FileListError::{OverCap, Incomplete, GitShort, Repeated, Mismatch}`, `BaseConfig` with `BaseConfigError::{Missing, NotARegularFile, NotUtf8, Plugins, Globs}`, `Nonce`, `RepeatedNonce`, `Encode`, `Invalid`): no run description; every variant fails the run. `O` and `N` are the ports' error types. A mismatch reports counts and the first differing path, `{:?}`-escaped.
- `InitReadError` (`Missing`, `Repeated`, `RepeatedKey`, `Field`, `Entry`, `TooMany`, `Name`): a session's `system/init` could not be read; `InitUnclean` (`CliVersion`, `McpServer`, `Tools`, `NotBuiltin`, `Unlisted`, `Repeated`): it was read and is not clean. Both are preflight failure `init-unclean`; names are shown `{:?}`-escaped. `ConfigError::Builtins` wraps `BuiltinsError` (`WithoutCli`, `Name`, `Repeated`, `TooMany`).
- `DoctorError<P, N>` (`Nonce`, `Probe`): the checks could not be run. A failed check is a `CheckFailure` in the report, not an error.
- `GateError` is an outcome, not a failure of the use case: a `GateRunner` error becomes `GateError::NotRun`, with the runner's message kept in `GateReport::cause`.
- `DecideError<O, S, A>` (`NotFirstAttempt`, `State` with the failed call as `StateStep::{Current, PullsOnHead, NewerRun}`, `Artifacts { job, file }`, `Recompute` (a port failed while recomputing the plan), `Objects`, `ShortRead`, `Encode`): `decide` could not reach a verdict; nothing is published and the job fails. `DecideFailure<O, S, A>` names it over the ports' error types. A refusal to publish is a `Refusal` inside `Authentication`, not an error.
- `PublishError<F, L>` (`DecisionKey`, `EvidenceKey`, `CheckMissing`, `Observe`, `Lock`, `LockBusy`, `Locked { step: ForgeStep, source, unlock }`): nothing was published (for `Locked`, a forge call under the lock failed at `step`, possibly after the evidence record); the job fails. `PublishFailure` names it over the ports' error types. `PersistFailure<L, B>` (`Bundle(BundleError)`, `Upload`, `Ledger`, with `code()`) and `BundleError` (`NotUtf8 { job, file }`, `TooLarge`, `Encode`) are outcomes inside `Written`, not errors: the verdict is still published.
- Use cases to come: one `thiserror` enum each; port failures surface through each port's associated error type.

## Test strategy
Integration tests in `tests/it/` drive use cases against in-memory fakes of the ports (TST-09); no real network, processes or clocks. Validation has one test per step and per disposition it emits (`tests/it/validation/`), a Z3-versus-Z4 test, and property tests (dev-dependency `proptest`) for determinism, relocation onto matching lines only, and each finding ending kept or dropped exactly once. Run: `cargo test -p assay-app`.

## Do not
- Do not call `gh`, `claude` or the file system directly; add or extend a port.
- Do not read environment variables; configuration arrives parsed from the CLI (ARC-11).
