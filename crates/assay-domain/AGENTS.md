# Crate charter: `assay-domain`

## Purpose
The rules of a review: findings, severities, fingerprints, the rubric, tiers, the run state machine and its events, and the `decide` logic over them. Fingerprints are computed here and only here. It is its own crate because it has the narrowest dependency profile in the workspace (no I/O at all) and changes only when review semantics change (ARC-07, `docs/architecture/02-architecture.md` §2).

## Layer
domain. Pure: no I/O, no clock, no randomness, no environment, no processes, no async runtime, no logging subscriber.

## Allowed dependencies
- Workspace crates: none.
- Third-party, and only these (02 §2): `serde` (derives on versioned contract types), `thiserror` (typed rejections, ERR-01), `sha2` (fingerprints and content hashes). Each is added by the story that first uses it.
- Dev-dependencies: crates on the pre-approved list in `.claude/temper.json`. The architecture test does not check them (it exempts every third-party dev-dependency of the domain); temper's H-16 pre-approval hook governs them, and any other is a human decision.
- Never: any other normal or build dependency, any `assay-*` crate (dev-dependencies included), `weighin-core` or temper code (P8). `crates/assay-cli/tests/it/architecture.rs` fails on a violation.

## Public surface
Workspace-internal, not published (`publish = false`). Re-exported from `lib.rs`:
- Closed vocabularies of 03, each with `ALL` and its wire `code()`, generated from one list by the private `closed_enum!` macro so serde, `code()` and `ALL` cannot drift: `Disposition` and `ReasonCode` (§5); `Class`, `FindingKind`, `Severity`, `IntroducedBy`, `Side`, `Confidence`, `SourceKind`, `GateConclusion`, `FindingsSchema` (§3); `EventKind`, `EventSchema`, `RateLimitStatus`, `VerifierVerdict`, `FeedbackSignal`, `VoidReason` (§6).
- `Marker` (`Marker::of`, `Finding::marker`): the display mapping of 03 §3, blocker 🔴, major 🟡, minor and nit 🟡 (nit), pre-existing 🟣.
- `FindingsDocument`, `Source`, `Stats`, `Finding`, `Caller`: `assay.findings/1` (03 §3).
- `Event`, `EventPayload` (with `GateRun`, `Preflight`, `SpecialistRun`) and `RunUid`: `assay.event/1` (03 §6).
- `Aeu`: an amount of API-equivalent dollars held exactly in micro-AEU (`from_micros`, `micros`, `saturating_add`), displayed as a plain decimal (`0.74`), the form `--max-budget-usd` reads.
- `normalise`: the one shared normaliser of 03 §3 (trailing `//` and ` # ` comments dropped, whitespace collapsed, quote styles unified to `"`, `...`/`…` made one wildcard `…` that absorbs adjacent spaces), for the fingerprint and the evidence check. Raw text only: it is not idempotent. Limits outside Rust: only `"` strings are tracked (a `#` or `//` in a single-quoted string can read as a comment), Python's `//` operator is stripped as a comment, and shell backticks are unified with `"`.
- `Anchor` (`fingerprint`, returning `Option<Fingerprint>`; built by `Finding::anchor`, which carries `expected_behavior` for an omission only), `Fingerprint` (`FromStr`, `Display`, serde as 16 lowercase hex) and `ParseFingerprintError`: the fingerprint of 03 §3. `EventPayload::WaiverApplied` carries a `Fingerprint`.
- `ContentHash` (`of_files`, `as_bytes`, `Display` as `sha256:<64 lowercase hex>`): SHA-256 over named files, each name and content prefixed by its byte length as a big-endian `u64`. The prompt bundle hash (04 §3) is one.
- `Dismissal` (`judge`) and `DismissalMatch` (`Unrelated`, `Suppressed`, `MoreSevere`): the fuzzy dismissal match of 03 §3 and R3-25.
- `Tier` and `PrClass` (04 §2.3, 03 §1), closed vocabularies.
- `tier(&RepoGlobs, &ChangeSet) -> Tiering`: deterministic tiering (04 §2.1 to §2.3, T17), pure and total. Inputs: `ChangeSet` (`FileChange` with `Lines` and `FileKind` (`File`, `Symlink`, `Gitlink`), the `ExecRoot`s (`Path`, `BuildSources`, `Everything`) of workspace build scripts and proc-macro crates, a non-canonical root holding every path, `ManifestTrustChange` with the closed `ManifestKey`, the `include_*!` targets of #64, `PackageDiff` and `PackageChange` with the closed `ExecCause` from #65, `BaselineChange`) and `RepoGlobs` (base `.assay/globs.toml` additions, parsed by `assay-app`). Output: `Tiering` (tier, `TierReason`s, classes, `RequiredRole`s, trust paths and exec surface changed, `FilteredStats`). `Glob` (`FromStr`, `matches`) and `GlobError`: the hand-rolled path glob it matches with.
- `Rubric` (`version`, `majors_block_threshold`, `max_requeues`, `is_micro_role`, `is_waivable`): the validated data of `rubric/v1.toml`, built only by deserialising; the caller parses the TOML.
- `decide(&Rubric, &DecisionInputs) -> Decision`: rubric v1 rules 1 to 9, waive and override (04 §5), pure and total. `DecisionInputs` and its parts (`Policy`, `PullRequest`, `Readiness`, `GateReport`, `GateOutcome`, `StepAttribution`, `GateFinding`, `ReviewedFinding`, `WeighIn`, `LlmStage` (`effective`), `NotRunReason`, `Deferral`, `LlmPolicy`, `InfraPolicy`, `OwnerApproval`, `Authorship`, `Waiver`, `Override`, `OverrideScope`) are a decide-specific projection, not a versioned contract.
- `Decision` with `DecisionSchema`, `Conclusion`, `Reason`, `Counts`, `FindingDisposition`, `Waived`, `DegradedRole`: `assay.decision/1` (03 §5); `Decision::reasons_digest` is the digest an override quotes.

## Invariants
- No I/O: every function is a pure function of its arguments.
- Fingerprints are computed only in this crate. The digest is SHA-256 over class code, rename-resolved head path, enclosing symbol, the first line of evidence with content (normalised, neither blank nor only wildcards) and, for an omission only, its normalised `expected_behavior`, each prefixed by its byte length as a big-endian `u64`, then the occurrence index as a big-endian `u32`; the fingerprint is its first 8 bytes. Golden tests pin both encodings: changing them orphans every recorded waiver and dismissal.
- Fingerprints fail closed: `Anchor::fingerprint` returns `None` for evidence with no line of content, or an omission whose `expected_behavior` has none, so such a finding can never carry a waiver or dismissal. Callers dispose of it as `evidence-missing`.
- `Finding::anchor` gives every omission a fifth field: a missing `expected_behavior` becomes `""`, so an unvalidated omission never hashes or matches as a defect.
- The fuzzy dismissal match compares the whole normalised evidence (and, for omissions, the normalised `expected_behavior`), by Levenshtein ratio over characters (`1 - distance / longer length`), in integers so 0.8 is exact. Evidence without a line of content, and an omission's `expected_behavior` without content, match nothing; text over 400 characters (the schema cap) is never similar. All three fail safe by publishing.
- `decide` is total and deterministic: equal rubric and inputs give byte-identical JSON. Its conclusion is that of the first rule that fires in the order 1, 2, 2a, 3, 4, 5, 6, 7, 8a, 8b, 8c; its reasons are those of every firing rule, in that order; `pending` comes only from rule 8a. `inputs_digest` is `sha256:<hex>` over a canonical length-prefixed encoding of the rubric and every input field (`src/decide/digest.rs`); the reasons digest is `sha256:<hex>` of the sorted reason codes, one per line, `override` excluded.
- Tiering fails closed: every path rule reads both sides of a rename; `.rs`, `build.rs`, shell, script, CI and manifest files, vendored files and trust paths are never excluded; code, agent instructions and `include_*!` targets are never `trivial`; a binary numstat forces `full`; an unavailable package diff is exec surface; a changed file at or under an exec root is exec surface; a path that is not canonical (empty, `.`/`..`/empty segment, leading `/` or `"`, `\`, control character) is a trust path; a symlink or gitlink is never docs and never excluded; `include_*!` targets match ignoring ASCII case, and one that is not canonical (the Z2s scan's `""` for a reference it cannot place) matches every path; repo globs only add to the shipped lists in `src/tiering/lists.rs`, so no addition removes a trust path or lowers a tier for one (property tests in `tests/it/tiering_properties.rs`). Lists that raise a tier match wide (ASCII case-insensitive, any ancestor directory); lists that lower one match exactly. Glob matching is one dynamic-programming pass per pattern, linear in segments, so a crafted path cannot make it exponential.
- Contract types serialise to exactly their schema's wire names and reject unknown fields and versions on deserialisation. They are plain data with `pub` fields: length caps, formats and conditional requirements are the schema's, checked by `assay-app` on read. `Severity` orders `nit < minor < major < blocker`.

## Errors
- `RubricError` (`EmptyVersion`): a rubric file that would make decisions without a `rubric_version`.
- `ParseFingerprintError` (`Length`, `Digit`): text that is not 16 lowercase hex digits.
- `GlobError` (`Empty`, `Absolute`, `Reserved`, `UnbalancedBrace`, `NestedBrace`, `SlashInBrace`, `TooManyAlternatives`, `EmptySegment`, `DotSegment`, `PartialDoubleStar`): a pattern outside the glob syntax, refused rather than read literally.
- `decide` and `tier` cannot fail: every input they are given has a result.
Rejections are `thiserror` enums per operation; business outcomes only, never infrastructure (ERR-10).

## Test strategy
Unit tests beside the code. `tests/it/` (dev-dependencies `serde_json` and `proptest`) pins every vocabulary to its schema `enum` and, where 03 lists one, to 03's text, round-trips every valid fixture in `schemas/fixtures/` and refuses the invalid fixtures whose fault is one of shape; `assay-app`'s `tests/it/domain_model.rs` checks that what these types write passes the schemas. `decide` has one test per rule and per precedence pair (`tests/it/decide*.rs`, dev-dependencies `toml` for `rubric/v1.toml` and `proptest`), property tests for byte-identical output, `pending` only from a deferred or unexcused stage, no silent success for a ready reviewed PR whose stage did not run, read-back, waived findings being exactly the uncounted ones, and a required gate no waiver can clear failing unless an `all` override applies, and the golden corpus `corpus/golden/` compared byte for byte (`tests/it/golden.rs`), which the `assay-self` gate will also replay (02 §7). Property tests pin fingerprint stability (`tests/it/fingerprint.rs`); state-machine invariants come with that story. Run: `cargo test -p assay-domain`.

## Do not
- Do not read time, ids, the environment or files here; the application passes them in through its ports.
- Do not add a dependency outside serde, thiserror and sha2: that changes 02 §2 and is a human decision (H-16).
