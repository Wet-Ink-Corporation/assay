# Crate charter: `assay-domain`

## Purpose
The rules of a review: findings, severities, fingerprints, the rubric, tiers, the run state machine and its events, and the `decide` logic over them. Fingerprints are computed here and only here. It is its own crate because it has the narrowest dependency profile in the workspace (no I/O at all) and changes only when review semantics change (ARC-07, `docs/architecture/02-architecture.md` §2).

## Layer
domain. Pure: no I/O, no clock, no randomness, no environment, no processes, no async runtime, no logging subscriber.

## Allowed dependencies
- Workspace crates: none.
- Third-party, and only these (02 §2): `serde` (derives on versioned contract types), `thiserror` (typed rejections, ERR-01), `sha2` (fingerprints and content hashes). Each is added by the story that first uses it.
- Dev-dependencies: crates on the pre-approved list in `.claude/temper.json`. The architecture test does not check them (it exempts every third-party dev-dependency of the domain); temper's H-16 pre-approval hook governs them, and any other is a human decision.
- Never: any other normal or build dependency, any `assay-*` crate (dev-dependencies included), `weighin-core` or temper code (P8). `crates/assay-cli/tests/it/architecture.rs` fails on a violation.

## Public surface
Workspace-internal, not published (`publish = false`). Re-exported from `lib.rs`:
- Closed vocabularies of 03, each with `ALL` and its wire `code()`, generated from one list by the private `closed_enum!` macro so serde, `code()` and `ALL` cannot drift: `Disposition` and `ReasonCode` (§5); `Class`, `FindingKind`, `Severity`, `IntroducedBy`, `Side`, `Confidence`, `SourceKind`, `GateConclusion`, `FindingsSchema` (§3); `EventKind`, `EventSchema`, `RateLimitStatus`, `VerifierVerdict`, `FeedbackSignal`, `VoidReason` (§6).
- `Marker` (`Marker::of(Severity, Provenance)`, `Finding::marker`) and `Provenance` (`Introduced`, `PreExisting`; #147): the display mapping of 03 §3, blocker 🔴, major 🟡, minor and nit 🟡 (nit), pre-existing 🟣.
- `FindingsDocument`, `Source`, `Stats`, `Finding`, `Caller`: `assay.findings/1` (03 §3).
- `Event`, `EventPayload` (with `GateRun`, `Preflight`, `SpecialistRun`) and `RunUid`: `assay.event/1` (03 §6). `Preflight.builtins` is the observed `BuiltinSet` (`plugins`, `skills`, `agents`; #121), omitted when absent. `auth_method` and `cli_version` are `unknown` when the preflight failed before observing them (#83). Reading an `Event` refuses a `FindingDisposed` without the fingerprint its code requires (`Disposition::requires_fingerprint`, the same codes as the schema's conditional rule; #170, #263) with the crate-private `EventError`, which serde reports as text. Kinds whose data 03 §6 lists no fields for refuse any field, while the schema keeps their `data` an open object: adding a field to one of them needs every reader upgraded first (#147; `schemas/fixtures/event/domain-invalid/`).
- `Aeu`: an amount of API-equivalent dollars held exactly in micro-AEU (`from_micros`, `micros`, `saturating_add`), displayed as a plain decimal (`0.74`), the form `--max-budget-usd` reads.
- `normalise`: the one shared normaliser of 03 §3 (trailing `//` and ` # ` comments dropped, whitespace collapsed, quote styles unified to `"`, `...`/`…` made one wildcard `…` that absorbs adjacent spaces), for the fingerprint and the evidence check. Raw text only: it is not idempotent. Limits outside Rust: only `"` strings are tracked (a `#` or `//` in a single-quoted string can read as a comment), Python's `//` operator is stripped as a comment, and shell backticks are unified with `"`.
- `Anchor` (`fingerprint`, returning `Option<Fingerprint>`; built by `Finding::anchor`, which carries `expected_behavior` for an omission only), `Fingerprint` (`FromStr`, `Display`, serde as 16 lowercase hex) and `ParseFingerprintError`: the fingerprint of 03 §3. `EventPayload::WaiverApplied` carries a `Fingerprint`.
- `ContentHash` (`of_files`, `as_bytes`, `Display` as `sha256:<64 lowercase hex>`): SHA-256 over named files, each name and content prefixed by its byte length as a big-endian `u64`. The prompt bundle hash (04 §3) is one.
- `Dismissal` (`judge`) and `DismissalMatch` (`Unrelated`, `Suppressed`, `MoreSevere`): the fuzzy dismissal match of 03 §3 and R3-25.
- `Tier` and `PrClass` (04 §2.3, 03 §1), closed vocabularies.
- `tier(&RepoGlobs, &ChangeSet) -> Tiering`: deterministic tiering (04 §2.1 to §2.3, T17), pure and total. Inputs: `ChangeSet` (`FileChange` with `Lines` and `FileKind` (`File`, `Symlink`, `Gitlink`), the `ExecRoot`s (`Path`, `BuildSources`, `Everything`) of workspace build scripts and proc-macro crates, a non-canonical root holding every path (`ExecRoot::holds` is public so that `assay-app` confines symlinks with the same rule, #65), `ManifestTrustChange` with the closed `ManifestKey`, the `include_*!` targets of #64, `PackageDiff` and `PackageChange` with the closed `ExecCause` from #65, `BaselineChange`) and `RepoGlobs` (base `.assay/globs.toml` additions, parsed by `assay-app`). Output: `Tiering` (tier, `TierReason`s, classes, `RequiredRole`s, trust paths and exec surface changed, `FilteredStats`). `Glob` (`FromStr`, `matches`) and `GlobError`: the hand-rolled path glob it matches with.
- `Rubric` (`version`, `majors_block_threshold`, `max_requeues`, `is_micro_role`, `is_waivable`): the validated data of `rubric/v1.toml`, built only by deserialising; the caller parses the TOML.
- `decide(&Rubric, &DecisionInputs) -> Decision`: rubric v1 rules 1 to 9, waive and override (04 §5), pure and total. `DecisionInputs` and its parts (`Policy`, `PullRequest`, `Readiness`, `GateReport`, `GateOutcome`, `StepAttribution`, `GateFinding`, `ReviewedFinding`, `WeighIn`, `LlmStage` (`effective`), `NotRunReason`, `Deferral`, `SupportOutcome` (coordinator and verifier) with `CallFailure`, `RequiredRole` (`completed_roles`, a set), `LlmPolicy`, `InfraPolicy`, `OwnerApproval`, `Authorship`, `Waiver`, `Override`, `OverrideScope`) are a decide-specific projection, not a versioned contract.
- `waivable_fingerprints(&Rubric, &[GateReport]) -> BTreeSet<Fingerprint>` (#126): the fingerprints an owner's waiver would clear, by the same predicate `decide`'s waive uses (every gate finding carrying the fingerprint has a rubric-waivable gate and rule; a reviewer finding never is), so `assay status` reports `waivable` exactly as `decide` applies it.
- `waiver_refusal(&Rubric, &'g [GateReport], Fingerprint) -> Option<WaiverRefusal<'g>>` (#59): why a waiver of the fingerprint clears nothing, `NoGateFinding` or `NotWaivable { gate, rule }` (borrowed from the gates) (the first carrier, in gate then finding order, whose rule is not waivable for its gate), or `None` when `decide` applies it; `decide`'s waive is this same predicate, so the verdict summary's refusal and the decision always agree.
- `Decision` with `DecisionSchema`, `Conclusion`, `Reason`, `Counts`, `FindingDisposition`, `Waived`, `DegradedRole`: `assay.decision/1` (03 §5); `Decision::reasons_digest` is the digest an override quotes.

- Weigh-In items as the checkpoints read them (04 §9, #108, `src/weigh_in.rs`): `WeighInId` (`FromStr` as `wi-` then 4 to 16 lowercase hex digits, ADR 0003, whitespace refused rather than trimmed; `as_str`, `Display`) with `ParseWeighInIdError` (`Prefix`, `Length`, `Digit`); the closed vocabularies `Door` (`one-way`, `two-way`, `unsure`) and `Authority` (`authority`, `judgment`); `Triage` (`door`, `authority`); `Blocks` (`Unstated`, `Stated`); and `standing(Option<Triage>, Blocks) -> Standing` (`Clear`, `PendingTriage`, `Blocking(BlockingCauses)`; `BlockingCauses` has private fields, `door() -> Option<Door>`, `authority()`, `blocks()` and `iter()` of `BlockingCause::{Door(Door), Authority, Blocks}` in that order, and is built only by `standing` when a cause holds, so it is never empty): pending until triaged, then blocking when the door is not two-way, the authority is the owner's or `blocks` is stated. Shared by CP1 and the Weigh-In gate adapter (#109).
## Invariants
- No I/O: every function is a pure function of its arguments.
- Fingerprints are computed only in this crate. The digest is SHA-256 over class code, rename-resolved head path, enclosing symbol, the first line of evidence with content (normalised, neither blank nor only wildcards) and, for an omission only, its normalised `expected_behavior`, each prefixed by its byte length as a big-endian `u64`, then the occurrence index as a big-endian `u32`; the fingerprint is its first 8 bytes. Golden tests pin both encodings: changing them orphans every recorded waiver and dismissal.
- Fingerprints fail closed: `Anchor::fingerprint` returns `None` for evidence with no line of content, or an omission whose `expected_behavior` has none, so such a finding can never carry a waiver or dismissal. Callers dispose of it as `evidence-missing`.
- `Finding::anchor` gives every omission a fifth field: a missing `expected_behavior` becomes `""`, so an unvalidated omission never hashes or matches as a defect.
- The fuzzy dismissal match compares the whole normalised evidence (and, for omissions, the normalised `expected_behavior`), by Levenshtein ratio over characters (`1 - distance / longer length`), in integers so 0.8 is exact. Evidence without a line of content, and an omission's `expected_behavior` without content, match nothing; text over 400 characters (the schema cap) is never similar. All three fail safe by publishing.
- `decide` is total and deterministic: equal rubric and inputs give byte-identical JSON. Its conclusion is that of the first rule that fires in the order 1, 2, 2a, 3, 4, 5, 6, 7, 8a, 8b, 8c; its reasons are those of every firing rule, in that order; `pending` comes only from rule 8a. Nothing downgrades silently: when the LLM stage completed, every required role of the PR's tier and classes (the table `tier` uses) either completed or is a degraded role (`missing` if it never reported); a failed coordinator or verifier is always degraded; on `full` a coordinator not run over reviewer findings is `missing`; on `full` or `lite` a verifier not run although a blocker or major was raised is `missing`; `Decision.degraded` lists them sorted by role and once each, a role's several reasons joined with `", "`, and rules 8b and 8c fire in that order. `inputs_digest` is `sha256:<hex>` over a canonical length-prefixed encoding of the rubric and every input field (`src/decide/digest.rs`); the reasons digest is `sha256:<hex>` of the sorted reason codes, one per line, `override` excluded. No override, `llm` or `all`, ever neutralises a decision in which rule 2 (`base-not-protected`) fires: it stays `failure` (R3-03).
- Tiering fails closed: every path rule reads both sides of a rename; `.rs`, `build.rs`, shell, script, CI and manifest files, vendored files and trust paths are never excluded; code, agent instructions and `include_*!` targets are never `trivial`; a binary numstat forces `full`; an unavailable package diff is exec surface; a changed file at or under an exec root is exec surface; a path that is not canonical (empty, `.`/`..`/empty segment, leading `/` or `"`, `\`, control character) is a trust path; a symlink or gitlink is never docs and never excluded; `include_*!` targets match ignoring ASCII case, and one that is not canonical (the Z2s scan's `""` for a reference it cannot place) matches every path; repo globs only add to the shipped lists in `src/tiering/lists.rs`, so no addition removes a trust path or lowers a tier for one (property tests in `tests/it/tiering_properties.rs`). Lists that raise a tier match wide (ASCII case-insensitive, any ancestor directory); lists that lower one match exactly. Glob matching is one dynamic-programming pass per pattern, linear in segments, so a crafted path cannot make it exponential.
- Contract types serialise to exactly their schema's wire names and reject unknown fields and versions on deserialisation. They are plain data with `pub` fields: length caps, formats and conditional requirements are the schema's, checked by `assay-app` on read, except that `Event` also refuses a `FindingDisposed` without the fingerprint its code requires. `Severity` orders `nit < minor < major < blocker`.

## Errors
- `RubricError` (`EmptyVersion`): a rubric file that would make decisions without a `rubric_version`.
- `ParseFingerprintError` (`Length`, `Digit`): text that is not 16 lowercase hex digits.
- `GlobError` (`Empty`, `Absolute`, `Reserved`, `UnbalancedBrace`, `NestedBrace`, `SlashInBrace`, `TooManyAlternatives`, `EmptySegment`, `DotSegment`, `PartialDoubleStar`): a pattern outside the glob syntax, refused rather than read literally.
- `EventError` (`FingerprintMissing`), crate-private: an event whose `FindingDisposed` omits the fingerprint its code requires; a reader sees it as serde's error text (#264).
- `decide` and `tier` cannot fail: every input they are given has a result.
Rejections are `thiserror` enums per operation; business outcomes only, never infrastructure (ERR-10).

## Test strategy
Unit tests beside the code. `tests/it/` (dev-dependencies `serde_json` and `proptest`) pins every vocabulary to its schema `enum` and, where 03 lists one, to 03's text, round-trips every valid fixture in `schemas/fixtures/`, refuses the invalid fixtures whose fault is one of shape or the fingerprint rule and the `domain-invalid` event fixtures, each with the message fragment `tests/it/round_trip.rs` lists; `assay-app`'s `tests/it/domain_model.rs` checks that what these types write passes the schemas. `decide` has one test per rule and per precedence pair (`tests/it/decide*.rs`, dev-dependencies `toml` for `rubric/v1.toml` and `proptest`), property tests for byte-identical output, `pending` only from a deferred or unexcused stage, no silent success for a ready reviewed PR whose stage did not run or completed without its required roles, read-back, waived findings being exactly the uncounted ones, and a required gate no waiver can clear failing unless an `all` override applies, and the golden corpus `corpus/golden/` compared byte for byte (`tests/it/golden.rs`), which the `assay-self` gate will also replay (02 §7). Property tests pin fingerprint stability (`tests/it/fingerprint.rs`); state-machine invariants come with that story. Run: `cargo test -p assay-domain`.

## Do not
- Do not read time, ids, the environment or files here; the application passes them in through its ports.
- Do not add a dependency outside serde, thiserror and sha2: that changes 02 §2 and is a human decision (H-16).
