# Crate charter: `assay-gates`

## Purpose
The gate adapters: the built-in `temper` and `weigh-in` adapters and the generic `exec` adapter, configured by `.assay/plugins.toml`. It implements the `GateRunner` port of `assay-app`. temper and Weigh-In knowledge lives only here, as parsers of their documented JSON (P8). It is its own crate because it is the one place that knows sibling tools' contracts (ARC-07, `docs/architecture/02-architecture.md` §2).

## Layer
adapter. Implements application ports; each tool's JSON shape is a DTO here, converted with `TryFrom` into domain types (OUT-01). No business rules.

## Allowed dependencies
- Workspace crates: `assay-app` and `assay-domain`, added by the story that first uses them.
- Third-party: crates on the pre-approved list in `.claude/temper.json`, each justified in the root decisions log when added.
- Never: `weighin-core` or any temper code: assay consumes them through contracts only (P8). Never `assay-forge`, `assay-runner` or `assay-cli`. `crates/assay-cli/tests/it/architecture.rs` fails on a violation.

Workspace-internal, not published (`publish = false`). Re-exported from `lib.rs`:

It runs the `test` steps through the same code as `TemperAdapter` in that job; `TemperSettings` holds a `TemperStepSettings` for its head tree, environment and run key.

- `GateEnvironment` (`from_vars`, `vars`): the inherited-variable allowlist (`src/environment.rs`).

## Invariants
- Gate tools run as external processes with timeouts and size-capped output (H-13).
- A gate process sees only `PATH`, `HOME`, `CI`, `ASSAY_BASE_SHA`, `ASSAY_HEAD_SHA` and `ASSAY_RUN_KEY` (exact, case-sensitive names, 03 §2; no other `ASSAY_*` variable) plus the adapter's `ASSAY_FINDINGS_OUT`; an inherited `ASSAY_FINDINGS_OUT` never passes the allowlist.
- The checkout and the output root are absolute paths (`ExecSettings::new`), so neither depends on this process's working directory.
- `exec` runs only in its own Z2b job: `gates-static`, another Z2b job or a non-`exec` plugin is refused before anything runs.
- The pinned cargo runs `cargo fetch --locked`, then (only if that exits 0) `cargo metadata --locked --offline --format-version 1 --all-features`, both with `--manifest-path <copy>/Cargo.toml`, `--config net.git-fetch-with-cli=false` and the copy as working directory. It sees only `PATH`, `HOME`, `RUSTUP_HOME` and the proxy variables, plus `CARGO_HOME`, `RUSTUP_TOOLCHAIN`, `RUSTC` (all from `CargoSettings`) and `CARGO_TERM_COLOR=never`; every inherited `CARGO_*`, `RUSTC*`, `RUSTFLAGS` or `RUSTUP_TOOLCHAIN` is dropped. Anything but exit 0 is `CargoError`, never a partial result. Precondition, checked before anything runs: no directory above the copy's canonical path (symlinks resolved, as cargo sees it) holds a `Cargo.toml` or a `.cargo` entry (cargo reads both from every ancestor of its working directory), else `CargoError::UnsafeAncestor`, or `InspectAncestor` when the copy cannot be made canonical or an ancestor cannot be inspected; the composition root places copies in a scratch directory of their own.
- Each run writes into `<output_root>/<plugin>/`, created fresh; an existing directory is refused, so a stale document is never read. The document is read only when it is a regular file (never through a symlink) of at most `max_document_bytes`.
- The temper adapter in `gates-lint` (#66, 03 §2.1 steps 5-7, `src/temper/lint.rs`, `src/temper/ratchet.rs`, `src/temper/lint_findings.rs`, `src/temper/evidence.rs`): with a `RatchetBase` set (else `NoRatchetBase` before anything runs), it first runs each declared step whose `job` is `lint` (`fmt`, `deny`), in file order, with its own argv (a program with a directory part resolved from the head tree, as `exec` does) and `timeout_s`, before any build script or proc-macro has run in the tree; then removes any `target/temper/findings.json` in the head tree (a directory there, or a symlink at `target` or `target/temper`, is `FindingsOut`); then runs `<node> <pinned>/temper.mjs baseline --check --locked --base <base> --findings-out target/temper/findings.json` from the head tree with the scan's environment under the plugin's `timeout_s`, all with 16 MiB output caps. A step a signal ended runs once more, the second termination deciding (the `gates-test` infra-class rule below, #229); `baseline --check` is never retried. A step that does not exit, after that retry, stops the run there. A run that does not exit, or a `baseline --check` exit other than 0 or 1, is returned as that termination with no document, so the use case reports `gate-error:timeout`, `signal`, `output-too-large` or `exit-N`; a step that exits non-zero fails the gate. The findings document is read only as a regular file (never through a symlink) of at most 64 MiB, parsed once refusing repeated keys (`assay_app::parse_json_strict`) and deserialised with every object's fields closed to temper 1.3.0's (`FindingsOutput` otherwise, as for an unknown severity or tool, a line of 0, another `temper_findings` format, a `ratchet.ok` other than "no `new_code`, `increases` or `errors`", or an exit code that disagrees with `ratchet.ok`). The ratchet is believed only when `mode` is exactly `diff+totals`, no note contains "only the totals", and `base` equals `RatchetBase::merge_base`; otherwise `RatchetDegraded` (`strict`, the no-baseline mode, included: Z2s already requires a baseline). The gate fails when temper does, when any `ratchet.raised` entry exists (reported like Z2s `raised`, at a synthesised spot in the baseline: locating each in the PR-controlled head baseline would be quadratic), or when a collection finding carries an `exception` base `.assay/exceptions.toml` does not admit by (file, lint) (Z2s's stricter check of the attribute itself still applies); their absence proves nothing. Display findings, which never decide the gate: `ratchet.new_code` with temper's severity mapped `must` to `blocker`, `should` to `major`, `consider` and `unmapped` to `minor`, each count above the baseline (at the baseline, the highest severity temper gave that lint) and each located compile error (`compile-error`, blocker), at most 1,000 findings with the failures first; a lint named like a waivable rule is prefixed `lint:`. Evidence is the cited line from the head commit's blob, or from base only for a file head does not hold at all (side `LEFT`; a head file shorter than the cited line falls back, never to base), read through `RevisionFiles` (one listing per side, one batch read, 16 MiB of cited files by listed size), never from the checkout a build script could rewrite; otherwise a synthesised quote.
- The temper adapter in `gates-test` (#67, 03 §2.1 step 7, `src/temper/test_job.rs`, `src/temper/steps.rs`): it runs each declared step whose `job` is `test` (`tests`, `doctests`), in file order, with its own argv (a program with a directory part resolved from the head tree), `timeout_s` and a 16 MiB output cap, from the head tree with the scan's environment; it reads nothing back (no document, no `nextest list`), needs no `RatchetBase` and never runs temper. A step that exits non-zero fails the gate, and the next step still runs (nextest exits 4 under `--no-tests=fail` when no test runs, so zero tests fail). A step a signal ended is the only infra-class outcome (06 F9) and runs once more, the second termination deciding; exits, timeouts, output caps and supervisor errors (which may leave the process running) are never retried. A step that does not exit, after that retry, stops the run as that termination (`gate-error:timeout`, `signal`, `output-too-large`); a plugin with no `test` step is `UnsupportedJob` before anything runs. Declared steps in `gates-lint` get the same single retry (#229).
- The temper adapter runs its Z2s checks only in `gates-static`, and only the base's pinned temper: `<node> <pinned>/temper.mjs scan --all --json` from the head tree, `<node>` absolute, with the `GateEnvironment` (its `PATH` absolute entries only) plus `GIT_CONFIG_NOSYSTEM`, `GIT_CONFIG_GLOBAL=/dev/null` and `GIT_CEILING_DIRECTORIES` (the head tree's parent). Nothing under the PR's `.claude/temper/` runs or is read; its drift from the pinned copy, by blob id, is a `major` `vendored-drift` finding that does not decide the gate (05 T4).
- What the scan's walk cannot see fails as `blind-spot`: `.rs` under `target`, `node_modules`, `.git` or `.temper` at any depth, submodules, every symlinked Rust file or `Cargo.toml` and every other symlink that does not resolve lexically inside the tree through real directories to a regular file, Rust whose extension is not exactly `.rs` (`lib.RS`; temper's walk matches `.rs` exactly) or whose whole file name is `.rs` (#177); from `src/temper/cargo_targets.rs` over step 4's parsed head manifests, every head `Cargo.toml`, changed by the PR or not (so one that predates it fails every PR until fixed), whose `[package]` or `[project]` `build` (a string, each string of an array, or `build.rs` for `build = true`; absent or `false` names none) or `[lib]`, `[[bin]]`, `[[test]]`, `[[bench]]` or `[[example]]` `path` is not a string whose last `/` segment is a stem followed by exactly `.rs` (byte for byte: `.RS`, `lib.rs/`, `lib.rs/.`, `.rs` and a trailing invisible character are refused) that resolves from the manifest's directory, inside the repository, through real directories and within the closure's path caps (`TreeIndex::resolve`: no absolute path, `\`, control character or `..` climbing out or through a non-directory), to a regular file of the head tree, so non-`.rs` text is never compiled unscanned; requiring the file in the tree is a fail-closed refusal that narrows one route (a target naming a file only a build script writes) and does not stop build-script writes in general (a build script can overwrite a scanned `.rs` file or add one a later cargo run discovers), which are the owner-approved exec surface (05 T6, R-07), and every target Cargo would not read as one (`package` or `lib` not a table, `bin`/`test`/`bench`/`example` not an array of tables, a non-string `path`, a `build` that is not a bool, string or array of strings), one finding per manifest (its first refused target) at line 1 (#169); a target table without `path` passes, as Cargo infers a `.rs` file and refuses a missing one before any build script runs; unlexable `.rs` (a literal or comment that never ends, a character outside ASCII in code, a token whose boundary depends on the edition, a shebang line, a leading frontmatter block); from `src/temper/attributes.rs`, `cfg_attr` naming `allow`, `expect` or `path` (raw or not) or a `$` fragment, a `cfg_attr` inside another `cfg_attr`'s arguments (refused unread, so no list is read once per level), `#[path]`, an `allow`, `expect`, `warn`, `deny`, `forbid` or `cfg_attr` attribute whose name is not followed by `(`, an attribute named by a raw identifier (`#[r#allow]`), any `#` not followed by `[`, `! [` or `$`, `#[$m]` and `#![$m]`, a fragment `$x` (or a repetition `$(..)op` that can end with a fragment or a lone punctuation mark) followed by `[`, `$`, `#` or `!` (an attribute assembled from call-site pieces, `$hash $list`, or a macro a fragment names, `$m!`), and `include`, `include_str` or `include_bytes` anywhere but called with `!` (a `use` or `as` rename); from `src/temper/references.rs`, every `macro_rules` (raw or not) that is not at bracket depth 0 outside every other `macro_rules!` body (nested in a transcriber, a block or a macro call's arguments, where an outer macro can bind a fragment to `$` and assemble an attribute, as in `$d h [allow(..)]`), every `include!` whatever it names, an `include_str!` or `include_bytes!` of anything but one literal, a `mod name;` inside any bracket (`(`, `[` or `{`: an inline module, a block, a macro call's arguments) or a `macro_rules!` body or named by a fragment, and a top-level `mod name;` whose `name.rs` or `name/mod.rs` is not a scanned file of the tree wherever rustc can look for it (`src/temper/layout.rs`: beside a crate root or `mod.rs`, otherwise in the directory named after the file; a crate root is `src/lib.rs`, `src/main.rs`, `build.rs`, `src/bin/*.rs`, `tests/*.rs`, `examples/*.rs`, `benches/*.rs` or a target directory's `main.rs` (`src/bin/*/main.rs`, `tests/*/main.rs`, `examples/*/main.rs`, `benches/*/main.rs`), directly under a directory holding a `Cargo.toml` in the tree; a crate root some `mod` can also make a module needs its modules' files in both places); and every plain `#[allow(` or `#![allow(` the lexer finds that the scan did not report as an `allow-attr` hit at the same file and line, since a hit temper's masker misses is one its baseline does not count either. Each line is reported once. Where rustc's reading cannot be modelled exactly, the check refuses rather than models (Weigh-In default wi-b5affa).
- The lexer's token boundaries follow edition 2021 and later; the forms an earlier edition or temper's masker ends elsewhere (`cr"`, `cr#`, a raw lifetime followed by `'`, and a literal suffix, lifetime or raw identifier ending in `r` followed at once by `#` or `"`, as in `'r"x"`, `"x"r"y"` and `r#r"z"`) are unlexable, so they fail closed, as is a file starting with a shebang line (`rustc_lexer::strip_shebang`'s test; a `#!` before `[` is an inner attribute). It reads a source as rustc does after normalising it (one leading byte order mark removed, CRLF made LF), drops comments and keeps literals whole, ending every token where `rustc_lexer` does: whole lifetimes and labels (`'r#x` too), suffixes on every literal, the word after `r#` as a plain identifier, and prefixed literals (`b`, `br`, `c`, `r"`, `r#"`). Code must be ASCII: rustc reads identifiers, lifetimes and some whitespace by Unicode tables this lexer does not carry, so any other character outside a literal or comment is unlexable, and literal and comment boundaries are found by ASCII rules only (Weigh-In wi-6c128e, wi-7b372a). `src/temper/corpus.rs` checks its token boundaries against proc-macro2's lexer on a corpus of those forms and on every `.rs` file of this workspace, and checks that no attribute in this workspace is one the scan cannot read. An `#[expect]` is admitted only when every `#[expect]` at the reported line names exactly one admitted lint, and an `#[expect]` the scan did not report fails; one whose argument list holds a `#` or more than 256 tokens names no lint, so it is never admitted.
- Step 4 (#64, 03 §2.1), read from base and head trees with every TOML parsed in-process and nothing expanded; each rule below fails closed:
  - Test inventory (`src/temper/inventory.rs`, `src/temper/statics.rs`): tokens from the step 2 lexer, compared per `.rs` file whose blob differs (moving tests between files fails). A test is an attribute whose last path segment holds `test` or is `bench` or `case`, counted as unconditional when neither its attribute run nor an item around it (up to the item's first `;` outside brackets, or through its first `{ .. }`) holds a condition, and otherwise kept in a multiset keyed by those conditions' normalised text, outermost first; an ignore is `#[ignore ..]` or any attribute naming `ignore` in its arguments; a condition is a `cfg` other than exactly `cfg(test)`, or a `cfg_attr` naming `cfg` or a `$` fragment. `test-inventory` (blocker, waivable) when unconditional tests drop, a conditional test's key disappears (gone, or its conditions changed), ignores rise, a condition is added on a `mod` or as an inner attribute, a top-level `mod name;` is dropped while a file it could name, or a file below it that those files' `mod` declarations reach at base (at most 1,000 per dropped module, and 64 MiB of work across all of one gate run's walks, one unit per file visited plus one per byte of the places it queues for its modules, each base file counted once, past which it counts as tested), is still in head and held tests at base (or could not be counted, or holds a module reference this check cannot follow by name), a `#[path]` module or a reference `references` cannot resolve (a nested `mod`, an include, a nested macro) is dropped, or the base text does not lex or was not read; a head file past the inventory's fixed work budget (more than 16 nested conditioned items, more than 1 MiB of condition text, or item scans past 18 times its tokens) fails as too complex to count; the base and head readers must return exactly one blob per file asked for, or the gate errors; a deleted file is reported on the base side. A head file that does not lex is step 2's `blind-spot` only.
  - Manifest switches (`src/temper/switches.rs`): any change, compared parsed and per target in file order, of `[patch]`, `[replace]`, `[workspace] exclude`, `members` and `default-members`, the presence of `[workspace]`, `package.workspace`, any path dependency removed (by table, `[target.<cfg>]` included, name and path, `[workspace.dependencies]` too), a package manifest deleted, `rust-version`, `edition` (package, `[project]`, `[workspace.package]`, per target), `autotests`/`autobenches`/`autobins`/`autoexamples`/`autolib`, and a target's `test`, `doctest`, `harness`, `required-features` and `path` is `manifest-switch` (blocker, waivable). A new manifest is compared with an empty one, except `edition.workspace = true`/`rust-version.workspace = true` and a target's `required-features`/`path`; a deleted one is compared with an empty head.
  - Lints table (`src/temper/manifests.rs`): `lints-table` (blocker, never admitted) for an entry of `[lints]` or `[workspace.lints]` removed, lowered (`allow` < `warn` < `deny` < `forbid`), given another priority or other keys, or unreadable when changed, and for an entry added below `deny`; a removed workspace manifest removes its lints; a removed member's own `[lints]` goes with it.
  - Lint inheritance: `lint-inheritance` (blocker, never admitted) for every head package manifest without `[lints] workspace = true`, outside a directory the root manifest `exclude`s at both base and head (an exclude entry that is absolute or holds `\` or `..` is not honoured); `members` globs are not modelled. A manifest that is not UTF-8 TOML is `manifest-unreadable` (blocker, never admitted); a symlinked one is step 2's `blind-spot`.
  - Admission: base `[[test_inventory]]` and `[[manifest_switch]]` entries bind (path, base blob, head blob) exactly; the finding's body quotes both blob ids.
- Compile-time reach (`src/temper/reach.rs`, `src/temper/closure.rs`, `src/temper/closure/visit.rs`, `src/temper/closure/targets.rs`, `src/temper/closure/index.rs`): include targets come from every regular `.rs` file and from every file one of them reads as Rust under another name (`include!("gen.txt")`, `#[path = "m.txt"]`); any symlink or submodule in the tree, a target that is a symlink or behind one, a `#[path]` in a file some `include!` reads, an unparseable manifest, a Cargo target `path` or `build` script that is not exactly `.rs` (#169), and more than 10,000 distinct include literals across the walk (deduplicated per file by literal and use) add `""`; a `#[path]` more than 64 attributes before its `mod` is uncertain. An include target that cannot be placed (a non-literal, escaped, byte-string, absolute or `\` path, one climbing out of the repository or through a `..` that is not a real directory, a call in a `macro_rules!` body, a renamed include, a `cfg_attr` naming `path`, an unlexable file) is `""`, which tiering matches against every path. The closure starts at each package's build script (`build.rs` when present and `build` is absent or `true`; each path `build` names, arrays included) and each proc-macro lib (`[lib] path` or `src/lib.rs`), resolving `mod name;` beside a crate root or `mod.rs` and, for any other module or `#[path]` file, both beside it and in the directory named after it, and an included file's own references from its directory and every includer's; data an `include_str!`/`include_bytes!` names is a root but never read as Rust. It is `Everything` for an unparseable, symlinked or submodule manifest, a `build` or `[lib] path` that is not a string (or array of strings) inside the repository, an entry or a directory on the way to one that is a symlink or submodule, an unlexable file (brackets nested more than 256 deep included), a non-literal or escaped include, a path outside the repository, a `#[path]` that is not `#[path = "literal"]` on a top-level `mod name;`, a `mod` inside brackets or a macro body or named by a fragment, a `mod` or `#[path]` in a file included inside brackets (`mod gen { include!(..) }`, `fn main() { include!(..) }`) or below one, an include inside a macro body, a renamed include, a nested `macro_rules!`, a `cfg_attr` naming `path` or a fragment, a raw-named attribute, a `#` that does not start an attribute, a fragment that can assemble one, more than 10,000 visits or build-script and proc-macro entry points, a work budget of 100,000 units spent before each file is queued (one per file plus one per directory its context holds) running out, a tree path or include literal past 4 KiB or 256 segments, a context past 32 directories of either kind, more than 32 MiB of queued paths and context directories, more than 32 MiB read on demand across the walk (files the tree does not already hold, charged by listed size before the read) (H-13), and a reader that returns another number of blobs than it was asked for.
- Fail closed: a baseline or `.claude/temper.json` missing, not a regular file or unparsable on either side, an unparsable base `.assay/exceptions.toml`, a head tree past the reader's limits, a scan that does not exit 0 or 1 or prints unparsable output, and an unreadable pinned copy are `TemperError`s, never a pass. Configuration (the exceptions allowlist) is read from base only. An absent `.assay/exceptions.toml` admits nothing.
- The Weigh-In adapter (#109, 04 §9, `src/weigh_in.rs`) runs experimental until D-WI: only for a non-required plugin (a required one is `WeighInError::Required`, before anything is read) and only in `gates-static`. It never runs or links Weigh-In (P8) and reads only the head tree, through `RevisionFiles`, from one listing of `.kb`: an entry at `.kb`, `.kb/_ledger`, `.kb/_intake` or either leaf directory (a file, symlink or submodule there hides everything below it) is a `weigh-in-unreadable` finding, never an empty ledger. It reads the regular `*.jsonl` files directly under `.kb/_ledger/journal/` and `*.md` directly under `.kb/_intake/decisions/`, in one batch read capped first by listed size (10,000 files, 16 MiB; past either, one `weigh-in-unreadable` finding at `.kb` and nothing is read). Journals (`src/weigh_in/journal.rs`) are read in decision 0003's format: one JSON object per line, parsed refusing repeated keys, with `type` one of `item_raised`, `item_triaged`, `item_grounded`, `item_presented`, `item_deferred`, `item_decided`, `item_defaulted`, `item_dismissed`, `record_written`, an `item_id` matching `wi-[0-9a-f]{4,16}` exactly and `ts` exactly `YYYY-MM-DDTHH:MM:SSZ`; only `item_raised.blocks` and `item_triaged.door`/`authority` are read beyond those. Atoms (`src/weigh_in/atom.rs`) are read only for the front matter's one `weighin_item: "<id>"` line, the file named `<id>-<slug>.md`; an atom without it is not Weigh-In's. A file not exactly in its form (a blank line, a final line without its newline, an unknown `type`, a second `weighin_item`, a symlink or submodule under a Weigh-In name) is refused whole as a `weigh-in-unreadable` finding (wi-b5affa). Events of all readable journals are folded in (`ts`, path, line) order (`src/weigh_in/ledger.rs`): the last status event decides the status (raised, triaged, grounded, presented and deferred are open, as is an item with no status event), the last triage its door and authority, the last raise its `blocks` (absent: unknown, never none) and its reported line. Every open item at head is reported, repository-wide: open and triaged with `blocks` not null or unknown, a door other than `two-way` or an authority other than `judgment` is `weigh-in-open-blocking` (`major`); open with a null or absent door or authority is `weigh-in-pending-triage` (`minor`); an atom naming a reported item is noted in its body as no corroboration. At most 1,000 findings, refused files first, then one `weigh-in-truncated`. The document concludes `pass` with no finding and `neutral` otherwise, never `fail`; every body says G2 is enforced by CP1 and convention until D-WI. Questions and other free text are never quoted; paths and triaged values go through `plain_name` into code spans.
- The adapter's own document always satisfies `findings-1.schema.json`: text is clipped to the schema's caps, and PR-controlled names in titles and bodies sit in code spans, reduced to `[A-Za-z0-9_:-./]` with `://` replaced. Parse errors of PR-controlled files never quote them.

## Errors
`ExecError<E>` (`NotExec`, `OutsideBuildJob`, `WrongJob`, `OutputDirectory`, `Supervisor(E)`, `ReadDocument`): the gate could not run, recorded by the use case as `gate-error:not-run`. A gate that ran and failed is a `GateRun`, never an error (ERR-10). `ExecSettingsError` (`RelativeCheckout`, `RelativeOutputRoot`): the composition root passed a relative directory. `TemperError<S, R>` (`NotTemper`, `UnsupportedJob` (a job the plugin declares no step for: `gates-test` without a `test` step), `NoRatchetBase`, `RatchetDegraded` with a `RatchetDegradation`, `FindingsOut`, `FindingsOutput`, `Lint` (a declared step or `baseline --check` the supervisor could not run, named, `S`; never retried), `Revision(R)`, `Missing`, `NotAFile`, `Malformed`, `Supervisor(S)`, `ScanEnded`, `ScanOutput`, `Pinned`, `BlobId(R)`, `Document`): the temper gate errors (`gate-error:not-run`; `RatchetDegraded` is `gate-error:ratchet-degraded`). `TemperSettingsError` (`RelativeNode`, `RelativeSearchPath`, `RelativePinned`, `NonUtf8Pinned`, `HeadTree`, `EmptyRunKey`). `CargoError<E>` (`CopyPath`, `UnsafeAncestor`, `InspectAncestor`, `Supervisor(E)`, `Failed` with the `CargoStep` and `Termination`, displayed in words, `NotUtf8`): no package set for that side, which `assay_app::exec_surface` reads as unavailable (fail closed). `CargoSettingsError` (`RelativeCargo`, `RelativeRustc`, `EmptyToolchain`, `RelativeCargoHome`). `WeighInError<R>` (`NotWeighIn`, `Required`, `OutsideStatic`, `Revision(R)`, `BlobCount`, `Document`): `gate-error:not-run`; a journal or atom it cannot read is a `weigh-in-unreadable` finding, not an error. `WeighInSettingsError` (`EmptyRunKey`).

## Known gaps
- Escaping the group kill: a gate is PR-controlled code, and a process it starts can leave the gate's process group with `setsid` or `setpgid`. The supervisor kills and waits for the group only, so such a process is neither killed at the deadline nor waited for, and can outlive the gate run (and write into the output directory afterwards). Only the job's VM or container boundary contains it; closing it needs a cgroup or PID-namespace supervisor (H-16, #150 review F5).
- FIFO swap (`read_document`): the document's type check and its open are two calls. The supervisor has shown the gate's group gone first, so only a process that left the group (`setsid`) could swap a FIFO in between, which would block the open. Closing it needs `O_NOFOLLOW | O_NONBLOCK`, which std cannot name without `libc` (H-16; #152 F8).
- `gates-test` (#67): a hostile test can lie about test results (05 T6), and a PR's `.cargo/config.toml` `[alias]` or `.config/nextest.toml` steer what `cargo nextest` runs; only that job's VM boundary contains it. The retry cannot tell a registry failure from a compile or test failure (cargo exits 101 for any failure, a failed download included), so registry flakes are not retried: the warm `target/` carries the registry cache instead. A retry leaves no trace in the document or the events, and a failed step carries no finding of its own (as in `gates-lint`), so the check says only that the gate failed. The retry covers declared steps only, in both jobs; `baseline --check` is not retried. Config refuses a `test` step that runs nextest without `--no-tests=fail` (`assay-app`'s `ConfigError::NoTestsFailMissing`, #229), but a step that runs nextest through a wrapper script or a cargo alias (`cargo nt`) is not recognised, and its zero-tests behaviour is the script's.
- `gates-lint` takes the merge base as a setting (`RatchetBase::merge_base`); computing it in Z2s and handing it to `gates-lint` through job outputs is composition-root wiring that no workflow does yet. A hostile `build.rs` in `gates-lint` can still rewrite the findings document while temper runs (05 T6, owner-approved exec surface); the strict read only refuses what temper 1.3.0 would never write.
- `gates-lint` admits an `exception` entry by (file, lint) only; the single-lint check of the `#[expect]` itself is Z2s's.
- Step 4 gaps (#64): the inventory reads source, not expansion, so a test a `macro_rules!` writes counts once per definition (dropping a call is unseen), a test a proc macro generates is not seen, and doctests (and a code block turned `ignore`) are not counted (`doctest = false` is a switch). Disabling tests by other means than counted ones is not seen: `#[should_panic]`, a test target whose `path` is not `.rs`, `[profile]` settings, `.cargo/config.toml` flags or `RUSTFLAGS` (trust paths in tiering). `nextest list` totals are not compared: no contract carries them from `gates-test`. An item's extent ends at its first `{ .. }`, so a `{` in its generics (`impl S<{ N }>`) ends it early and a condition on it does not reach the tests after that brace. Noise accepted as fail-closed: a renamed or moved test file fails as a loss at its old path; dropping any `include!` or nested `mod` from a file fails, and so does dropping any `mod name;` from a file whose modules the reach scan cannot all place (a `#[path]` past its window, a `cfg_attr` naming `path`); removing or moving a path dependency fails, an inherited one (`workspace = true`) read through the root `Cargo.toml`'s `[workspace.dependencies]` and counted as a path dependency when the root does not resolve it or does not own the manifest (an excluded directory, or below another manifest with `[workspace]`), and an own `path` never equal to an inherited one; a condition removed from a test fails (its conditional key disappears); deleting a crate fails as a switch (every switch it set is removed); any symlink or submodule in the tree makes an include target `""`, so no change is `trivial`; a new crate with its own `edition` fails as a switch; enabling a lint at `warn` fails as a weakening (a group may have set it to `deny`) and needs an owner override; every package manifest in the tree (vendored crates and fixture packages too) must inherit unless the workspace excludes its directory.
- `raised` compares crate names as the baselines spell them: a crate renamed in the PR makes its entries new, which fails (closed) where temper would carry the counts over.
- The scan reads the head tree from disk: the job must materialise exactly the head commit there, outside any other git repository or Cargo workspace (temper's project discovery climbs to the outermost `Cargo.toml`).
- Blind spots not closed by the Z2s checks (#169): attributes a proc macro emits are not read, an accepted gap (owner, 2026-11-01) whose backstop is the compiler-enforced forbid of #172, which sees attributes after expansion; and a macro a dependency re-exports under another name (`dep::inc!`, a renamed `include!`) is not recognised. Cargo targets that are not `.rs` files of the tree are closed (#169, above). A crate root at a path Cargo's conventions do not name (a `[[bin]] path`, or a crate without a `Cargo.toml` in the tree) has its `mod` declarations resolved as a non-root's, not as rustc would. An `include_str!` or `include_bytes!` of a literal passes: it embeds data, never code, and this workspace embeds its schemas that way (`assay-app`'s `contract.rs`) (Weigh-In default wi-855abd). The `allow` cross-check matches by file and line, so a second `allow` on a line temper reported once passes with the first. The checks fail closed on harmless forms too: a `cfg_attr` forwarding any `$x` fragment, any `#[$m]` (so macros forward named attributes, as `closed_enum!` does), a fragment indexed in a transcriber (`$xs [0]`), an identifier `allow`, `expect` or `path` anywhere in a `cfg_attr`'s arguments (`cfg_attr(feature = "x", derive(path))`), any raw-named attribute, any non-ASCII identifier, `include!` of a computed path, any identifier named `include` (a function too), every `include!` (generated code included from `OUT_DIR` too), every symlinked `.rs` file or `Cargo.toml`, every `macro_rules!` defined inside a function, block, macro call or another macro, every file with a shebang line, every target file a build script generates (it must be committed), every head manifest with such a target whether or not the PR touched it, `mod` declarations in inline modules, blocks and any macro call (`cfg_if!`), a `cfg`'d-out `mod name;` whose file is absent, a crate root some `mod` could also make a module without its modules' files in both places, and a name ending in `r` against a quote (`'r"`, `1r"`) that rustc lexes alike in every edition. The lexer's agreement with rustc is checked against proc-macro2's lexer, not rustc's own, on a corpus and this workspace, not proven. The `.rs` files of one head are read in one batch, so a head with more Rust than the reader's byte limit (32 MiB in `assay-cli`) is a gate error rather than a partial check.
- Weigh-In experimental mode (#109): CP2's corroboration (`set_digest`, acks), evidence and append-only rules (04 §9 rules 2, 3 and 5) and commit trailers (not in the trees `RevisionFiles` reads) are not checked; items are not scoped to the PR, so an item left open on the base branch is reported on every PR. The event vocabulary is this repository's journal plus `item_deferred`, and `ts` is whole-second UTC: both checked against the Weigh-In 0.9.0 CLI on 2026-10-19 (`weighin raise`, `weighin defer`, `weighin journal`; decision 0003's note), not its source; an event type spelled otherwise refuses its journal. Any `.md` without a `---` front matter in `.kb/_intake/decisions/` (a README) is refused, not skipped (fail-closed, kept on purpose). The one `.kb` listing holds every entry under `.kb`, so a `.kb` past the reader's listing cap is a gate error. No CI job runs the adapter yet: base `.assay/plugins.toml` and the `gates-static` job are not built. The per-gate check names the experimental note only for a gate named `weigh-in` (the reserved name); a `builtin:weigh-in` under another name gets it in its findings only.
- An `[[exception]]` admits a covered (non-attribute) hit by (file, lint), so one admitted lint covers every hit temper attributes to it in that file; the attribute's own hit is what binds the exception to a single-lint `#[expect]`.

## Test strategy
Integration tests in `tests/it/` parse recorded tool outputs; missing contract surface is requested upstream, not reverse-engineered. The exec adapter is tested against a scripted `Supervisor` that plays the gate process (`tests/it/support.rs`). The temper adapter is tested against in-memory base and head trees (`FakeRevisions`, blob ids from a hash of the bytes) and a scripted scan whose hits model temper 1.3.0's `scan --all --json` (`tests/it/temper_support.rs`); every outcome goes through `run_gates`, so its document is schema-checked. End-to-end fixture PRs (git repositories) are in `assay-cli` (`tests/it/temper.rs`). The lexer has unit tests beside it and a differential test (`src/temper/corpus.rs`, dev-dependency `syn` with `parsing`, pre-approved and already in the graph) against proc-macro2's lexer, which also checks that each form a review named either lexes as proc-macro2 lexes it or is a blind spot, and runs the whole `analyse` over this workspace's crates as a head tree, which must find no blind spot and no plain `allow`; `tests/it/temper_blind.rs` pins each form that once desynchronised the lexer or hid an attribute as a `blind-spot` finding. The pinned cargo is tested against a scripted `CaptureSupervisor` (`tests/it/cargo.rs`: argv, working directory, exact environment, step order and failures); the real cargo runs in `assay-cli`'s `tests/it/exec_surface.rs`. Step 4 is tested through the adapter on in-memory trees: `tests/it/temper_inventory.rs` (each loss, each counted form, admission by exact blobs) and `tests/it/temper_manifest.rs` (one fixture per switch, each lints weakening, inheritance, an unparseable manifest); `tests/it/temper_lint.rs` drives `gates-lint` with a scripted `CaptureSupervisor` that writes temper's findings document (`tests/fixtures/temper-check-strict.json`, a real temper 1.3.0 recording of this repository; `temper-check-diff-totals.json` and `temper-check-git-diff-failed.json`, written from temper 1.3.0's `collectFindings` and `ratchet`, the latter as it is when `git diff` throws) and plays the steps; `tests/it/temper_test.rs` drives `gates-test` with a scripted `CaptureSupervisor` whose attempts per step end as scripted (cargo-nextest never runs): order, argv, timeouts and environment, zero tests (exit 4) and failures failing without a retry, one retry of a signalled step and its result deciding, a second signal, a timeout and an output cap as gate errors, a step that cannot start, and the 16 MiB output cap of each step; `temper_steps_only.rs` (#67, `assay gate`) checks that `TemperTestAdapter` reports and runs exactly what `TemperAdapter` does in `gates-test` for each of those scripts, refuses `gates-static` and `gates-lint` before anything runs, and that `TemperStepSettings` refuses what `TemperSettings` refuses of the head tree, `PATH` and run key; `temper_lint.rs` also pins a signalled `lint` step's one retry and a non-zero exit run once; caps are tested at the cap and one past it in the modules' unit tests. Path resolution (`src/temper/layout.rs`) and quoting (`src/temper/head.rs`) are also property-tested with `proptest` (pre-approved workspace dev-dependency) against their pre-#184 readings as oracles, and their 20,000-segment and 20,000-line worst cases are checked for the right answer (ignored under Miri; the timings live in the #184 plan, not in assertions). `tests/it/reach.rs` drives `compile_time_reach` over `FakeRevisions` and checks, through the domain's `tier`, that the closure makes a build script's `include!("src/cli.rs")` and a root `mod codegen;` reaching `codegen/other.rs` exec surface. The Weigh-In adapter is tested through `run_gates` against `FakeRevisions` heads of journals and atoms shaped like this repository's (`tests/it/weigh_in.rs`, `tests/it/weigh_in_support.rs`: each standing, ordering across journals, each refused form, the caps at and past their limit, truncation, sanitising, the plugin and job refusals), and reads this repository's own `.kb` without refusing a file; id, journal, atom and fold rules have unit tests beside them. Run: `cargo test -p assay-gates`.
