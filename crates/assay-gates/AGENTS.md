# Crate charter: `assay-gates`

## Purpose
The gate adapters: the built-in `temper` and `weigh-in` adapters and the generic `exec` adapter, configured by `.assay/plugins.toml`. It implements the `GateRunner` port of `assay-app`. temper and Weigh-In knowledge lives only here, as parsers of their documented JSON (P8). It is its own crate because it is the one place that knows sibling tools' contracts (ARC-07, `docs/architecture/02-architecture.md` §2).

## Layer
adapter. Implements application ports; each tool's JSON shape is a DTO here, converted with `TryFrom` into domain types (OUT-01). No business rules.

## Allowed dependencies
- Workspace crates: `assay-app` and `assay-domain`, added by the story that first uses them.
- Third-party: crates on the pre-approved list in `.claude/temper.json`, each justified in the root decisions log when added.
- Never: `weighin-core` or any temper code: assay consumes them through contracts only (P8). Never `assay-forge`, `assay-runner` or `assay-cli`. `crates/assay-cli/tests/it/architecture.rs` fails on a violation.

## Public surface
Workspace-internal, not published (`publish = false`). Re-exported from `lib.rs`:
- `ExecAdapter<S>` (`new`; implements `assay_app::GateRunner`), `ExecSettings` (`new`, refusing a relative checkout or output root with `ExecSettingsError`), `ExecLimits` (`DEFAULT`), `FINDINGS_OUT_VAR`, `FINDINGS_FILE`: the `exec` adapter (`src/exec.rs`).
- `Supervisor` (implemented for `&mut S` too) and `ProcessSpec`: the bounded process runner the exec adapter is generic over. The production implementation is `assay_cli::ForgeSupervisor`, which delegates to `assay-forge`'s process-group supervisor (wi-603c63); this crate does not depend on forge.
- `GateEnvironment` (`from_vars`, `vars`): the inherited-variable allowlist (`src/environment.rs`).
- `TemperAdapter<S, R>` (`new`; implements `assay_app::GateRunner` in `gates-static`), `TemperPaths` (`node`, `pinned`, `head_tree`), `TemperSettings` (`new(paths, environment, run_key)`, refusing a relative `node`, a relative or non-UTF-8 pinned copy, a relative or root head tree, a `PATH` with an empty or relative entry and an empty run key with `TemperSettingsError`), `TemperError`: the temper adapter's Z2s checks, 03 §2.1 steps 1-4 (`src/temper.rs`).
- `compile_time_reach(revisions, revision)` and `CompileTimeReach` (`include_targets`, `exec_roots`): what one revision's Rust reads at compile time, for tiering's `ChangeSet` (04 §2.2, §2.3): include and `#[path]` targets, and the `include!`/`#[path]`/`mod` closure of every build script and proc-macro lib (`src/temper/closure.rs`, #64). The plan use case that calls it for base and head is not built yet.
- `CaptureSupervisor` (implemented for `&mut S` too) and `CapturedRun`: a `Supervisor` that keeps stdout, for the pinned `temper scan` (`src/capture.rs`). Production: `assay_cli::ForgeSupervisor`.
- `RevisionFiles` (`list`, `read`, `blob_id`; implemented for `&R` too), `Revision`, `TreeEntry`, `EntryKind`: the PR's base and head trees as data, listed, read in bounded batches and compared by blob id (`src/revision.rs`). Production: `assay_cli::ForgeRevisions`, over forge's object-only repository; this crate does not depend on forge.
- `PinnedCargo<S: CaptureSupervisor>` (`new`, `metadata(copy)`), `PinnedToolchain`, `CargoSettings` (`new`, refusing relative binaries or `CARGO_HOME` and an empty toolchain name with `CargoSettingsError`), `CargoEnvironment` (`from_vars`, `vars`), `CargoLimits` (`DEFAULT`), `CargoStep`, `CargoError`: the pinned base cargo on a sanitised manifest-only copy, for exec-surface detection in `gates-static` (`src/cargo.rs`, 04 §2.2, #65).

## Invariants
- Gate tools run as external processes with timeouts and size-capped output (H-13).
- A gate process sees only `PATH`, `HOME`, `CI`, `ASSAY_BASE_SHA`, `ASSAY_HEAD_SHA` and `ASSAY_RUN_KEY` (exact, case-sensitive names, 03 §2; no other `ASSAY_*` variable) plus the adapter's `ASSAY_FINDINGS_OUT`; an inherited `ASSAY_FINDINGS_OUT` never passes the allowlist.
- The checkout and the output root are absolute paths (`ExecSettings::new`), so neither depends on this process's working directory.
- `exec` runs only in its own Z2b job: `gates-static`, another Z2b job or a non-`exec` plugin is refused before anything runs.
- The pinned cargo runs `cargo fetch --locked`, then (only if that exits 0) `cargo metadata --locked --offline --format-version 1 --all-features`, both with `--manifest-path <copy>/Cargo.toml`, `--config net.git-fetch-with-cli=false` and the copy as working directory. It sees only `PATH`, `HOME`, `RUSTUP_HOME` and the proxy variables, plus `CARGO_HOME`, `RUSTUP_TOOLCHAIN`, `RUSTC` (all from `CargoSettings`) and `CARGO_TERM_COLOR=never`; every inherited `CARGO_*`, `RUSTC*`, `RUSTFLAGS` or `RUSTUP_TOOLCHAIN` is dropped. Anything but exit 0 is `CargoError`, never a partial result. Precondition, checked before anything runs: no directory above the copy's canonical path (symlinks resolved, as cargo sees it) holds a `Cargo.toml` or a `.cargo` entry (cargo reads both from every ancestor of its working directory), else `CargoError::UnsafeAncestor`, or `InspectAncestor` when the copy cannot be made canonical or an ancestor cannot be inspected; the composition root places copies in a scratch directory of their own.
- Each run writes into `<output_root>/<plugin>/`, created fresh; an existing directory is refused, so a stale document is never read. The document is read only when it is a regular file (never through a symlink) of at most `max_document_bytes`.
- The temper adapter runs only in `gates-static`, and only the base's pinned temper: `<node> <pinned>/temper.mjs scan --all --json` from the head tree, `<node>` absolute, with the `GateEnvironment` (its `PATH` absolute entries only) plus `GIT_CONFIG_NOSYSTEM`, `GIT_CONFIG_GLOBAL=/dev/null` and `GIT_CEILING_DIRECTORIES` (the head tree's parent). Nothing under the PR's `.claude/temper/` runs or is read; its drift from the pinned copy, by blob id, is a `major` `vendored-drift` finding that does not decide the gate (05 T4).
- What the scan's walk cannot see fails as `blind-spot`: `.rs` under `target`, `node_modules`, `.git` or `.temper` at any depth, submodules, every symlinked Rust file or `Cargo.toml` and every other symlink that does not resolve lexically inside the tree through real directories to a regular file, Rust whose extension is not exactly `.rs` (`lib.RS`; temper's walk matches `.rs` exactly), unlexable `.rs` (a literal or comment that never ends, a character outside ASCII in code, a token whose boundary depends on the edition, a shebang line, a leading frontmatter block); from `src/temper/attributes.rs`, `cfg_attr` naming `allow`, `expect` or `path` (raw or not) or a `$` fragment, `#[path]`, an `allow`, `expect`, `warn`, `deny`, `forbid` or `cfg_attr` attribute whose name is not followed by `(`, an attribute named by a raw identifier (`#[r#allow]`), any `#` not followed by `[`, `! [` or `$`, `#[$m]` and `#![$m]`, a fragment `$x` (or a repetition `$(..)op` that can end with a fragment or a lone punctuation mark) followed by `[`, `$`, `#` or `!` (an attribute assembled from call-site pieces, `$hash $list`, or a macro a fragment names, `$m!`), and `include`, `include_str` or `include_bytes` anywhere but called with `!` (a `use` or `as` rename); from `src/temper/references.rs`, every `macro_rules` (raw or not) that is not at bracket depth 0 outside every other `macro_rules!` body (nested in a transcriber, a block or a macro call's arguments, where an outer macro can bind a fragment to `$` and assemble an attribute, as in `$d h [allow(..)]`), every `include!` whatever it names, an `include_str!` or `include_bytes!` of anything but one literal, a `mod name;` inside any bracket (`(`, `[` or `{`: an inline module, a block, a macro call's arguments) or a `macro_rules!` body or named by a fragment, and a top-level `mod name;` whose `name.rs` or `name/mod.rs` is not a scanned file of the tree wherever rustc can look for it (`src/temper/layout.rs`: beside a crate root or `mod.rs`, otherwise in the directory named after the file; a crate root is `src/lib.rs`, `src/main.rs`, `build.rs`, `src/bin/*.rs`, `tests/*.rs`, `examples/*.rs`, `benches/*.rs` or a target directory's `main.rs` (`src/bin/*/main.rs`, `tests/*/main.rs`, `examples/*/main.rs`, `benches/*/main.rs`), directly under a directory holding a `Cargo.toml` in the tree; a crate root some `mod` can also make a module needs its modules' files in both places); and every plain `#[allow(` or `#![allow(` the lexer finds that the scan did not report as an `allow-attr` hit at the same file and line, since a hit temper's masker misses is one its baseline does not count either. Each line is reported once. Where rustc's reading cannot be modelled exactly, the check refuses rather than models (Weigh-In default wi-b5affa).
- The lexer's token boundaries follow edition 2021 and later; the forms an earlier edition or temper's masker ends elsewhere (`cr"`, `cr#`, a raw lifetime followed by `'`, and a literal suffix, lifetime or raw identifier ending in `r` followed at once by `#` or `"`, as in `'r"x"`, `"x"r"y"` and `r#r"z"`) are unlexable, so they fail closed, as is a file starting with a shebang line (`rustc_lexer::strip_shebang`'s test; a `#!` before `[` is an inner attribute). It reads a source as rustc does after normalising it (one leading byte order mark removed, CRLF made LF), drops comments and keeps literals whole, ending every token where `rustc_lexer` does: whole lifetimes and labels (`'r#x` too), suffixes on every literal, the word after `r#` as a plain identifier, and prefixed literals (`b`, `br`, `c`, `r"`, `r#"`). Code must be ASCII: rustc reads identifiers, lifetimes and some whitespace by Unicode tables this lexer does not carry, so any other character outside a literal or comment is unlexable, and literal and comment boundaries are found by ASCII rules only (Weigh-In wi-6c128e, wi-7b372a). `src/temper/corpus.rs` checks its token boundaries against proc-macro2's lexer on a corpus of those forms and on every `.rs` file of this workspace, and checks that no attribute in this workspace is one the scan cannot read. An `#[expect]` is admitted only when every `#[expect]` at the reported line names exactly one admitted lint, and an `#[expect]` the scan did not report fails.
- Step 4 (#64, 03 §2.1), read from base and head trees with every TOML parsed in-process and nothing expanded; each rule below fails closed:
  - Test inventory (`src/temper/inventory.rs`, `src/temper/statics.rs`): tokens from the step 2 lexer, compared per `.rs` file whose blob differs (moving tests between files fails). A test is an attribute whose last path segment holds `test` or is `bench` or `case`, counted only when its attribute run holds no condition; an ignore is `#[ignore ..]` or any attribute naming `ignore` in its arguments; a condition is a `cfg` other than exactly `cfg(test)`, or a `cfg_attr` naming `cfg` or a `$` fragment. `test-inventory` (blocker, waivable) when tests drop, ignores rise, a condition is added on a `mod` or as an inner attribute, a top-level `mod name;` is dropped while a file it could name is still in head and held tests at base (or could not be counted), or the base text does not lex; a deleted file is reported on the base side. A head file that does not lex is step 2's `blind-spot` only.
  - Manifest switches (`src/temper/switches.rs`): any change, compared parsed and per target in file order, of `[patch]`, `[replace]`, `[workspace] exclude`, `rust-version`, `edition` (package, `[project]`, `[workspace.package]`, per target), `autotests`/`autobenches`/`autobins`/`autoexamples`/`autolib`, and a target's `test`, `doctest`, `harness`, `required-features` and `path` is `manifest-switch` (blocker, waivable). A new manifest is compared with an empty one, except `edition.workspace = true`/`rust-version.workspace = true` and a target's `required-features`/`path`.
  - Lints table (`src/temper/manifests.rs`): `lints-table` (blocker, never admitted) for an entry of `[lints]` or `[workspace.lints]` removed, lowered (`allow` < `warn` < `deny` < `forbid`), given another priority or other keys, or unreadable when changed, and for an entry added below `deny`; a removed workspace manifest removes its lints; a removed member's own `[lints]` goes with it.
  - Lint inheritance: `lint-inheritance` (blocker, never admitted) for every head package manifest without `[lints] workspace = true`, outside a directory the root manifest `exclude`s at both base and head (an exclude entry that is absolute or holds `\` or `..` is not honoured); `members` globs are not modelled. A manifest that is not UTF-8 TOML is `manifest-unreadable` (blocker, never admitted); a symlinked one is step 2's `blind-spot`.
  - Admission: base `[[test_inventory]]` and `[[manifest_switch]]` entries bind (path, base blob, head blob) exactly; the finding's body quotes both blob ids.
- Compile-time reach (`src/temper/reach.rs`, `src/temper/closure.rs`): an include target that cannot be placed (a non-literal, escaped, byte-string, absolute or `\` path, one climbing out of the repository or through a `..` that is not a real directory, a call in a `macro_rules!` body, a renamed include, a `cfg_attr` naming `path`, an unlexable file) is `""`, which tiering matches against every path. The closure starts at each package's build script (`build.rs` when present and `build` is absent or `true`; each path `build` names, arrays included) and each proc-macro lib (`[lib] path` or `src/lib.rs`), resolving `mod name;` beside a crate root or `mod.rs` and, for any other module or `#[path]` file, both beside it and in the directory named after it, and an included file's own references from its directory and every includer's; data an `include_str!`/`include_bytes!` names is a root but never read as Rust. It is `Everything` for an unparseable, symlinked or submodule manifest, a `build` or `[lib] path` that is not a string (or array of strings) inside the repository, an entry or a directory on the way to one that is a symlink or submodule, an unlexable file, a non-literal or escaped include, a path outside the repository, a `#[path]` that is not `#[path = "literal"]` on a top-level `mod name;`, a `mod` inside brackets or a macro body or named by a fragment, an include inside a macro body, a renamed include, a nested `macro_rules!`, a `cfg_attr` naming `path` or a fragment, a raw-named attribute, a `#` that does not start an attribute, a fragment that can assemble one, and more than 10,000 visits (H-13).
- Fail closed: a baseline or `.claude/temper.json` missing, not a regular file or unparsable on either side, an unparsable base `.assay/exceptions.toml`, a head tree past the reader's limits, a scan that does not exit 0 or 1 or prints unparsable output, and an unreadable pinned copy are `TemperError`s, never a pass. Configuration (the exceptions allowlist) is read from base only. An absent `.assay/exceptions.toml` admits nothing.
- The adapter's own document always satisfies `findings-1.schema.json`: text is clipped to the schema's caps, and PR-controlled names in titles and bodies sit in code spans, reduced to `[A-Za-z0-9_:-./]` with `://` replaced. Parse errors of PR-controlled files never quote them.

## Errors
`ExecError<E>` (`NotExec`, `OutsideBuildJob`, `WrongJob`, `OutputDirectory`, `Supervisor(E)`, `ReadDocument`): the gate could not run, recorded by the use case as `gate-error:not-run`. A gate that ran and failed is a `GateRun`, never an error (ERR-10). `ExecSettingsError` (`RelativeCheckout`, `RelativeOutputRoot`): the composition root passed a relative directory. `TemperError<S, R>` (`NotTemper`, `OutsideStatic`, `Revision(R)`, `Missing`, `NotAFile`, `Malformed`, `Supervisor(S)`, `ScanEnded`, `ScanOutput`, `Pinned`, `BlobId(R)`, `Document`): the temper gate errors (`gate-error:not-run`). `TemperSettingsError` (`RelativeNode`, `RelativeSearchPath`, `RelativePinned`, `NonUtf8Pinned`, `HeadTree`, `EmptyRunKey`). `CargoError<E>` (`CopyPath`, `UnsafeAncestor`, `InspectAncestor`, `Supervisor(E)`, `Failed` with the `CargoStep` and `Termination`, displayed in words, `NotUtf8`): no package set for that side, which `assay_app::exec_surface` reads as unavailable (fail closed). `CargoSettingsError` (`RelativeCargo`, `RelativeRustc`, `EmptyToolchain`, `RelativeCargoHome`).

## Known gaps
- Escaping the group kill: a gate is PR-controlled code, and a process it starts can leave the gate's process group with `setsid` or `setpgid`. The supervisor kills and waits for the group only, so such a process is neither killed at the deadline nor waited for, and can outlive the gate run (and write into the output directory afterwards). Only the job's VM or container boundary contains it; closing it needs a cgroup or PID-namespace supervisor (H-16, #150 review F5).
- FIFO swap (`read_document`): the document's type check and its open are two calls. The supervisor has shown the gate's group gone first, so only a process that left the group (`setsid`) could swap a FIFO in between, which would block the open. Closing it needs `O_NOFOLLOW | O_NONBLOCK`, which std cannot name without `libc` (H-16; #152 F8).
- temper's Z2b part (`baseline --check` in `gates-lint`, 03 §2.1 steps 5-6) is not built: the temper adapter refuses every job but `gates-static` (`OutsideStatic`), so a required temper gate is `gate-error:not-run` in `gates-lint` until it is.
- Step 4 gaps (#64): the inventory reads source, not expansion, so a test a `macro_rules!` writes counts once per definition (dropping a call is unseen), a test a proc macro generates is not seen, and doctests (and a code block turned `ignore`) are not counted (`doctest = false` is a switch). Disabling tests by other means than counted ones is not seen: a `cfg` on an `impl`/`fn` around nested items, `#[should_panic]`, a test target whose `path` is not `.rs`, `[profile]` settings, `.cargo/config.toml` flags or `RUSTFLAGS` (trust paths in tiering). `nextest list` totals are not compared: no contract carries them from `gates-test`. Noise accepted as fail-closed: a renamed or moved test file fails as a loss at its old path; a new crate with its own `edition` fails as a switch; enabling a lint at `warn` fails as a weakening (a group may have set it to `deny`) and needs an owner override; every package manifest in the tree (vendored crates and fixture packages too) must inherit unless the workspace excludes its directory.
- `raised` compares crate names as the baselines spell them: a crate renamed in the PR makes its entries new, which fails (closed) where temper would carry the counts over.
- The scan reads the head tree from disk: the job must materialise exactly the head commit there, outside any other git repository or Cargo workspace (temper's project discovery climbs to the outermost `Cargo.toml`).
- Blind spots not closed by the Z2s checks (#169): attributes a proc macro emits are not read, a macro a dependency re-exports under another name (`dep::inc!`, a renamed `include!`) is not recognised, and Cargo's `build = "build.txt"` or `[lib] path`/`[[bin]] path` pointing at a non-`.rs` file compiles text the scan never reads (manifest checks are step 4b's). A crate root at a path Cargo's conventions do not name (a `[[bin]] path`, or a crate without a `Cargo.toml` in the tree) has its `mod` declarations resolved as a non-root's, not as rustc would. An `include_str!` or `include_bytes!` of a literal passes: it embeds data, never code, and this workspace embeds its schemas that way (`assay-app`'s `contract.rs`) (Weigh-In default wi-855abd). The `allow` cross-check matches by file and line, so a second `allow` on a line temper reported once passes with the first. The checks fail closed on harmless forms too: a `cfg_attr` forwarding any `$x` fragment, any `#[$m]` (so macros forward named attributes, as `closed_enum!` does), a fragment indexed in a transcriber (`$xs [0]`), an identifier `allow`, `expect` or `path` anywhere in a `cfg_attr`'s arguments (`cfg_attr(feature = "x", derive(path))`), any raw-named attribute, any non-ASCII identifier, `include!` of a computed path, any identifier named `include` (a function too), every `include!` (generated code included from `OUT_DIR` too), every symlinked `.rs` file or `Cargo.toml`, every `macro_rules!` defined inside a function, block, macro call or another macro, every file with a shebang line, `mod` declarations in inline modules, blocks and any macro call (`cfg_if!`), a `cfg`'d-out `mod name;` whose file is absent, a crate root some `mod` could also make a module without its modules' files in both places, and a name ending in `r` against a quote (`'r"`, `1r"`) that rustc lexes alike in every edition. The lexer's agreement with rustc is checked against proc-macro2's lexer, not rustc's own, on a corpus and this workspace, not proven. The `.rs` files of one head are read in one batch, so a head with more Rust than the reader's byte limit (32 MiB in `assay-cli`) is a gate error rather than a partial check.
- An `[[exception]]` admits a covered (non-attribute) hit by (file, lint), so one admitted lint covers every hit temper attributes to it in that file; the attribute's own hit is what binds the exception to a single-lint `#[expect]`.

## Test strategy
Integration tests in `tests/it/` parse recorded tool outputs; missing contract surface is requested upstream, not reverse-engineered. The exec adapter is tested against a scripted `Supervisor` that plays the gate process (`tests/it/support.rs`). The temper adapter is tested against in-memory base and head trees (`FakeRevisions`, blob ids from a hash of the bytes) and a scripted scan whose hits model temper 1.3.0's `scan --all --json` (`tests/it/temper_support.rs`); every outcome goes through `run_gates`, so its document is schema-checked. End-to-end fixture PRs (git repositories) are in `assay-cli` (`tests/it/temper.rs`). The lexer has unit tests beside it and a differential test (`src/temper/corpus.rs`, dev-dependency `syn` with `parsing`, pre-approved and already in the graph) against proc-macro2's lexer, which also checks that each form a review named either lexes as proc-macro2 lexes it or is a blind spot, and runs the whole `analyse` over this workspace's crates as a head tree, which must find no blind spot and no plain `allow`; `tests/it/temper_blind.rs` pins each form that once desynchronised the lexer or hid an attribute as a `blind-spot` finding. The pinned cargo is tested against a scripted `CaptureSupervisor` (`tests/it/cargo.rs`: argv, working directory, exact environment, step order and failures); the real cargo runs in `assay-cli`'s `tests/it/exec_surface.rs`. Step 4 is tested through the adapter on in-memory trees: `tests/it/temper_inventory.rs` (each loss, each counted form, admission by exact blobs) and `tests/it/temper_manifest.rs` (one fixture per switch, each lints weakening, inheritance, an unparseable manifest); `tests/it/reach.rs` drives `compile_time_reach` over `FakeRevisions` and checks, through the domain's `tier`, that the closure makes a build script's `include!("src/cli.rs")` and a root `mod codegen;` reaching `codegen/other.rs` exec surface. Run: `cargo test -p assay-gates`.

## Do not
- Do not link or vendor temper or Weigh-In code to read their state.
